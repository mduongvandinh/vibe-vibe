# 5.2.2 Cuối cùng đã thay đổi cái gì — Định dạng lịch sử cập nhật

### Giải quyết vấn đề trong một câu

Lịch sử cập nhật cho bạn biết: **tài liệu này so với lần trước đã thay đổi gì**.

### Tại sao cần lịch sử cập nhật

- **Truy vết ngược lại thay đổi**: Khi có vấn đề, có thể tìm ra lần sửa đổi nào gây ra
- **Hiểu được sự phát triển**: Thành viên mới có thể nhanh chóng nắm được quá trình tiến hóa của yêu cầu
- **So sánh phiên bản**: Biết được từ phiên bản nào bắt đầu có tính năng nào

### Định dạng tiêu chuẩn của lịch sử cập nhật

```markdown
## Lịch sử cập nhật

| Phiên bản | Ngày tháng | Nội dung thay đổi | Tác giả |
|------|------|----------|------|
| v1.2 | 2024-01-20 | Thêm chức năng bình luận | Lý Tư |
| v1.1 | 2024-01-15 | Tối ưu hóa logic tìm kiếm, hỗ trợ tìm kiếm mờ | Trương Tam |
| v1.0 | 2024-01-10 | Xuất bản phiên bản ban đầu | Trương Tam |
```

### Quy chuẩn phiên bản

Sử dụng phiên bản ngữ pháp (Semantic Versioning) phiên bản đơn giản hóa:

```
v phiên bản chính.phiên bản phụ

Phiên bản chính: Những thay đổi lớn, thay đổi không tương thích
Phiên bản phụ: Thêm tính năng mới, thay đổi tương thích ngược
```

**Ví dụ**:
- `v1.0` → `v1.1`: Thêm một trường mới
- `v1.1` → `v2.0`: Cấu trúc dữ liệu toàn bộ được tái cấu trúc

### Cách viết nội dung thay đổi

**Cách viết tốt**: Rõ ràng, cụ thể, có thể truy vết

```
✅ Thêm chức năng tải lên ảnh đại diện người dùng, hỗ trợ định dạng jpg/png
✅ Sửa đổi giao diện đăng nhập, thêm xác minh mã xác nhận
✅ Xóa API getOldUser đã bị loại bỏ
```

**Cách viết kém**: Mơ hồ, chung chung

```
❌ Sửa một số vấn đề
❌ Tối ưu hóa
❌ Cập nhật
```

### Mối quan hệ với Git

Lịch sử cập nhật của tài liệu và lịch sử commit Git có thể được sử dụng cùng nhau:

```markdown
## Lịch sử cập nhật

| Phiên bản | Ngày tháng | Nội dung thay đổi | Commit |
|------|------|----------|--------|
| v1.2 | 2024-01-20 | Thêm chức năng bình luận | [abc123](./commit-link) |
```

Nhưng lịch sử cập nhật của tài liệu nên là tóm tắt từ **góc nhìn kinh doanh**, không phải là sao chép từng commit Git.

### Phương án đơn giản hóa

Đối với dự án cá nhân, có thể đơn giản hóa thành:

```markdown
## Lịch sử thay đổi

- 2024-01-20: Thêm chức năng bình luận
- 2024-01-15: Tối ưu hóa tìm kiếm
- 2024-01-10: Phiên bản ban đầu
```

Chủ yếu là **có ghi chép**, định dạng có thể điều chỉnh theo quy mô dự án.

### Tác động đến hợp tác với AI

Khi tài liệu có nhiều phiên bản, hãy nói rõ với AI về phiên bản:

```
Vui lòng tạo mã dựa trên PRD phiên bản v1.2.
Lưu ý: v1.2 so với v1.1 đã thêm chức năng bình luận.

[Nội dung tài liệu]
```
