# 5.6.1 Các chương trình gọi nhau như thế nào——Thiết kế giao diện

### Giải quyết vấn đề bằng một câu

Thiết kế giao diện là xác định **cách phía trước và phía sau tương tác**: ai bắt đầu, nói gì, phản hồi thế nào.

### Cơ sở RESTful API

REST là một kiểu thiết kế, ý tưởng cốt lõi là **coi mọi thứ là tài nguyên**:

| Phương thức HTTP | Ý nghĩa | Ví dụ |
|-----------|------|------|
| GET | Lấy tài nguyên | GET /posts - Lấy danh sách bài viết |
| POST | Tạo tài nguyên | POST /posts - Tạo bài viết |
| PUT | Cập nhật tài nguyên (toàn bộ) | PUT /posts/1 - Cập nhật bài viết |
| PATCH | Cập nhật tài nguyên (một phần) | PATCH /posts/1 - Cập nhật một phần |
| DELETE | Xóa tài nguyên | DELETE /posts/1 - Xóa bài viết |

### Mẫu thiết kế giao diện

```markdown
## POST /api/posts

### Mô tả chức năng
Tạo bài viết mới

### Tham số yêu cầu
| Trường | Kiểu | Bắt buộc | Mô tả |
|------|------|------|------|
| title | string | Có | Tiêu đề bài viết, 1-100 ký tự |
| content | string | Có | Nội dung bài viết, định dạng Markdown |
| categoryId | string | Có | ID danh mục |
| tags | string[] | Không | Mảng thẻ, tối đa 5 thẻ |

### Ví dụ yêu cầu
```json
{
  "title": "Bài viết đầu tiên của tôi",
  "content": "# Xin chào\nĐây là nội dung",
  "categoryId": "cat_123",
  "tags": ["kỹ thuật", "hướng dẫn"]
}
```

### Ví dụ phản hồi
```json
{
  "id": "post_456",
  "title": "Bài viết đầu tiên của tôi",
  "slug": "my-first-post",
  "createdAt": "2024-01-15T10:00:00Z"
}
```

### Phản hồi lỗi
| Mã trạng thái | Mã lỗi | Mô tả |
|--------|--------|------|
| 400 | MISSING_TITLE | Tiêu đề không được để trống |
| 400 | TITLE_TOO_LONG | Tiêu đề vượt quá 100 ký tự |
| 401 | UNAUTHORIZED | Chưa đăng nhập |
```

### Quy chuẩn thiết kế URL

```
✅ Thiết kế tốt
GET    /api/posts           # Lấy danh sách bài viết
GET    /api/posts/:id       # Lấy chi tiết một bài viết
POST   /api/posts           # Tạo bài viết
PUT    /api/posts/:id       # Cập nhật bài viết
DELETE /api/posts/:id       # Xóa bài viết
GET    /api/posts/:id/comments  # Lấy bình luận của bài viết

❌ Thiết kế kém
GET    /api/getPostList     # Động từ không nên xuất hiện trong URL
POST   /api/createPost      # Động từ lặp lại
GET    /api/post/1/comment  # Số ít/số nhiều không nhất quán
```

### Phân trang và lọc

```markdown
## Tham số chung của giao diện danh sách

### Phân trang
| Tham số | Kiểu | Giá trị mặc định | Mô tả |
|------|------|--------|------|
| page | number | 1 | Số trang |
| pageSize | number | 10 | Số lượng trên mỗi trang |

### Sắp xếp
| Tham số | Kiểu | Mô tả |
|------|------|------|
| sortBy | string | Trường sắp xếp |
| order | "asc" \| "desc" | Hướng sắp xếp |

### Lọc
| Tham số | Kiểu | Mô tả |
|------|------|------|
| categoryId | string | Lọc theo danh mục |
| keyword | string | Tìm kiếm từ khóa |

### Định dạng phản hồi
```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "pageSize": 10,
    "total": 100,
    "totalPages": 10
  }
}
```
```

### Để AI giúp bạn thiết kế giao diện

```
Bạn: Giúp tôi thiết kế giao diện API cho hệ thống blog

AI: ## Thiết kế API hệ thống blog

### Mô-đun bài viết
| Phương thức | Đường dẫn | Mô tả |
|------|------|------|
| GET | /api/posts | Lấy danh sách bài viết |
| GET | /api/posts/:slug | Lấy chi tiết bài viết |
| POST | /api/posts | Tạo bài viết |
| PUT | /api/posts/:id | Cập nhật bài viết |
| DELETE | /api/posts/:id | Xóa bài viết |

### Mô-đun danh mục
| Phương thức | Đường dẫn | Mô tả |
|------|------|------|
| GET | /api/categories | Lấy danh sách danh mục |
| POST | /api/categories | Tạo danh mục |

### Mô-đun xác thực
| Phương thức | Đường dẫn | Mô tả |
|------|------|------|
| POST | /api/auth/login | Đăng nhập |
| POST | /api/auth/logout | Đăng xuất |
| GET | /api/auth/me | Lấy thông tin người dùng hiện tại |
```

### Quản lý phiên bản giao diện

Khi giao diện cần thay đổi không tương thích:

```
Phương án một: Phiên bản đường dẫn URL
/api/v1/posts
/api/v2/posts

Phương án hai: Phiên bản Header
Accept: application/vnd.blog.v1+json
```

Đối với dự án cá nhân, nên sử dụng phiên bản đường dẫn URL, trực quan hơn.
