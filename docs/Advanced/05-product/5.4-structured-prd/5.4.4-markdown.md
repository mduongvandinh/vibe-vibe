# 5.4.4 Tại sao AI ưa thích Markdown——Tối ưu hóa định dạng Markdown

### Một câu nói lên vấn đề

Markdown là **điểm cân bằng tốt nhất giữa con người có thể đọc và máy có thể phân tích**.

### Tại sao dùng Markdown

| Định dạng | Con người có thể đọc | Máy có thể phân tích | Thân thiện với quản lý phiên bản |
|------|-----------|------------|--------------|
| Word | ⭐⭐⭐ | ❌ | ❌ |
| PDF | ⭐⭐⭐ | ❌ | ❌ |
| HTML | ⭐ | ⭐⭐⭐ | ⭐⭐ |
| **Markdown** | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |

Ưu điểm của Markdown:
- **Định dạng tệp văn bản thuần**: Có thể mở bằng bất kỳ trình biên tập nào
- **Cấu trúc rõ ràng**: Tiêu đề, danh sách, khối mã phân cấp rõ ràng
- **Thân thiện với AI**: Các mô hình lớn được đào tạo với nhiều định dạng Markdown
- **Quản lý phiên bản**: Git diff hiển thị các thay đổi rõ ràng

### Cách AI "nhìn" Markdown

Mô hình AI có sự hiểu biết tự nhiên về cấu trúc Markdown:

```markdown
# Tiêu đề cấp 1 → AI nhận ra là chủ đề chính
## Tiêu đề cấp 2 → AI nhận ra là chủ đề phụ
- Mục danh sách → AI nhận ra là quan hệ song song
1. Danh sách có thứ tự → AI nhận ra là các bước/thứ tự

| Tiêu đề | Tiêu đề |
|------|------|
| Dữ liệu | Dữ liệu | → AI nhận ra là dữ liệu có cấu trúc

```code``` → AI nhận ra là mã/cấu hình
```

### Thủ thuật để tài liệu dễ phân tích hơn

#### 1. Dùng cấp tiêu đề rõ ràng

```markdown
❌ Không tốt
Chức năng một
Đây là mô tả chức năng
Chức năng hai
Đây là một chức năng khác

✅ Tốt
# Mô-đun quản lý người dùng

## Chức năng một: Đăng ký người dùng
Đây là mô tả chức năng

## Chức năng hai: Đăng nhập người dùng
Đây là một chức năng khác
```

#### 2. Dùng bảng thay vì các đoạn dài

```markdown
❌ Không tốt
Trường email là bắt buộc, loại là chuỗi ký tự, định dạng phải là email hợp lệ.
Trường mật khẩu cũng bắt buộc, chiều dài yêu cầu 8-20 ký tự.

✅ Tốt
| Trường | Loại | Bắt buộc | Ràng buộc |
|------|------|------|------|
| email | string | Có | Định dạng email hợp lệ |
| password | string | Có | 8-20 ký tự |
```

#### 3. Dùng khối mã để hiển thị cấu trúc dữ liệu

```markdown
❌ Không tốt
Trả về id người dùng, email, tên và thời gian tạo

✅ Tốt
```json
{
  "id": "user_123",
  "email": "user@example.com",
  "name": "Nguyễn Văn A",
  "createdAt": "2024-01-15T10:00:00Z"
}
```
```

#### 4. Dùng danh sách để hiển thị các bước

```markdown
❌ Không tốt
Trước tiên kiểm tra đầu vào, sau đó truy vấn cơ sở dữ liệu, tiếp theo tạo người dùng, cuối cùng trả về kết quả

✅ Tốt
1. Kiểm tra các tham số đầu vào
2. Truy vấn xem email đã tồn tại chưa
3. Tạo bản ghi người dùng
4. Trả về thông tin người dùng
```

### Quy tắc định dạng Markdown

#### Quy tắc tiêu đề
```markdown
# H1 chỉ dùng cho tiêu đề tài liệu
## H2 dùng cho các phần chính
### H3 dùng cho các phần phụ
#### H4 dùng cho nội dung chi tiết
```

#### Quy tắc danh sách
```markdown
- Danh sách không thứ tự cho các mục song song
- Dùng `-` thay vì `*`

1. Danh sách có thứ tự cho các bước
2. Hoặc nội dung có thứ tự nhất định
```

#### Quy tắc khối mã
```markdown
Mã nội dòng dùng `backtick`

Khối mã nhiều dòng ghi rõ ngôn ngữ:
```typescript
const user = await prisma.user.create({
  data: { email, password }
})
```
```

#### Quy tắc bảng
```markdown
| Canh trái | Canh giữa | Canh phải |
|:-------|:----:|-------:|
| Dữ liệu | Dữ liệu | Dữ liệu |
```

### Các yếu tố Markdown thường dùng

```markdown
## Nhấn mạnh
**Đậm** dùng cho nội dung quan trọng
*Nghiêng* dùng cho định nghĩa thuật ngữ
`Mã` dùng cho tên biến, lệnh

## Liên kết và trích dẫn
[Văn bản liên kết](url)
> Khối trích dẫn dùng cho lưu ý

## Danh sách công việc
- [x] Hoàn thành
- [ ] Chưa hoàn thành

## Đường phân cách
---
```

### Dùng Markdown khi tương tác với AI

Khi cung cấp yêu cầu cho AI, dùng Markdown có hiệu quả hơn:

```markdown
## Nhiệm vụ
Cài đặt API đăng ký người dùng

## Ràng buộc kỹ thuật
- Next.js 16 App Router
- Prisma ORM
- PostgreSQL

## Đầu vào
| Trường | Loại | Bắt buộc |
|------|------|------|
| email | string | Có |
| password | string | Có |

## Đầu ra
Phản hồi thành công với thông tin người dùng và JWT token
```

### Lời khuyên thực tế

1. **Thống nhất phong cách**: Toàn dự án dùng cùng phong cách Markdown
2. **Dùng công cụ hỗ trợ**: VS Code + plugin Markdown có thể xem trước theo thời gian thực
3. **Giữ nội dung rõ ràng**: Đừng lạm dụng định dạng, nội dung rõ ràng là quan trọng nhất
4. **Chú ý tương thích**: Các nền tảng khác nhau hỗ trợ các phần mở rộng Markdown khác nhau
