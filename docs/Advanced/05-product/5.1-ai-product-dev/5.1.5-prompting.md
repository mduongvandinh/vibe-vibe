# 5.1.5 Làm sao nói chuyện tốt với AI — Nguyên tắc cốt lõi của Prompt Engineering

### Ý chính trong một câu

Ba yếu tố của Prompt tốt: **Rõ ràng** (AI có thể hiểu), **Cụ thể** (giảm mơ hồ), **Có cấu trúc** (thuận tiện thực thi).

### Nguyên tắc cốt lõi

#### Nguyên tắc một: Diễn đạt rõ ràng ý định

```
❌ Mơ hồ: "Giúp tôi tối ưu đoạn code này"
(Tối ưu cái gì? Hiệu năng? Dễ đọc? Bảo mật?)

✅ Rõ ràng: "Hàm này chạy quá chậm, hãy tối ưu hiệu năng,
hiện tại xử lý 1000 dữ liệu mất 5 giây, mong muốn giảm xuống dưới 1 giây"
```

#### Nguyên tắc hai: Cung cấp đủ ngữ cảnh

```
❌ Thiếu ngữ cảnh: "Viết một bảng user"

✅ Ngữ cảnh đầy đủ:
"Dùng Prisma viết một bảng user:
- Sử dụng database PostgreSQL
- Cần hỗ trợ đăng nhập bằng email
- User có thông tin cơ bản (nickname, avatar)
- Cần ghi lại thời gian tạo và cập nhật"
```

#### Nguyên tắc ba: Làm rõ điều kiện ràng buộc

```
❌ Không có ràng buộc: "Làm một trang đăng nhập"

✅ Có ràng buộc:
"Làm một trang đăng nhập:
- Sử dụng Next.js App Router
- Style dùng Tailwind CSS
- Cần validate form (định dạng email, độ dài password 8-20)
- Gọi interface /api/auth/login"
```

### Template cấu trúc Prompt

Một Prompt phát triển đầy đủ thường bao gồm:

```markdown
## Nhiệm vụ
[Một câu nói rõ muốn làm gì]

## Bối cảnh
[Thông tin ngữ cảnh liên quan]

## Ràng buộc kỹ thuật
- [Sử dụng tech stack gì]
- [Cần tuân thủ quy chuẩn gì]

## Đầu vào/Đầu ra
- Đầu vào: [Nhận dữ liệu gì]
- Đầu ra: [Trả về kết quả gì]

## Ví dụ
[Nếu có thì cung cấp ví dụ tham khảo]

## Lưu ý
[Những chỗ dễ sai]
```

### Ví dụ thực chiến

**Yêu cầu**: Tạo API quản lý bài viết

```markdown
## Nhiệm vụ
Tạo API routes CRUD cho bài viết

## Bối cảnh
Đây là interface backend của hệ thống blog, frontend dùng React,
cần hỗ trợ tạo, đọc, cập nhật và xóa bài viết

## Ràng buộc kỹ thuật
- Next.js 16 App Router
- Sử dụng Prisma ORM
- Database là PostgreSQL
- Trả về định dạng JSON

## Định nghĩa interface
- GET /api/posts - Lấy danh sách bài viết (hỗ trợ phân trang)
- GET /api/posts/[id] - Lấy một bài viết
- POST /api/posts - Tạo bài viết
- PUT /api/posts/[id] - Cập nhật bài viết
- DELETE /api/posts/[id] - Xóa bài viết

## Cấu trúc dữ liệu
Bài viết bao gồm: id, title, content, authorId,
createdAt, updatedAt

## Lưu ý
- Tạo và cập nhật cần validate trường bắt buộc
- Xóa cần trả về mã trạng thái 204
- Interface danh sách mặc định mỗi trang 10 bản ghi
```

### Hiểu lầm thường gặp

**Hiểu lầm 1: Nói quá nhiều một lần**

```
❌ "Giúp tôi làm một hệ thống blog hoàn chỉnh, bao gồm quản lý bài viết, hệ thống user,
chức năng comment, tìm kiếm, RSS..."

✅ Chia thành từng bước: Làm CRUD bài viết trước, xác minh xong rồi thêm chức năng khác
```

**Hiểu lầm 2: Kỳ vọng AI đọc vị**

```
❌ "Làm theo cách thông thường là được"
(AI không biết "thông thường" theo bạn là gì)

✅ Chỉ rõ: Sử dụng phong cách RESTful, tuân theo quy chuẩn code hiện có của dự án
```

**Hiểu lầm 3: Không đưa phản hồi**

```
❌ Nhận code rồi dùng luôn, phát hiện vấn đề mới nói "code bạn đưa sai"

✅ Nhận code rồi kiểm tra, nói rõ chỗ nào không đúng mong đợi:
"Khi tạo bài viết, nếu tiêu đề rỗng nên trả về lỗi 400,
nhưng hiện tại trả về 500"
```

### Kỹ thuật nâng cao chất lượng Prompt

1. **Viết xong đọc lại**: Viết xong Prompt đọc lại một lần, xem bản thân có hiểu không
2. **Coi AI như người mới**: Coi AI như đồng nghiệp mới vào, cần giải thích chi tiết bối cảnh
3. **Cung cấp ví dụ**: Có thể đưa ví dụ code thì hãy đưa, AI học từ ví dụ nhanh nhất
4. **Tối ưu lặp lại**: Lần đầu không hoàn hảo là bình thường, điều chỉnh Prompt theo kết quả
