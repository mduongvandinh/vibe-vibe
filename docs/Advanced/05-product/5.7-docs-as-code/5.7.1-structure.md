# 5.7.1 Nên đặt tài liệu ở đâu — Cấu trúc thư mục tài liệu

### Giải đáp nhanh

Thư mục tài liệu nên **tương ứng với cấu trúc mã**, để người dùng biết ngay nơi tìm kiếm.

### Cấu trúc thư mục được đề xuất

```
my-project/
├── docs/                   # Thư mục tài liệu
│   ├── README.md           # Trang đầu tài liệu
│   ├── getting-started.md  # Hướng dẫn bắt đầu nhanh
│   ├── api/                # Tài liệu API
│   │   ├── auth.md         # Liên quan đến xác thực
│   │   └── posts.md        # Liên quan đến bài viết
│   ├── guides/             # Hướng dẫn sử dụng
│   │   ├── deployment.md   # Hướng dẫn triển khai
│   │   └── development.md  # Hướng dẫn phát triển
│   └── architecture/       # Giải thích kiến trúc
│       └── overview.md     # Tổng quan kiến trúc
├── src/                    # Mã nguồn
│   ├── app/
│   │   └── api/
│   │       ├── auth/       ← Tương ứng docs/api/auth.md
│   │       └── posts/      ← Tương ứng docs/api/posts.md
│   └── ...
└── README.md               # Điểm vào dự án
```

### Mối quan hệ tương ứng giữa tài liệu và mã

| Đường dẫn mã | Đường dẫn tài liệu | Nội dung |
|----------|----------|------|
| `src/app/api/auth/` | `docs/api/auth.md` | Giải thích giao diện xác thực |
| `src/app/api/posts/` | `docs/api/posts.md` | Giải thích giao diện bài viết |
| `prisma/schema.prisma` | `docs/architecture/database.md` | Thiết kế cơ sở dữ liệu |
| `src/lib/` | `docs/architecture/libs.md` | Giải thích hàm tiện ích |

### Cấu trúc tài liệu tối giản

Với dự án cá nhân, bạn có thể đơn giản hóa hơn:

```
my-project/
├── docs/
│   ├── README.md      # Giải thích dự án + bắt đầu nhanh
│   ├── api.md         # Tài liệu API (tất cả giao diện)
│   └── deployment.md  # Giải thích triển khai
├── src/
└── README.md          # Điểm vào dự án (hướng đến docs/)
```

### Quy chuẩn đặt tên tài liệu

```
Đúng cách
- getting-started.md   # Chữ thường + dấu nối
- api-authentication.md
- deploy-to-vercel.md

Sai cách
- GettingStarted.md    # Tránh camelCase
- api authentication.md # Tránh dấu cách
- 部署说明.md          # Tránh tên tệp Trung Quốc
```

### Thiết kế điểm vào tài liệu

README.md của dự án nên cung cấp điều hướng rõ ràng:

```markdown
# My Blog

Hệ thống blog cá nhân được xây dựng bằng Next.js.

## Bắt đầu nhanh

\`\`\`bash
pnpm install
pnpm dev
\`\`\`

## Tài liệu

- [Hướng dẫn phát triển](./docs/development.md)
- [Tài liệu API](./docs/api.md)
- [Giải thích triển khai](./docs/deployment.md)

## Công nghệ

- Next.js 16
- Prisma
- PostgreSQL
```

### Lời khuyên thực tế

1. **Nguyên tắc gần**: Đặt tài liệu liên quan gần nhau
2. **Ưu tiên phẳng**: Không lồng ghép quá sâu
3. **Đặt tên rõ ràng**: Nhìn vào tên tệp là biết nội dung
4. **Lưu trữ kịp thời**: Di chuyển tài liệu lỗi thời vào thư mục archive
