# 5.7.4 Để máy tính nhắc nhở bạn cập nhật tài liệu — Kiểm tra tự động

### Giải đáp nhanh

Dùng CI để kiểm tra tài liệu tự động, **để máy tính thay người đề phòng** bạn cập nhật tài liệu.

### Giá trị của kiểm tra tự động

```
Không có tự động hóa:
  Gửi mã → Quên cập nhật tài liệu → Hợp nhất → Phát hiện tài liệu lỗi thời → Bổ sung

Có tự động hóa:
  Gửi mã → CI kiểm tra tài liệu → Nhắc nhở thiếu → Bổ sung tài liệu → Hợp nhất
```

### Có thể kiểm tra tự động cái gì

| Mục kiểm tra | Công cụ | Giải thích |
|--------|------|------|
| Định dạng Markdown | markdownlint | Quy chuẩn định dạng |
| Hiệu lực liên kết | markdown-link-check | Kiểm tra liên kết chết |
| Kiểm tra chính tả | cspell | Kiểm tra từ |
| Độ bao phủ tài liệu | Tập lệnh tùy chỉnh | Hoàn chỉnh tài liệu API |

### Cấu hình CI cơ bản

Ví dụ GitHub Actions:

```yaml
# .github/workflows/docs.yml
name: Docs Check

on:
  push:
    paths:
      - 'docs/**'
      - '*.md'
  pull_request:
    paths:
      - 'docs/**'
      - '*.md'

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Lint Markdown
        uses: DavidAnson/markdownlint-cli2-action@v14
        with:
          globs: '**/*.md'
```

### Kiểm tra định dạng Markdown

Tạo tệp cấu hình `.markdownlint.json`:

```json
{
  "default": true,
  "MD013": false,
  "MD033": false,
  "MD041": false
}
```

Quy tắc thường gặp:
- MD013: Giới hạn độ dài dòng (thường tắt)
- MD033: Cấm HTML (thường tắt)
- MD041: Dòng đầu phải là tiêu đề

### Kiểm tra liên kết

Kiểm tra xem liên kết trong tài liệu có hiệu lực không:

```yaml
- name: Check Links
  uses: gaurav-nelson/github-action-markdown-link-check@v1
  with:
    use-quiet-mode: 'yes'
    config-file: '.markdown-link-check.json'
```

Tệp cấu hình `.markdown-link-check.json`:

```json
{
  "ignorePatterns": [
    { "pattern": "^https://localhost" }
  ],
  "timeout": "10s",
  "retryOn429": true
}
```

### Kiểm tra độ bao phủ tài liệu

Tập lệnh tùy chỉnh kiểm tra hoàn chỉnh tài liệu API:

```javascript
// scripts/check-docs.js
const fs = require('fs')
const path = require('path')

// Lấy tất cả các tuyến đường API
const apiDir = 'src/app/api'
const routes = fs.readdirSync(apiDir, { recursive: true })
  .filter(f => f.endsWith('route.ts'))
  .map(f => path.dirname(f))

// Kiểm tra xem tài liệu có tồn tại không
const docsDir = 'docs/api'
const missing = routes.filter(route => {
  const docPath = path.join(docsDir, `${route}.md`)
  return !fs.existsSync(docPath)
})

if (missing.length > 0) {
  console.error('Missing docs for:', missing)
  process.exit(1)
}

console.log('All APIs have docs!')
```

### Mẫu PR nhắc nhở

Tạo mẫu PR `.github/pull_request_template.md`:

```markdown
## Giải thích thay đổi

### Thay đổi mã
-

### Cập nhật tài liệu
- [ ] Không cần cập nhật tài liệu
- [ ] Đã cập nhật tài liệu API
- [ ] Đã cập nhật README
- [ ] Đã cập nhật tài liệu triển khai

### Bài kiểm tra
- [ ] Bài kiểm tra cục bộ vượt qua
```

### Tự động hóa phiên bản đơn giản

Với dự án cá nhân, bạn có thể dùng cách đơn giản nhất:

```yaml
# .github/workflows/docs.yml
name: Docs

on: [push, pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Check Markdown
        run: npx markdownlint-cli2 "**/*.md"
```

### Kiểm tra sơ bộ cục bộ

Kiểm tra trước khi gửi:

```json
// package.json
{
  "scripts": {
    "docs:lint": "markdownlint-cli2 '**/*.md'",
    "docs:links": "markdown-link-check docs/**/*.md"
  }
}
```

Dùng husky thêm hook pre-commit:

```bash
# Cài đặt
pnpm add -D husky
npx husky install

# Thêm hook
npx husky add .husky/pre-commit "pnpm docs:lint"
```

### Lời khuyên thực tế

1. **Bắt đầu từ những cái đơn giản**: Trước tiên làm kiểm tra định dạng, rồi từ từ thêm
2. **Đừng quá sâu**: Kiểm tra quá chặt sẽ làm người khác mất kiên nhẫn
3. **Phản hồi nhanh**: Kiểm tra CI phải nhanh, trong vài phút
4. **Cung cấp gợi ý sửa**: Bảo người khác cách sửa lỗi
