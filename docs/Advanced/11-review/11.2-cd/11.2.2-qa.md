# 11.2.2 Kiểm tra chất lượng: Testing/Build/Quét bảo mật

## Giải quyết vấn đề bằng một câu

Kiểm soát chất lượng thông qua **kiểm tra tự động hóa** đảm bảo code tuân theo tiêu chuẩn, code không đạt chất lượng không thể merge vào nhánh chính.

## Giá trị cốt lõi

Cấu hình kiểm soát chất lượng cho phép bạn:
- Tự động chặn code có vấn đề
- Giảm gánh nặng review thủ công
- Giữ code repository sạch sẽ và nhất quán

## Cấu hình kiểm tra chất lượng hoàn chỉnh

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  # Type checking
  typecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run typecheck

  # Code style check
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run lint

  # Unit tests
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm test -- --coverage
      - name: Upload coverage
        uses: codecov/codecov-action@v3

  # Build verification
  build:
    runs-on: ubuntu-latest
    needs: [typecheck, lint, test]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run build
```

## Quét bảo mật dependencies

```yaml
  # Quét lỗ hổng dependencies
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run npm audit
        run: npm audit --audit-level=high

      # Hoặc sử dụng Snyk
      - name: Run Snyk
        uses: snyk/actions/node@master
        env:
          SNYK_TOKEN: ${{ secrets.SNYK_TOKEN }}
```

## Cấu hình quy tắc bảo vệ nhánh

Bật bảo vệ nhánh trong cài đặt repo GitHub:

```
Settings → Branches → Branch protection rules → Add rule

Chọn:
☑ Require a pull request before merging
☑ Require status checks to pass before merging
  └─ Select: typecheck, lint, test, build
☑ Require branches to be up to date before merging
```

## Xử lý khi kiểm tra thất bại

```yaml
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - name: Run ESLint
        run: npm run lint
        continue-on-error: false  # Chặn workflow khi thất bại

      # Tùy chọn: tải lên báo cáo lỗi
      - name: Upload lint report
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: lint-report
          path: lint-results.json
```

## Hướng dẫn tránh sai lầm

::: danger Sai lầm dễ mắc phải nhất của người mới
1. Quá nhiều kiểm tra dẫn đến thời gian CI kéo dài (nên chạy song song)
2. Không cấu hình quy tắc bảo vệ nhánh (kiểm tra có thể bị vượt qua)
3. Bỏ qua kết quả quét bảo mật
4. Đặt ngưỡng coverage quá cao dẫn đến thất bại thường xuyên
:::
