# 0.4.2 Tại sao phiên bản Node của tôi không đúng - Quản lý phiên bản Node.js với nvm

## Tóm tắt một câu

Các dự án khác nhau cần phiên bản Node khác nhau. **Dùng nvm để quản lý Node**, dùng `.nvmrc` để khóa phiên bản dự án, tránh tình trạng "chạy được trên máy tôi" đáng xấu hổ.

## Cài đặt và cấu hình nvm: Windows/macOS/Linux

- Windows: Sử dụng `nvm-windows` (phiên bản của Corey Butler).
  - Sau khi cài đặt, xác minh trong PowerShell: `Get-Command nvm`
  - Lệnh thường dùng: `nvm list`, `nvm install 18.19.0`, `nvm use 18.19.0`
- macOS/Linux: Sử dụng `nvm` (phiên bản Shell script).
  - Lệnh thường dùng tương tự: `nvm ls`, `nvm install 20`, `nvm use 20`

## Chiến lược chọn phiên bản Node.js: LTS vs Current

- Phát triển và sản xuất ưu tiên chọn **LTS** (Hỗ trợ dài hạn), ổn định và khả năng tương thích hệ sinh thái tốt.
- Khám phá tính năng mới hoặc môi trường thử nghiệm có thể dùng **Current**, nhưng không khuyến nghị dùng cho sản xuất.

## Khóa phiên bản cấp dự án: .nvmrc

- Tạo `.nvmrc` tại thư mục gốc dự án, nội dung là phiên bản mục tiêu:

```
18.19.0
```

- Đọc và chuyển đổi trong Windows PowerShell:

```powershell
$version = Get-Content .nvmrc | Select-Object -First 1
nvm use $version
node -v
```

## Quản lý biến môi trường và cấu hình

- Thiết lập phiên hiện tại: `$env:NODE_ENV = 'development'`
- Thiết lập bền vững: `setx NODE_ENV production`
- Biến tùy chỉnh: `$env:API_BASE = 'https://api.example.com'`

## Cấu hình và tối ưu hóa trình quản lý gói (Sử dụng kết hợp với nvm)

- registry:
  - `npm config set registry https://registry.npmmirror.com`
  - `pnpm config set registry https://registry.npmmirror.com`
- cache:
  - `npm cache verify`
  - `pnpm store prune`

## Hướng dẫn cộng tác với AI

- Ý định cốt lõi: Để AI giúp bạn **chuẩn hóa phiên bản** và **tạo script chuyển đổi**.
- Công thức định nghĩa yêu cầu:
  - "Trong Windows PowerShell, phát hiện `.nvmrc` và tự động chuyển sang phiên bản tương ứng, nếu chưa cài đặt thì tự động cài đặt."
- Thuật ngữ quan trọng: `nvm-windows`, `.nvmrc`, `LTS`, `NODE_ENV`, `registry`, `cache`.

## Hướng dẫn tránh các vấn đề

- `nvm-windows` trên Windows khác với `nvm` trên Unix; cần chú ý tương thích khi trao đổi script.
- Node toàn cục và `.nvmrc` của dự án không nhất quán sẽ dẫn đến biên dịch dependencies thất bại (như `node-gyp`).
- Sau khi chuyển phiên bản Node, khuyến nghị dọn dẹp và cài đặt lại dependencies, đảm bảo binary binding nhất quán.
