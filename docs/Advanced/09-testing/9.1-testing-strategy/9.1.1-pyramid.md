# 9.1.1 Các test cũng có cấp bậc — Test pyramid: Unit/Integration/End-to-end

**Các loại test khác nhau giải quyết các vấn đề ở các lớp khác nhau, việc nhầm lẫn ranh giới của chúng là nguồn gốc của hiệu suất test thấp.**

## Ba tầng của test pyramid

```mermaid
graph TB
    subgraph Test Pyramid
        E2E[E2E Test]
        INT[Integration Test]
        UNIT[Unit Test]
    end

    E2E --> |Mô phỏng người dùng thực| Tự động hóa trình duyệt
    INT --> |Xác minh sự hợp tác| Gọi API/Tương tác DB
    UNIT --> |Xác minh từng hàm| Logic thuần/Không side effect

    style E2E fill:#ff6b6b

    style UNIT fill:#6bcb77
```

## Giải thích chi tiết ba loại test

### Unit test: Xác minh ở mức độ nhỏ nhất

Unit test kiểm tra **từng hàm hoặc class riêng lẻ**, không liên quan đến các phụ thuộc bên ngoài.

```typescript
// utils/price.ts
export function calculateDiscount(price: number, rate: number): number {
  if (rate < 0 || rate > 1) {
    throw new Error('Tỉ lệ chiết khấu phải nằm trong khoảng 0-1');
  }
  return Math.round(price * (1 - rate) * 100) / 100;
}

// __tests__/utils/price.test.ts
import { calculateDiscount } from '@/utils/price';

describe('calculateDiscount', () => {
  it('nên tính toán đúng giá chiết khấu', () => {
    expect(calculateDiscount(100, 0.2)).toBe(80);
    expect(calculateDiscount(99.99, 0.1)).toBe(89.99);
  });

  it('nên từ chối tỉ lệ chiết khấu không hợp lệ', () => {
    expect(() => calculateDiscount(100, -0.1)).toThrow();
    expect(() => calculateDiscount(100, 1.5)).toThrow();
  });
});
```

**Các trường hợp áp dụng**:
- Hàm thuần, hàm tiện ích
- Chuyển đổi dữ liệu, logic định dạng
- Tính toán quy tắc kinh doanh

### Integration test: Xác minh sự hợp tác giữa các module

Integration test xác minh **sự hợp tác giữa nhiều module**, thường liên quan đến cơ sở dữ liệu, gọi API, v.v.

```typescript
// services/order.service.ts
export class OrderService {
  constructor(private prisma: PrismaClient) {}

  async createOrder(userId: string, items: CartItem[]) {
    return this.prisma.$transaction(async (tx) => {
      const order = await tx.order.create({
        data: {
          userId,
          status: 'PENDING',
          items: { create: items.map(item => ({ ...item })) },
        },
      });

      // Giảm tồn kho
      for (const item of items) {
        await tx.product.update({
          where: { id: item.productId },
          data: { stock: { decrement: item.quantity } },
        });
      }

      return order;
    });
  }
}

// __tests__/services/order.service.test.ts
describe('OrderService', () => {
  let prisma: PrismaClient;
  let orderService: OrderService;

  beforeAll(async () => {
    prisma = new PrismaClient();
    orderService = new OrderService(prisma);
  });

  beforeEach(async () => {
    // Làm sạch và chuẩn bị dữ liệu test
    await prisma.order.deleteMany();
    await prisma.product.deleteMany();
    await prisma.product.create({
      data: { id: 'prod-1', name: 'Sản phẩm test', price: 100, stock: 10 },
    });
  });

  it('nên tạo đơn hàng và giảm tồn kho', async () => {
    const order = await orderService.createOrder('user-1', [
      { productId: 'prod-1', quantity: 2, price: 100 },
    ]);

    expect(order.status).toBe('PENDING');

    const product = await prisma.product.findUnique({ where: { id: 'prod-1' } });
    expect(product?.stock).toBe(8); // 10 - 2 = 8
  });
});
```

**Các trường hợp áp dụng**:
- Logic tầng service
- Các hoạt động cơ sở dữ liệu
- Gọi API bên ngoài (sử dụng Mock)

### End-to-end test: Mô phỏng người dùng thực

E2E test thông qua tự động hóa trình duyệt, **mô phỏng các hoạt động của người dùng thực**.

```typescript
// e2e/checkout.spec.ts (Playwright)
import { test, expect } from '@playwright/test';

test('người dùng nên hoàn thành quy trình thanh toán', async ({ page }) => {
  // Đăng nhập
  await page.goto('/login');
  await page.fill('[name="email"]', 'test@example.com');
  await page.fill('[name="password"]', 'password123');
  await page.click('button[type="submit"]');

  // Thêm sản phẩm vào giỏ hàng
  await page.goto('/products/1');
  await page.click('button:has-text("Thêm vào giỏ hàng")');

  // Thanh toán
  await page.goto('/cart');
  await page.click('button:has-text("Thanh toán")');

  // Xác minh đơn hàng được tạo thành công
  await expect(page).toHaveURL(/\/orders\/\d+/);
  await expect(page.locator('h1')).toContainText('Đơn hàng đã được tạo');
});
```

**Các trường hợp áp dụng**:
- Quy trình người dùng cốt lõi (đăng ký, đăng nhập, thanh toán)
- Các đường dẫn kinh doanh quan trọng
- Tương tác giữa các trang

## So sánh ba loại test

| Đặc tính | Unit test | Integration test | E2E test |
|----------|-----------|-----------------|----------|
| Tốc độ thực thi | Millisecond | Giây | Phút |
| Chi phí bảo trì | Thấp | Trung bình | Cao |
| Phát hiện vấn đề | Lỗi logic | Lỗi tích hợp | Vấn đề UX |
| Xác định vấn đề | Chính xác | Khá chính xác | Mơ hồ |
| Phạm vi bảo phủ | Nhỏ | Trung bình | Lớn |
| Phụ thuộc môi trường | Không | DB/Mock | Môi trường hoàn chỉnh |

## Hướng dẫn hợp tác với AI

Khi bạn cần thêm test cho code hiện có, bạn có thể giao tiếp với AI như sau:

> **Ý định cốt lõi**: Cho AI biết bạn đang test code ở lớp nào
>
> **Công thức định nghĩa yêu cầu**:
> - Unit test: `Viết unit test cho hàm thuần này, bao gồm các input bình thường và điều kiện biên`
> - Integration test: `Viết integration test cho phương thức tầng service này, cần chuẩn bị dữ liệu test và logic làm sạch`
> - E2E test: `Viết test Playwright cho quy trình đăng nhập của người dùng, bao gồm các kịch bản thành công và thất bại`

**Các thuật ngữ chính**: `describe`, `it`, `expect`, `beforeEach`, `afterEach`, `mock`

## Kết luận phần này

Hiểu được test pyramid ở trọng tâm là: **mỗi loại test đều có trường hợp áp dụng tốt nhất của nó**. Unit test nhanh và chính xác nhưng phạm vi bảo phủ hẹp, E2E test có phạm vi rộng nhưng chi phí bảo trì cao, integration test đạt được sự cân bằng giữa hai loại. Đối với nhà phát triển Vibe Coding, tập trung sức lực vào integration test tầng service là lựa chọn có tỷ lệ chi phí-lợi ích cao nhất.
