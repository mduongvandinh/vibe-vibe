# 8.3.1 Định dạng tiêu chuẩn của commit message

Quy chuẩn Conventional Commits định nghĩa một định dạng commit message có cấu trúc, giúp con người và máy tính đều có thể hiểu dễ dàng.

## Định dạng đầy đủ

```
<type>(<scope>): <subject>
<dòng trống>
<body>
<dòng trống>
<footer>
```

### Chi tiết từng phần

#### 1. Header (bắt buộc)

```
<type>(<scope>): <subject>
```

| Phần | Bắt buộc | Mô tả |
|------|------|------|
| type | Có | Loại thay đổi |
| scope | Không | Phạm vi ảnh hưởng |
| subject | Có | Mô tả ngắn gọn (tối đa 50 ký tự) |

**Ví dụ**:
```bash
feat(auth): 添加用户注册功能
fix: 修复首页加载失败的问题
docs(readme): 更新安装说明
```

#### 2. Body (tùy chọn)

Mô tả chi tiết về động lực và cách thức thực hiện thay đổi:

```
feat(auth): 添加用户注册功能

- 实现邮箱注册流程
- 添加邮箱验证码发送
- 集成 Supabase Auth

使用 Supabase Auth 替代自建认证系统，
降低维护成本，提升安全性。
```

**Quy tắc viết Body**:
- Sử dụng dòng trống để phân tách với Header
- Giải thích "là gì" và "tại sao", không phải "làm thế nào"
- Mỗi dòng không quá 72 ký tự

#### 3. Footer (tùy chọn)

Dùng để liên kết Issue hoặc đánh dấu breaking change:

```
feat(api)!: 重构用户认证接口

BREAKING CHANGE: 认证接口从 /api/auth 迁移到 /api/v2/auth
旧接口将在下个版本移除

Closes #123, #456
```

**Footer phổ biến**:
- `Closes #123` - Đóng Issue
- `Refs #456` - Tham chiếu Issue liên quan
- `BREAKING CHANGE:` - Mô tả breaking change

## Breaking change

Khi commit chứa breaking change, có hai cách đánh dấu:

```bash
# Cách 1: Thêm ! sau type
feat(api)!: 移除废弃的 v1 接口

# Cách 2: Mô tả trong footer
feat(api): 重构认证系统

BREAKING CHANGE: 需要重新配置环境变量
```

## Tập hợp ví dụ

### Phát triển tính năng

```bash
# Tính năng đơn giản
git commit -m "feat: 添加暗黑模式切换"

# Có scope
git commit -m "feat(ui): 添加用户头像上传组件"

# Có body
git commit -m "feat(auth): 实现 JWT 刷新机制

- access token 有效期 15 分钟
- refresh token 有效期 7 天
- 自动刷新逻辑封装在 axios 拦截器中"
```

### Sửa lỗi

```bash
# Sửa lỗi đơn giản
git commit -m "fix: 修复登录按钮点击无响应"

# Có liên kết Issue
git commit -m "fix(cart): 修复购物车数量计算错误

修复当商品数量为 0 时，总价显示 NaN 的问题

Fixes #789"
```

### Các loại khác

```bash
# Tài liệu
git commit -m "docs: 添加 API 使用说明"

# Tái cấu trúc
git commit -m "refactor: 提取公共验证逻辑到 utils"

# Kiểu dáng
git commit -m "style: 统一代码缩进为 2 空格"

# Kiểm tra
git commit -m "test: 添加用户服务单元测试"

# Build
git commit -m "build: 升级 Next.js 到 14.0"

# CI
git commit -m "ci: 添加自动化部署 workflow"

# Công việc khác
git commit -m "chore: 更新依赖版本"
```

## Hướng dẫn cộng tác với AI

Để AI giúp bạn tạo commit message tiêu chuẩn:

**Ví dụ Prompt**:
> "Tôi đã sửa đổi src/components/UserCard.tsx, thêm chức năng hiển thị ảnh đại diện người dùng, và sửa lỗi tràn văn bản khi tên quá dài. Vui lòng giúp tôi tạo commit message tuân theo quy chuẩn Conventional Commits."

## Danh sách kiểm tra

- [ ] Hiểu được vai trò của Header, Body, Footer
- [ ] Có thể sử dụng scope để đánh dấu phạm vi ảnh hưởng một cách chính xác
- [ ] Biết cách đánh dấu breaking change
- [ ] Có thể viết Body mô tả rõ ràng
