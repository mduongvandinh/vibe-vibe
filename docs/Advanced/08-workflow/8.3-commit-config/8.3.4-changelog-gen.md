# 8.3.4 Tự động tạo nhật ký cập nhật——Tạo CHANGELOG

Commit message tiêu chuẩn không chỉ để trông đẹp——nó cho phép công cụ tự động tạo nhật ký phát hành.

## Tại sao cần CHANGELOG

CHANGELOG là "sổ tay hướng dẫn" cập nhật phiên bản của dự án:

- Người dùng biết phiên bản mới có những thay đổi gì
- Nhà phát triển biết đã đưa vào những breaking change nào
- Nhân viên vận hành biết có cần bước nâng cấp đặc biệt không

## Lựa chọn công cụ

| Công cụ | Đặc điểm | Trường hợp sử dụng |
|------|------|----------|
| conventional-changelog | Công cụ cũ | Kích hoạt thủ công tạo |
| standard-version | Quản lý phiên bản toàn diện | Dự án vừa và nhỏ |
| semantic-release | Phát hành hoàn toàn tự động | Tích hợp CI/CD |
| changesets | Thân thiện với Monorepo | Dự án đa package |

## Sử dụng standard-version

### Cài đặt

```bash
pnpm add -D standard-version
```

### Cấu hình package.json

```json
{
  "scripts": {
    "release": "standard-version",
    "release:minor": "standard-version --release-as minor",
    "release:major": "standard-version --release-as major"
  }
}
```

### Quy trình sử dụng

```bash
# Tự động xác định số phiên bản dựa trên lịch sử commit
pnpm release

# Chỉ định loại phiên bản
pnpm release:minor  # 1.0.0 -> 1.1.0
pnpm release:major  # 1.0.0 -> 2.0.0

# Phát hành lần đầu tiên
pnpm release -- --first-release
```

Sau khi thực thi sẽ:
1. Phân tích lịch sử commit, xác định số phiên bản
2. Cập nhật version trong `package.json`
3. Tạo/cập nhật `CHANGELOG.md`
4. Tạo commit phiên bản và tag

### Quy tắc số phiên bản

Dựa trên Semantic Versioning:

| Loại commit | Thay đổi phiên bản | Ví dụ |
|----------|----------|------|
| feat | minor | 1.0.0 → 1.1.0 |
| fix | patch | 1.0.0 → 1.0.1 |
| BREAKING CHANGE | major | 1.0.0 → 2.0.0 |

## Ví dụ kết quả CHANGELOG

```markdown
# Changelog

## [1.2.0](https://github.com/user/repo/compare/v1.1.0...v1.2.0) (2024-01-15)

### Features

* **auth:** 添加 Google OAuth 登录 ([#123](https://github.com/user/repo/issues/123)) ([abc1234](https://github.com/user/repo/commit/abc1234))
* **ui:** 支持暗黑模式切换 ([def5678](https://github.com/user/repo/commit/def5678))

### Bug Fixes

* **api:** 修复分页查询参数解析错误 ([#145](https://github.com/user/repo/issues/145)) ([ghi9012](https://github.com/user/repo/commit/ghi9012))

## [1.1.0](https://github.com/user/repo/compare/v1.0.0...v1.1.0) (2024-01-01)

### Features

* 初始化项目结构 ([jkl3456](https://github.com/user/repo/commit/jkl3456))
```

## Cấu hình tùy chỉnh

Tạo `.versionrc.json`:

```json
{
  "types": [
    { "type": "feat", "section": "Features" },
    { "type": "fix", "section": "Bug Fixes" },
    { "type": "perf", "section": "Performance" },
    { "type": "refactor", "section": "Refactoring", "hidden": true },
    { "type": "docs", "section": "Documentation", "hidden": true },
    { "type": "style", "hidden": true },
    { "type": "chore", "hidden": true },
    { "type": "test", "hidden": true },
    { "type": "build", "hidden": true },
    { "type": "ci", "hidden": true }
  ],
  "commitUrlFormat": "https://github.com/user/repo/commit/{{hash}}",
  "compareUrlFormat": "https://github.com/user/repo/compare/{{previousTag}}...{{currentTag}}"
}
```

## Tích hợp CI/CD

### GitHub Actions phát hành tự động

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    branches: [main]

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-node@v4
        with:
          node-version: '20'

      - run: pnpm install

      - name: Release
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          pnpm release
          git push --follow-tags origin main
```

## semantic-release (nâng cao)

Thích hợp cho các dự án hoàn toàn tự động hóa:

```bash
pnpm add -D semantic-release @semantic-release/changelog @semantic-release/git
```

Cấu hình `.releaserc.json`:

```json
{
  "branches": ["main"],
  "plugins": [
    "@semantic-release/commit-analyzer",
    "@semantic-release/release-notes-generator",
    "@semantic-release/changelog",
    "@semantic-release/npm",
    "@semantic-release/git",
    "@semantic-release/github"
  ]
}
```

## Các thực hành tốt nhất

1. **Giữ commit chuẩn**: Chất lượng CHANGELOG phụ thuộc vào chất lượng commit message
2. **Liên kết Issue**: Làm cho thay đổi có thể truy vết được
3. **Đánh dấu Breaking Change**: Giúp người dùng biết cách nâng cấp
4. **Phát hành thường xuyên**: Tránh CHANGELOG quá dài
