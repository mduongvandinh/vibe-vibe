# 8.4.2 Mật khẩu không nên cam kết—Quản lý tệp nhạy cảm

Một khi khóa vào lịch sử Git, ngay cả khi xóa cũng vẫn còn—vì vậy bước đầu tiên là chặn nó.

## Các loại thông tin nhạy cảm

| Loại | Ví dụ | Rủi ro |
|------|------|------|
| Mật khẩu cơ sở dữ liệu | DATABASE_URL | Rò rỉ dữ liệu |
| Khóa API | OPENAI_API_KEY | Mất chi phí |
| Khóa xác thực | JWT_SECRET | Giả mạo danh tính |
| Thông tin xác thực dịch vụ đám mây | AWS_SECRET_KEY | Tài nguyên bị đánh cắp |
| Chứng chỉ khóa riêng | *.pem, *.key | Lỗ hổng bảo mật |

## Chiến lược bỏ qua tệp .env

### Cấu hình cơ bản

```gitignore
# Bỏ qua tất cả các tệp biến môi trường
.env
.env.local
.env.development.local
.env.test.local
.env.production.local

# Nhưng giữ tệp ví dụ
!.env.example
!.env.template
```

### Quy tắc biến môi trường Next.js

```gitignore
# Biến môi trường cục bộ (không cam kết)
.env.local
.env.*.local

# Biến môi trường chung (cam kết theo nhu cầu)
# .env              # Có thể chứa các giá trị không nhạy cảm mặc định
# .env.development  # Giá trị mặc định môi trường phát triển
# .env.production   # Giá trị mặc định môi trường production
```

## Mẫu .env.example

Tạo `.env.example` để cho đồng đội biết cần những cấu hình nào:

```bash
# Cơ sở dữ liệu
DATABASE_URL=postgresql://user:password@localhost:5432/mydb

# Xác thực
NEXTAUTH_SECRET=your-secret-here
NEXTAUTH_URL=http://localhost:3000

# Dịch vụ bên thứ ba
OPENAI_API_KEY=sk-xxx
STRIPE_SECRET_KEY=sk_test_xxx

# Cấu hình tùy chọn
# REDIS_URL=redis://localhost:6379
```

**Nguyên tắc**:
- Giữ lại tên biến và định dạng
- Thay thế các giá trị thực bằng trình giữ chỗ
- Thêm bình luận tóm tắt giải thích mục đích

## Cam kết vô tình như thế nào

### Trường hợp 1: Chưa đẩy

```bash
# 1. Xóa khỏi khu vực tạm thời
git rm --cached .env

# 2. Thêm vào .gitignore
echo ".env" >> .gitignore

# 3. Sửa đổi commit trước
git commit --amend
```

### Trường hợp 2: Đã đẩy

```bash
# 1. Thay đổi ngay lập tức tất cả các khóa bị rò rỉ!

# 2. Sử dụng git-filter-repo để làm sạch lịch sử (được khuyến nghị)
pip install git-filter-repo
git filter-repo --path .env --invert-paths

# 3. Đẩy mạnh
git push --force-with-lease

# 4. Thông báo cho đội xây dựng lại
```

> **Quan trọng**: Ngay cả khi xóa khỏi lịch sử, cũng phải thay đổi khóa! Vì có thể đã bị người khác kéo.

- Khóa API OpenAI

- Và hơn thế nữa

## Công cụ quản lý biến môi trường

| Công cụ | Đặc điểm | Trường hợp sử dụng |
|------|------|----------|
| Vercel environment variables | Tích hợp với triển khai | Dự án triển khai Vercel |
| GitHub Secrets | Sử dụng CI/CD | GitHub Actions |
| Doppler | Quản lý cấp đội | Nhiều môi trường, nhiều dự án |
| 1Password | Trình quản lý mật khẩu | Nhà phát triển cá nhân |

## Lưu ý hợp tác AI

Khi hỏi AI:

**Không nên**:
```
DATABASE_URL của tôi là postgresql://admin:MyP@ssw0rd@db.example.com:5432/prod
Tại sao không thể kết nối?
```

**Nên**:
```
DATABASE_URL của tôi có định dạng postgresql://user:password@host:5432/database
Lỗi kết nối "connection refused", có thể là lý do gì?
```
