# 4.3.1 Làm sao tạo một bảng — DDL Định nghĩa dữ liệu: Câu lệnh CREATE/ALTER/DROP

### Một câu giải thích

DDL là ngôn ngữ để định nghĩa "bộ xương" của cơ sở dữ liệu — tạo bảng, sửa cấu trúc, xóa bảng đều nhờ vào nó.

### Ba thao tác DDL chính

| Thao tác | Giải thích | Mức độ nguy hiểm |
|------|------|----------|
| **CREATE** | Tạo bảng, index, view | Thấp |
| **ALTER** | Sửa cấu trúc bảng | Trung bình |
| **DROP** | Xóa bảng, index | Cao (dữ liệu sẽ mất!) |

### CREATE: Tạo bảng

**Cú pháp SQL**:
```sql
CREATE TABLE users (
  id         VARCHAR(36) PRIMARY KEY,
  email      VARCHAR(255) NOT NULL UNIQUE,
  name       VARCHAR(100),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Prisma Schema tương ứng**:
```prisma
model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String?
  createdAt DateTime @default(now())
}
```

**Đối chiếu kiểu dữ liệu thường dùng**:

| Kiểu SQL | Kiểu Prisma | Giải thích |
|----------|-------------|------|
| VARCHAR(n) | String | Chuỗi ký tự độ dài thay đổi |
| TEXT | String | Văn bản dài |
| INTEGER | Int | Số nguyên |
| BIGINT | BigInt | Số nguyên lớn |
| BOOLEAN | Boolean | Giá trị boolean |
| TIMESTAMP | DateTime | Dấu thời gian |
| DECIMAL | Decimal | Số thập phân chính xác |
| JSON | Json | Dữ liệu JSON |

### ALTER: Sửa cấu trúc bảng

**Thêm cột**:
```sql
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
```

**Sửa kiểu cột**:
```sql
ALTER TABLE users ALTER COLUMN name TYPE VARCHAR(200);
```

**Xóa cột**:
```sql
ALTER TABLE users DROP COLUMN phone;
```

**Thêm index**:
```sql
CREATE INDEX idx_users_email ON users(email);
```

**Trong Prisma**: Sửa schema.prisma rồi thực thi `npx prisma migrate dev`

### DROP: Xóa bảng

```sql
-- Xóa bảng (dữ liệu sẽ mất toàn bộ!)
DROP TABLE users;

-- Chỉ xóa nếu bảng tồn tại (tránh báo lỗi)
DROP TABLE IF EXISTS users;
```

::: danger Cảnh báo
DROP TABLE sẽ **xóa vĩnh viễn** tất cả dữ liệu, không thể phục hồi! Thận trọng khi dùng trong môi trường production.
:::

### Prisma Migration và DDL

Prisma quản lý DDL thông qua migration (di chuyển):

```bash
# 1. Sửa schema.prisma
# 2. Tạo file migration (chứa SQL)
npx prisma migrate dev --name add_phone_field

# 3. Xem SQL được tạo
cat prisma/migrations/xxx_add_phone_field/migration.sql
```

Ví dụ file migration được tạo:
```sql
-- migration.sql
ALTER TABLE "User" ADD COLUMN "phone" TEXT;
```

### Tại sao cần hiểu DDL?

1. **Debug vấn đề migration**: Khi migration thất bại cần hiểu lỗi SQL
2. **Sửa dữ liệu thủ công**: Đôi khi cần thực thi SQL trực tiếp
3. **Tối ưu hiệu suất**: Hiểu cú pháp tạo index

### Tóm tắt phần này

- DDL dùng để định nghĩa cấu trúc cơ sở dữ liệu (CREATE/ALTER/DROP)
- Prisma tự động tạo DDL thông qua migration
- DROP là thao tác nguy hiểm, sẽ xóa vĩnh viễn dữ liệu
- Hiểu DDL giúp debug và tối ưu
