# 4.4.9 Dữ liệu đảm bảo nhất quán như thế nào — Xử lý transaction: Đảm bảo tính nhất quán dữ liệu

### Tóm tắt trong một câu

Transaction cho phép nhiều thao tác hoặc thành công hoàn toàn, hoặc rollback hoàn toàn — đây là cơ chế cốt lõi để đảm bảo tính nhất quán dữ liệu.

### Các loại transaction trong Prisma

| Loại | Mục đích | Đặc điểm |
|------|------|------|
| **Sequential transaction** | Nhiều thao tác độc lập | Đơn giản, không thể thêm logic giữa các thao tác |
| **Interactive transaction** | Các thao tác có phụ thuộc | Linh hoạt, có thể thêm logic nghiệp vụ giữa các thao tác |

### Sequential transaction

```typescript
// Nhiều thao tác truyền vào dạng mảng, thực thi tuần tự
const [user, post] = await prisma.$transaction([
  prisma.user.create({
    data: { email: 'user@example.com', name: 'Người dùng' }
  }),
  prisma.post.create({
    data: { title: 'Bài viết', authorId: 'xxx' }
  })
])
```

**Tình huống áp dụng**: Nhiều thao tác độc lập cần thực thi theo nguyên tử

### Interactive transaction

```typescript
// Có thể viết logic nghiệp vụ trong transaction
const result = await prisma.$transaction(async (tx) => {
  // 1. Query số dư hiện tại
  const account = await tx.account.findUnique({
    where: { userId: senderId }
  })

  // 2. Logic nghiệp vụ kiểm tra
  if (!account || account.balance < amount) {
    throw new Error('Số dư không đủ')
  }

  // 3. Trừ số dư người gửi
  await tx.account.update({
    where: { userId: senderId },
    data: { balance: { decrement: amount } }
  })

  // 4. Cộng số dư người nhận
  await tx.account.update({
    where: { userId: receiverId },
    data: { balance: { increment: amount } }
  })

  // 5. Ghi log giao dịch
  const transaction = await tx.transaction.create({
    data: {
      senderId,
      receiverId,
      amount,
      type: 'TRANSFER'
    }
  })

  return transaction
})
```

### Tùy chọn cấu hình transaction

```typescript
await prisma.$transaction(
  async (tx) => {
    // ...
  },
  {
    maxWait: 5000,      // Thời gian chờ tối đa để lấy transaction (milliseconds)
    timeout: 10000,     // Thời gian thực thi tối đa của transaction (milliseconds)
    isolationLevel: 'Serializable'  // Mức độ cô lập
  }
)
```

**Mức độ cô lập**:

| Mức độ | Mô tả |
|------|------|
| `ReadUncommitted` | Cô lập thấp nhất, có thể đọc dữ liệu chưa commit |
| `ReadCommitted` | Chỉ đọc dữ liệu đã commit (mặc định PostgreSQL) |
| `RepeatableRead` | Đọc nhiều lần trong cùng transaction cho kết quả nhất quán |
| `Serializable` | Cô lập cao nhất, hoàn toàn tuần tự hóa |

### Tình huống transaction thường gặp

**Tình huống 1: Tạo đơn hàng + Trừ tồn kho**

```typescript
async function createOrder(userId: string, items: OrderItem[]) {
  return prisma.$transaction(async (tx) => {
    // Kiểm tra và trừ tồn kho
    for (const item of items) {
      const product = await tx.product.findUnique({
        where: { id: item.productId }
      })

      if (!product || product.stock < item.quantity) {
        throw new Error(`Sản phẩm ${item.productId} không đủ hàng`)
      }

      await tx.product.update({
        where: { id: item.productId },
        data: { stock: { decrement: item.quantity } }
      })
    }

    // Tạo đơn hàng
    const order = await tx.order.create({
      data: {
        userId,
        items: {
          create: items.map(item => ({
            productId: item.productId,
            quantity: item.quantity,
            price: item.price
          }))
        }
      }
    })

    return order
  })
}
```

**Tình huống 2: Đăng ký user + Khởi tạo dữ liệu**

```typescript
async function registerUser(data: RegisterData) {
  return prisma.$transaction(async (tx) => {
    // Tạo user
    const user = await tx.user.create({
      data: {
        email: data.email,
        name: data.name
      }
    })

    // Tạo cấu hình user
    await tx.userSettings.create({
      data: {
        userId: user.id,
        theme: 'light',
        notifications: true
      }
    })

    // Tạo ví ban đầu
    await tx.wallet.create({
      data: {
        userId: user.id,
        balance: 0
      }
    })

    return user
  })
}
```

### Nested write vs transaction

**Nested write** (Prisma tự động dùng transaction):

```typescript
// Đây đã là thao tác nguyên tử
const user = await prisma.user.create({
  data: {
    email: 'user@example.com',
    profile: {
      create: { bio: '...' }
    },
    posts: {
      create: [
        { title: 'Bài viết 1' },
        { title: 'Bài viết 2' }
      ]
    }
  }
})
```

**Khi nào cần transaction tường minh**:
- Cần thêm logic nghiệp vụ giữa các thao tác
- Cần thực hiện trên nhiều thao tác top-level
- Cần cấu hình tùy chọn transaction

### Xử lý lỗi

```typescript
try {
  await prisma.$transaction(async (tx) => {
    // ...
  })
} catch (error) {
  if (error instanceof Prisma.PrismaClientKnownRequestError) {
    // Lỗi Prisma
    if (error.code === 'P2002') {
      // Conflict unique constraint
    }
  }
  throw error
}
```

### Hướng dẫn tránh lỗi

1. **Transaction phải ngắn**: Transaction dài sẽ lock resource, ảnh hưởng đồng thời

2. **Không gọi service ngoài trong transaction**:
   ```typescript
   // Ví dụ sai
   await prisma.$transaction(async (tx) => {
     await tx.order.create({ ... })
     await sendEmail()  // Gọi bên ngoài có thể fail hoặc rất chậm
   })

   // Đúng: Transaction trước, sau đó gọi
   const order = await prisma.$transaction(async (tx) => {
     return tx.order.create({ ... })
   })
   await sendEmail()  // Gửi email sau khi transaction thành công
   ```

3. **Xử lý deadlock**: Đặt thời gian timeout hợp lý

### Tóm tắt phần này

- Sequential transaction dùng cho thực thi nguyên tử nhiều thao tác đơn giản
- Interactive transaction dùng cho tình huống cần logic nghiệp vụ
- Nested write tự động dùng transaction, tình huống đơn giản không cần transaction tường minh
- Transaction phải ngắn, tránh gọi service bên ngoài trong transaction
