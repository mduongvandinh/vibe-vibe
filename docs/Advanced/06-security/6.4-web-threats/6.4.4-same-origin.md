# 6.4.4 Same-Origin Policy: Cơ sở bảo mật trình duyệt

## Phá vỡ vấn đề bằng một câu

Same-Origin Policy là cơ chế bảo mật mặc định của trình duyệt: **chỉ những script từ cùng một "nguồn gốc" mới có thể đọc dữ liệu của nhau**. Đây là lớp bảo vệ đầu tiên của bảo mật Web.

## Giá trị cốt lõi

Hiểu Same-Origin Policy sẽ giúp bạn:
- Rõ tại sao cần CORS
- Hiểu vấn đề cross-origin khi tách riêng frontend và backend
- Biết những thao tác nào sẽ bị trình duyệt chặn

## "Cùng nguồn gốc" là gì?

Một URL được tạo thành từ giao thức, tên miền, cổng. Chỉ khi cả ba hoàn toàn giống nhau, mới được coi là "cùng nguồn gốc".

| URL A | URL B | Cùng nguồn gốc không? | Lý do |
|-------|-------|----------|------|
| `https://example.com` | `https://example.com/page` | ✅ Cùng | Đường dẫn không ảnh hưởng |
| `https://example.com` | `http://example.com` | ❌ Khác | Giao thức khác |
| `https://example.com` | `https://api.example.com` | ❌ Khác | Tên miền khác |
| `https://example.com` | `https://example.com:8080` | ❌ Khác | Cổng khác |

## Same-Origin Policy giới hạn những gì?

### Các thao tác bị giới hạn

```javascript
// ❌ Không thể đọc phản hồi yêu cầu cross-origin
fetch('https://other-site.com/api')
  .then(res => res.json())  // Bị chặn

// ❌ Không thể đọc nội dung iframe cross-origin
const iframe = document.querySelector('iframe')
iframe.contentDocument  // Bị chặn

// ❌ Không thể đọc Cookie/Storage của trang khác
localStorage.getItem('other-site-data')  // Chỉ có thể đọc của trang này
```

### Các thao tác không bị giới hạn

```html
<!-- ✅ Có thể tải tài nguyên cross-origin -->
<img src="https://other-site.com/image.png" />
<script src="https://cdn.example.com/lib.js"></script>
<link href="https://fonts.googleapis.com/css" rel="stylesheet" />

<!-- ✅ Có thể gửi yêu cầu cross-origin (nhưng không thể đọc phản hồi) -->
<form action="https://other-site.com/submit" method="POST">
```

## Cách vượt qua Same-Origin Policy một cách hợp pháp

### 1. CORS (khuyến nghị)

Máy chủ trả về header phản hồi cho phép cross-origin:

```http
Access-Control-Allow-Origin: https://your-site.com
```

### 2. Proxy

Chuyển tiếp yêu cầu qua máy chủ cùng nguồn gốc:

```typescript
// Phía client yêu cầu API cùng nguồn
fetch('/api/proxy?url=https://other-site.com/data')

// Máy chủ proxy chuyển tiếp
export async function GET(request: Request) {
  const url = new URL(request.url).searchParams.get('url')
  const res = await fetch(url!)
  return Response.json(await res.json())
}
```

### 3. JSONP (lỗi thời)

Tận dụng đặc tính thẻ `<script>` không bị giới hạn bởi Same-Origin Policy, hiện không khuyến nghị sử dụng.

## Hướng dẫn tránh lỗi

::: tip Những hiểu lầm phổ biến khi phát triển
**Vấn đề**: Khi phát triển cục bộ, `localhost:3000` gọi API của `localhost:8000` bị chặn

**Lý do**: Cổng khác = Không cùng nguồn gốc

**Giải pháp**:
1. Backend cấu hình CORS cho phép `localhost:3000`
2. Hoặc sử dụng API Routes của Next.js làm proxy
:::
