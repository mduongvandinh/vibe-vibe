# 6.4.5 Xác thực đầu vào: Phòng chống cuộc tấn công injection

## Phá vỡ vấn đề bằng một câu

Bản chất của cuộc tấn công injection là: **đầu vào của kẻ tấn công bị coi như code và được thực thi**. Chìa khóa phòng chống là: tách dữ liệu và code một cách tuyệt đối.

## Giá trị cốt lõi

Nắm vững xác thực đầu vào sẽ giúp bạn:
- Phòng chống SQL injection dẫn đến rò rỉ dữ liệu
- Phòng chống command injection dẫn đến máy chủ bị kiểm soát
- Vượt qua kiểm toán bảo mật

## Bắt đầu nhanh

### Sử dụng Zod để xác thực đầu vào

```typescript
import { z } from 'zod'

const UserSchema = z.object({
  email: z.string().email(),
  name: z.string().min(1).max(100),
  age: z.number().int().min(0).max(150),
})

export async function POST(request: Request) {
  const body = await request.json()

  const result = UserSchema.safeParse(body)
  if (!result.success) {
    return Response.json({ error: result.error.issues }, { status: 400 })
  }

  // Sử dụng result.data, type-safe
}
```

### Sử dụng Prisma để phòng chống SQL injection

```typescript
// ✅ An toàn: Prisma tự động tham số hóa
const user = await prisma.user.findUnique({
  where: { email: userInput }
})

// ✅ An toàn: Sử dụng template string của $queryRaw
const users = await prisma.$queryRaw`
  SELECT * FROM users WHERE name = ${userInput}
`

// ❌ Nguy hiểm: Sử dụng $queryRawUnsafe
const users = await prisma.$queryRawUnsafe(
  `SELECT * FROM users WHERE name = '${userInput}'`
)
```

### Các quy tắc xác thực phổ biến

```typescript
const schemas = {
  // Định dạng ID
  id: z.string().uuid(),

  // Chỉ cho phép chữ cái và số
  slug: z.string().regex(/^[a-zA-Z0-9-]+$/),

  // Số điện thoại
  phone: z.string().regex(/^1[3-9]\d{9}$/),

  // Giới hạn độ dài
  bio: z.string().max(500),

  // Giá trị enum
  role: z.enum(['user', 'admin', 'editor']),

  // Phạm vi số
  page: z.coerce.number().int().min(1).default(1),
}
```

### Xác thực tải lên tệp

```typescript
const allowedTypes = ['image/jpeg', 'image/png', 'image/webp']
const maxSize = 5 * 1024 * 1024 // 5MB

export async function POST(request: Request) {
  const formData = await request.formData()
  const file = formData.get('file') as File

  if (!allowedTypes.includes(file.type)) {
    return Response.json({ error: 'Loại tệp không được hỗ trợ' }, { status: 400 })
  }

  if (file.size > maxSize) {
    return Response.json({ error: 'Tệp quá lớn' }, { status: 400 })
  }

  // Xử lý tải lên
}
```

## Hướng dẫn tránh lỗi

::: danger Lỗi phổ biến nhất mà người mới làm
1. Chỉ xác thực ở phía client, không xác thực ở backend——xác thực phía client có thể bị vượt qua
2. Sử dụng regex để khớp "ký tự nguy hiểm"——dễ thiếu sót, nên dùng danh sách trắng
3. Ghép câu lệnh SQL——luôn sử dụng truy vấn tham số hóa
4. Tin tưởng phần mở rộng tệp——nên xác thực kiểu MIME
:::
