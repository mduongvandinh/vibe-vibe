# 6.4.2 CSRF: Xác thực token và SameSite

## Phá vỡ vấn đề bằng một câu

CSRF attack là sử dụng danh tính đăng nhập của bạn, làm cho trình duyệt của bạn thay kẻ tấn công gửi yêu cầu. Chìa khóa phòng chống là: **để máy chủ có thể phân biệt giữa "yêu cầu bạn chủ động gửi" và "yêu cầu bạn bị lừa gửi"**.

## Giá trị cốt lõi

Hiểu CSRF sẽ giúp bạn:
- Bảo vệ các thao tác nhạy cảm của người dùng không bị mạo danh
- Tránh những sự cố bảo mật "chuyển tiền thay người dùng"
- Hiểu tại sao framework hiện đại phải thiết kế như vậy

## Bắt đầu nhanh

### Giải pháp 1: SameSite Cookie (đơn giản nhất)

Các trình duyệt hiện đại hỗ trợ thuộc tính SameSite, tự động chặn Cookie được mang theo từ yêu cầu cross-site:

```typescript
// Cấu hình NextAuth
cookies: {
  sessionToken: {
    options: {
      sameSite: 'lax',  // Khuyến nghị: chặn yêu cầu POST cross-site
      secure: true,
      httpOnly: true,
    }
  }
}
```

### Giải pháp 2: CSRF Token

Nhúng token ngẫu nhiên trong biểu mẫu, xác thực khi gửi:

```tsx
// Máy chủ tạo token
import { randomBytes } from 'crypto'
const csrfToken = randomBytes(32).toString('hex')

// Form bao gồm token
<form action={submitForm}>
  <input type="hidden" name="csrf" value={csrfToken} />
  <button>Gửi</button>
</form>

// Máy chủ xác thực
export async function submitForm(formData: FormData) {
  const token = formData.get('csrf')
  if (token !== session.csrfToken) {
    throw new Error('Xác thực CSRF thất bại')
  }
}
```

### Giải pháp 3: Xác thực header Origin

```typescript
export async function POST(request: Request) {
  const origin = request.headers.get('origin')
  if (origin !== 'https://your-domain.com') {
    return Response.json({ error: 'Yêu cầu bất hợp pháp' }, { status: 403 })
  }
}
```

## Bảo vệ tích hợp của Next.js Server Actions

Khi sử dụng Server Actions, Next.js đã tự động xử lý CSRF:

```typescript
'use server'

export async function createOrder(formData: FormData) {
  // Server Actions tự động xác thực nguồn yêu cầu
  // Bạn chỉ cần tập trung vào logic kinh doanh
}
```

## Hướng dẫn tránh lỗi

::: danger Lỗi phổ biến nhất mà người mới làm
1. Sử dụng yêu cầu GET để thực thi các thao tác nhạy cảm (như `/api/delete?id=1`)
2. Quên thiết lập thuộc tính SameSite trên Cookie
3. Sử dụng API Routes nhưng quên thêm bảo vệ CSRF thủ công
:::
