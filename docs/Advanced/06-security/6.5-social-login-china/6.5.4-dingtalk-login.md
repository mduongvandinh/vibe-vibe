# 6.5.4 DingTalk Login: Enterprise Internal Application và Third-party Application

## Phá vỡ vấn đề bằng một câu

DingTalk login chủ yếu hướng tới kịch bản B2B, chia thành **ứng dụng doanh nghiệp nội bộ** (đăng nhập nhân viên) và **ứng dụng bên thứ ba** (sản phẩm SaaS), quy trình tích hợp có chút khác biệt.

## Giá trị cốt lõi

Tích hợp DingTalk login sẽ cho phép bạn:
- Cung cấp đăng nhập thuận tiện cho sản phẩm cấp doanh nghiệp
- Lấy thông tin nhận dạng doanh nghiệp của người dùng
- Tích hợp sâu với workbench DingTalk

## Hai loại ứng dụng

| Loại | Kịch bản ứng dụng | Phạm vi người dùng |
|------|----------|----------|
| Enterprise Internal Application | Hệ thống tự sử dụng của doanh nghiệp | Chỉ nhân viên doanh nghiệp này |
| Third-party Application | Sản phẩm SaaS | Tất cả người dùng DingTalk |

## Tích hợp ứng dụng doanh nghiệp nội bộ

### Điều kiện tiên quyết

1. Đăng nhập [DingTalk Open Platform](https://open.dingtalk.com/)
2. Tạo ứng dụng doanh nghiệp nội bộ
3. Lấy AppKey và AppSecret

### Mã triển khai

```typescript
// app/api/auth/dingtalk/route.ts
export async function GET() {
  const state = generateSecureState()

  const params = new URLSearchParams({
    appid: process.env.DINGTALK_APP_KEY!,
    response_type: 'code',
    scope: 'openid',
    redirect_uri: 'https://your-site.com/api/auth/dingtalk/callback',
    state,
    prompt: 'consent',
  })

  return Response.redirect(
    `https://login.dingtalk.com/oauth2/auth?${params}`
  )
}
```

```typescript
// app/api/auth/dingtalk/callback/route.ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url)
  const authCode = searchParams.get('authCode')
  const state = searchParams.get('state')

  if (!verifyState(state)) {
    return Response.redirect('/login?error=invalid_state')
  }

  // 1. Lấy user access_token
  const tokenRes = await fetch('https://api.dingtalk.com/v1.0/oauth2/userAccessToken', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      clientId: process.env.DINGTALK_APP_KEY,
      clientSecret: process.env.DINGTALK_APP_SECRET,
      code: authCode,
      grantType: 'authorization_code',
    }),
  })

  const { accessToken } = await tokenRes.json()

  // 2. Lấy thông tin người dùng
  const userRes = await fetch('https://api.dingtalk.com/v1.0/contact/users/me', {
    headers: { 'x-acs-dingtalk-access-token': accessToken },
  })

  const userInfo = await userRes.json()

  // 3. Tạo hoặc liên kết người dùng
  const user = await findOrCreateUser({
    dingtalkUnionId: userInfo.unionId,
    dingtalkOpenId: userInfo.openId,
    nickname: userInfo.nick,
    avatar: userInfo.avatarUrl,
    mobile: userInfo.mobile,
  })

  await createSession(user)
  return Response.redirect('/dashboard')
}
```

## Mã nhận dạng người dùng của DingTalk

| Mã nhận dạng | Giải thích | Giữa các ứng dụng |
|------|------|--------|
| `openId` | Duy nhất trong ứng dụng | Không |
| `unionId` | Duy nhất trong doanh nghiệp | Có (doanh nghiệp tương tự) |
| `userId` | ID danh bạ doanh nghiệp | Cần quyền bổ sung |

## Lấy thông tin doanh nghiệp

Nếu cần lấy thông tin doanh nghiệp nơi người dùng làm việc, cần gọi API bổ sung:

```typescript
// Lấy enterprise access_token
const corpTokenRes = await fetch(
  `https://oapi.dingtalk.com/gettoken?appkey=${appKey}&appsecret=${appSecret}`
)
const { access_token: corpToken } = await corpTokenRes.json()

// Lấy userId dựa trên unionId
const userIdRes = await fetch(
  `https://oapi.dingtalk.com/topapi/user/getbyunionid?access_token=${corpToken}`,
  {
    method: 'POST',
    body: JSON.stringify({ unionid: userInfo.unionId }),
  }
)

// Lấy thông tin người dùng chi tiết (bao gồm phòng ban, v.v.)
const detailRes = await fetch(
  `https://oapi.dingtalk.com/topapi/v2/user/get?access_token=${corpToken}`,
  {
    method: 'POST',
    body: JSON.stringify({ userid }),
  }
)
```

## Hướng dẫn tránh cạm bẫy

::: danger Lỗi phổ biến nhất của người mới bắt đầu
1. Nhầm lẫn API phiên bản mới và phiên bản cũ (khuyên dùng phiên bản mới v1.0)
2. Ứng dụng doanh nghiệp nội bộ chỉ có thể được sử dụng bởi nhân viên doanh nghiệp này
3. unionId chỉ giống nhau trong cùng một doanh nghiệp, khác nhau ở các doanh nghiệp khác
4. Một số API cần ủy quyền quản trị viên doanh nghiệp
:::
