# 10.5.1 Website còn sống không — Giám sát ứng dụng: Health check endpoint và thu thập chỉ số

Cứ 5 phút hỏi một lần "bạn còn khỏe không", tốt hơn nhiều so với người dùng báo cho bạn biết "down rồi".

    A[Service giám sát] -->|Request định kỳ| B[/health]

## Thiết kế health check endpoint

### Phiên bản cơ bản

```typescript
// NestJS health.controller.ts
@Controller('health')
export class HealthController {
  @Get()
  check() {
    return { status: 'ok' };
  }
}
```

### Phiên bản đầy đủ

```typescript
@Controller('health')
export class HealthController {
  constructor(
    private prisma: PrismaService,
    private redis: RedisService,
  ) {}

  @Get()
  async check() {
    const checks = {
      status: 'ok',
      timestamp: new Date().toISOString(),
      services: {},
    };

    // Kiểm tra database
    try {
      await this.prisma.$queryRaw`SELECT 1`;
      checks.services['database'] = 'ok';
    } catch {
      checks.services['database'] = 'error';
      checks.status = 'degraded';
    }

    // Kiểm tra Redis
    try {
      await this.redis.ping();
      checks.services['redis'] = 'ok';
    } catch {
      checks.services['redis'] = 'error';
      checks.status = 'degraded';
    }

    return checks;
  }

  @Get('live')
  liveness() {
    return { status: 'ok' };
  }

  @Get('ready')
  async readiness() {
    // Kiểm tra tất cả dependency đã sẵn sàng chưa
    await this.prisma.$queryRaw`SELECT 1`;
    return { status: 'ok' };
  }
}
```

## Các loại health check

| Loại | Endpoint | Công dụng |
|------|------|------|
| Liveness | `/health/live` | Process có còn sống không |
| Readiness | `/health/ready` | Có thể nhận traffic không |
| Startup | `/health/startup` | Khởi động đã hoàn tất chưa |

      start_period: 40s

## Các chỉ số quan trọng

### Chỉ số server

| Chỉ số | Giá trị cảnh báo | Giải thích |
|------|--------|------|
| CPU usage | > 80% | Cân nhắc mở rộng |
| Memory usage | > 85% | Có thể OOM |
| Disk usage | > 90% | Dọn log |
| Network bandwidth | > 80% | Nâng cấp bandwidth |

### Chỉ số ứng dụng

| Chỉ số | Giá trị cảnh báo | Giải thích |
|------|--------|------|
| Response time | > 2s | Vấn đề hiệu năng |
| Error rate | > 1% | Vấn đề code |
| QPS | Gần tới giới hạn | Cân nhắc mở rộng |

## Thu thập chỉ số tùy chỉnh

### Counter đơn giản

```typescript
// Thống kê số lần gọi API
const apiMetrics = {
  totalRequests: 0,
  errorRequests: 0,

  record(success: boolean) {
    this.totalRequests++;
    if (!success) this.errorRequests++;
  },

  getStats() {
    return {
      total: this.totalRequests,
      errors: this.errorRequests,
      errorRate: this.errorRequests / this.totalRequests,
    };
  }
};

@Get('metrics')
getMetrics() {
  return apiMetrics.getStats();
}
```

## Best practice giám sát

1. **Giám sát đa tầng**: Server + Ứng dụng + Business
2. **Khoảng thời gian hợp lý**: Giám sát bên ngoài 5 phút, bên trong có thể thường xuyên hơn
3. **Tránh báo lỗi giả**: Thiết lập số lần retry, chỉ cảnh báo khi thất bại liên tục
4. **Giám sát cái giám sát**: Đảm bảo service giám sát chính nó cũng khả dụng
5. **Ghi chép tài liệu**: Ghi lại ý nghĩa và ngưỡng của từng chỉ số

## Vấn đề thường gặp

| Vấn đề | Nguyên nhân | Giải pháp |
|------|------|----------|
| Quá nhiều báo lỗi giả | Ngưỡng thiết lập không hợp lý | Điều chỉnh ngưỡng, tăng retry |
| Giám sát chậm | Khoảng thời gian kiểm tra quá dài | Rút ngắn khoảng thời gian (nhưng chú ý chi phí) |
| Không thể truy cập | Vấn đề network/firewall | Kiểm tra quy tắc security group |
