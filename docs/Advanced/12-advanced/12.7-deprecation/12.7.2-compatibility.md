# 12.7.2 Đừng để nâng cấp làm hỏng ứng dụng cũ — Backward Compatibility: Tránh breaking changes

### Một câu phá đề

Backward compatibility có nghĩa là "phiên bản mới không phá vỡ mã cũ" — điều này cần được xem xét trong giai đoạn thiết kế để dự phòng cho sự phát triển trong tương lai.

### Breaking changes là gì

| Loại thay đổi | Ví dụ | Có phá vỡ |
|----------|------|------------|
| Thêm trường tùy chọn | Thêm trường `meta` trong phản hồi | Không |
| Thêm trường bắt buộc | Yêu cầu bao gồm `userId` | Có |
| Xóa trường | Xóa trường `legacyId` | Có |
| Đổi tên trường | `user_name` → `userName` | Có |
| Thay đổi loại | `id: number` → `id: string` | Có |
| Thay đổi hành vi | Thay đổi thứ tự sắp xếp | Có thể |

### Thêm trường thay vì xóa

```typescript
// Phản hồi phiên bản cũ
interface UserV1 {
  id: number;
  name: string;
}

// Phản hồi phiên bản mới (backward compatible)
interface UserV2 {
  id: number;
  name: string;
  email?: string;      // Trường tùy chọn mới
  displayName?: string; // Trường tùy chọn mới
}

// Mã máy khách vẫn hoạt động
function displayUser(user: UserV1) {
  console.log(user.name); // Vẫn hoạt động
}
```

### Sử dụng Adapter Pattern

Khi phải thay đổi cấu trúc, hãy cung cấp một lớp chuyển đổi:

```typescript
// Sử dụng cấu trúc mới bên trong
interface UserInternal {
  id: string; // Thay đổi thành string
  profile: {
    displayName: string;
    email: string;
  };
}

// Cung cấp cấu trúc cũ được chuyển đổi cho bên ngoài
function toV1Response(user: UserInternal): UserV1 {
  return {
    id: parseInt(user.id), // Chuyển ngược thành number
    name: user.profile.displayName,
  };
}

function toV2Response(user: UserInternal): UserV2 {
  return {
    id: user.id, // Sử dụng loại string mới
    displayName: user.profile.displayName,
    email: user.profile.email,
  };
}
```

### Feature Flags

Sử dụng feature flags để di chuyển từng bước:

```typescript
interface FeatureFlags {
  useNewUserFormat: boolean;
  enableEmailField: boolean;
}

async function getUser(id: string, flags: FeatureFlags) {
  const user = await db.user.findUnique({ where: { id } });

  if (flags.useNewUserFormat) {
    return {
      id: user.id,
      profile: {
        displayName: user.name,
        email: flags.enableEmailField ? user.email : undefined,
      },
    };
  }

  // Trả về định dạng cũ
  return {
    id: parseInt(user.id),
    name: user.name,
  };
}
```

### Kiểm tra tương thích

```typescript
import { describe, it, expect } from 'vitest';

describe('Kiểm tra tương thích API', () => {
  it('phản hồi v2 phải tương thích với máy khách v1', async () => {
    const v2Response = await fetch('/api/v2/users/1');
    const data = await v2Response.json();

    // Các trường mà máy khách v1 mong đợi phải tồn tại
    expect(data).toHaveProperty('id');
    expect(data).toHaveProperty('name');
    expect(typeof data.id).toBe('number'); // v1 mong đợi number
  });

  it('các trường mới không nên làm hỏng máy khách cũ', async () => {
    const response = await fetch('/api/v2/users/1');
    const data = await response.json();

    // Máy khách cũ bỏ qua các trường mới, không nên báo lỗi
    const oldClientCode = () => {
      console.log(data.name);
    };

    expect(oldClientCode).not.toThrow();
  });
});
```

### Hướng dẫn hợp tác với AI

- **Ý định cốt lõi**: Để AI giúp bạn đánh giá xem liệu một thay đổi API có phá vỡ tương thích.
- **Công thức định nghĩa yêu cầu**: `"Vui lòng phân tích xem thay đổi API này có phải là breaking change hay không, nếu có, hãy gợi ý cách duy trì backward compatibility."`
- **Các thuật ngữ chính**: `backward compatibility`, `breaking change`, `adapter pattern`

### Hướng dẫn tránh lỗi

- **Thêm chứ không xóa**: Không bao giờ xóa trường, chỉ thêm trường mới.
- **Tùy chọn chứ không bắt buộc**: Các trường mới nên được đặt thành tùy chọn nếu có thể.
- **Đánh dấu trong tài liệu**: Rõ ràng ghi chú những trường nào có thể thay đổi trong các phiên bản tương lai.
