# 12.7.1 Quy tắc của phiên bản API — Chiến lược phiên bản hóa API: Kiểm soát phiên bản URL/Header

### Một câu phá đề

Kiểm soát phiên bản API có ba cách chính: đường dẫn URL, tham số Query, tiêu đề yêu cầu — lựa chọn cái nào phụ thuộc vào trường hợp của bạn và sở thích của nhóm.

### So sánh các cách thực hiện

| Cách | Ví dụ | Ưu điểm | Nhược điểm |
|------|------|--------|----------|
| Đường dẫn URL | `/api/v1/users` | Trực quan, dễ cache | URL thay đổi lớn |
| Tham số Query | `/api/users?version=1` | Linh hoạt | Dễ bị bỏ qua |
| Tiêu đề yêu cầu | `Accept: application/vnd.api+json;version=1` | URL sạch | Không trực quan |

### Kiểm soát phiên bản đường dẫn URL

Cách phổ biến nhất, được khuyến nghị cho hầu hết các trường hợp:

```typescript
// app/api/v1/users/route.ts
export async function GET() {
  return Response.json({ version: 'v1', users: [] });
}

// app/api/v2/users/route.ts
export async function GET() {
  return Response.json({
    version: 'v2',
    data: { users: [] },  // v2 thay đổi cấu trúc phản hồi
    meta: { total: 0 },
  });
}
```

### Kiểm soát phiên bản tiêu đề yêu cầu

Phù hợp cho các trường hợp không muốn thay đổi URL:

```typescript
// app/api/users/route.ts
export async function GET(req: Request) {
  const version = req.headers.get('X-API-Version') || '1';

  switch (version) {
    case '1':
      return Response.json({ users: [] });
    case '2':
      return Response.json({ data: { users: [] }, meta: {} });
    default:
      return Response.json({ error: 'Phiên bản không được hỗ trợ' }, { status: 400 });
  }
}
```

### Semantic Versioning

Tuân theo quy tắc SemVer:

```
Phiên bản chính.Phiên bản phụ.Số bản vá
      ^          ^          ^
      |          |          +--- Bản vá lỗi tương thích ngược
      |          +---------- Tính năng mới tương thích ngược
      +----------------- Breaking change
```

```typescript
// Công cụ so sánh phiên bản
interface Version {
  major: number;
  minor: number;
  patch: number;
}

function parseVersion(version: string): Version {
  const [major, minor, patch] = version.split('.').map(Number);
  return { major, minor, patch };
}

function isCompatible(required: string, current: string): boolean {
  const req = parseVersion(required);
  const cur = parseVersion(current);

  // Phiên bản chính phải khớp
  if (req.major !== cur.major) return false;

  // Phiên bản hiện tại phải >= phiên bản yêu cầu
  if (cur.minor < req.minor) return false;
  if (cur.minor === req.minor && cur.patch < req.patch) return false;

  return true;
}
```

### Đa phiên bản API trong Next.js

```typescript
// lib/api-versions.ts
type Handler = (req: Request) => Promise<Response>;

const handlers: Record<string, Record<string, Handler>> = {
  'v1': {
    'GET /users': async () => Response.json({ users: [] }),
  },
  'v2': {
    'GET /users': async () => Response.json({ data: { users: [] } }),
  },
};

export function createVersionedHandler(path: string) {
  return async (req: Request) => {
    const version = req.headers.get('X-API-Version') || 'v2'; // phiên bản mặc định mới nhất
    const method = req.method;
    const key = `${method} ${path}`;

    const handler = handlers[version]?.[key];
    if (!handler) {
      return Response.json({ error: 'Endpoint không tồn tại' }, { status: 404 });
    }

    return handler(req);
  };
}
```

### Hướng dẫn hợp tác với AI

- **Ý định cốt lõi**: Để AI giúp bạn thiết kế chiến lược phiên bản hóa API.
- **Công thức định nghĩa yêu cầu**: `"Vui lòng giúp tôi thiết kế một phương án kiểm soát phiên bản cho Next.js API, hỗ trợ cả phiên bản đường dẫn URL và phiên bản tiêu đề yêu cầu."`
- **Các thuật ngữ chính**: `API versioning`, `SemVer`, `backward compatibility`, `breaking change`

### Hướng dẫn tránh lỗi

- **Bắt đầu từ v1**: Không dùng v0, nó gợi ý sự không ổn định.
- **Cập nhật tài liệu**: Mỗi phiên bản cần tài liệu riêng biệt.
- **Đặt phiên bản mặc định**: Khi không chỉ định phiên bản, hãy sử dụng phiên bản ổn định (không nhất thiết là phiên bản mới nhất).
