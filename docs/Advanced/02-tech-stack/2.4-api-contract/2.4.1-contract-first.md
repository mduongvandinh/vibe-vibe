# 2.4.1 Thống nhất trước, viết code sau — Contract first

## Một câu phá đề

Bản chất của contract first là: **Trước khi viết bất kỳ code nào, trước tiên dùng TypeScript type để định nghĩa chặt format interface**. Frontend-backend phát triển dựa trên cùng một định nghĩa type, khi liên điều chỉ cần xác minh implementation có tuân thủ contract hay không.

## Hình thức của contract

### Định nghĩa TypeScript type

```typescript
// types/api.ts
// Đây chính là "contract": format request và response

// Format response chung
interface ApiResponse<T> {
  code: number
  message: string
  data: T
}

// Liên quan đến user
interface User {
  id: string
  name: string
  email: string
  avatar?: string
  createdAt: string
}

interface CreateUserInput {
  name: string
  email: string
  password: string
}

interface UpdateUserInput {
  name?: string
  avatar?: string
}

// Liên quan đến bài viết
interface Post {
  id: string
  title: string
  content: string
  author: User
  createdAt: string
  updatedAt: string
}

interface CreatePostInput {
  title: string
  content: string
}
```

### Zod Schema (Xác thực runtime)

```typescript
// schemas/user.ts
import { z } from 'zod'

export const CreateUserSchema = z.object({
  name: z.string().min(2, 'Tên tối thiểu 2 ký tự'),
  email: z.string().email('Định dạng email không đúng'),
  password: z.string().min(8, 'Mật khẩu tối thiểu 8 ký tự'),
})

export const UpdateUserSchema = z.object({
  name: z.string().min(2).optional(),
  avatar: z.string().url().optional(),
})

// Xuất TypeScript type từ Zod Schema
export type CreateUserInput = z.infer<typeof CreateUserSchema>
export type UpdateUserInput = z.infer<typeof UpdateUserSchema>
```

## Cách tổ chức contract

### Cấu trúc thư mục

```
src/
├── types/
│   ├── api.ts        # API type chung
│   ├── user.ts       # Type liên quan đến user
│   └── post.ts       # Type liên quan đến bài viết
├── schemas/
│   ├── user.ts       # User validation Schema
│   └── post.ts       # Post validation Schema
└── app/
    └── api/
        └── users/
            └── route.ts  # API implementation
```

### Ví dụ file contract hoàn chỉnh

```typescript
// types/user.ts

// ============ Entity type ============
export interface User {
  id: string
  name: string
  email: string
  avatar: string | null
  role: 'admin' | 'user'
  createdAt: string
  updatedAt: string
}

// ============ Request type ============
export interface CreateUserRequest {
  name: string
  email: string
  password: string
}

export interface UpdateUserRequest {
  name?: string
  avatar?: string
}

export interface ListUsersRequest {
  page?: number
  pageSize?: number
  search?: string
}

// ============ Response type ============
export interface UserResponse {
  code: number
  message: string
  data: User
}

export interface UsersListResponse {
  code: number
  message: string
  data: {
    users: User[]
    total: number
    page: number
    pageSize: number
  }
}
```

## Frontend-backend sử dụng contract như thế nào

### Backend implementation

```typescript
// app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { CreateUserSchema } from '@/schemas/user'
import type { UserResponse, CreateUserRequest } from '@/types/user'

export async function POST(request: NextRequest) {
  const body: CreateUserRequest = await request.json()

  // Sử dụng Zod để xác thực
  const validated = CreateUserSchema.safeParse(body)
  if (!validated.success) {
    return NextResponse.json({
      code: 400,
      message: 'Lỗi tham số',
      errors: validated.error.flatten().fieldErrors,
    }, { status: 400 })
  }

  // Tạo user
  const user = await prisma.user.create({
    data: validated.data,
  })

  // Trả về response tuân thủ contract
  const response: UserResponse = {
    code: 200,
    message: 'Tạo thành công',
    data: user,
  }

  return NextResponse.json(response)
}
```

### Frontend gọi API

```typescript
// services/user.ts
import type {
  CreateUserRequest,
  UserResponse,
  UsersListResponse
} from '@/types/user'

export async function createUser(data: CreateUserRequest): Promise<UserResponse> {
  const res = await fetch('/api/users', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  })
  return res.json()
}

export async function getUsers(params?: { page?: number }): Promise<UsersListResponse> {
  const searchParams = new URLSearchParams()
  if (params?.page) searchParams.set('page', String(params.page))

  const res = await fetch(`/api/users?${searchParams}`)
  return res.json()
}
```

## Quy chuẩn thiết kế API

### RESTful style

| Thao tác | HTTP Method | URL | Ví dụ |
|------|-----------|-----|------|
| Danh sách | GET | /api/users | Lấy danh sách user |
| Chi tiết | GET | /api/users/:id | Lấy một user |
| Tạo | POST | /api/users | Tạo user |
| Cập nhật | PUT/PATCH | /api/users/:id | Cập nhật user |
| Xóa | DELETE | /api/users/:id | Xóa user |

### Format response thống nhất

```typescript
// Response thành công
{
  "code": 200,
  "message": "Thao tác thành công",
  "data": { ... }
}

// Response lỗi
{
  "code": 400,
  "message": "Lỗi tham số",
  "errors": {
    "email": ["Định dạng email không đúng"]
  }
}

// Response phân trang
{
  "code": 200,
  "message": "Lấy thành công",
  "data": {
    "items": [...],
    "total": 100,
    "page": 1,
    "pageSize": 10
  }
}
```

## Giác ngộ: Vấn đề thường gặp trong thiết kế contract

### 1. Type quá rộng

```typescript
// ❌ Quá rộng, AI không biết format cụ thể
interface ApiResponse {
  data: any
}

// ✅ Định nghĩa type rõ ràng
interface UserResponse {
  code: number
  message: string
  data: User
}
```

### 2. Request và Response type dùng chung

```typescript
// ❌ Khi tạo không nên có id
interface User {
  id: string
  name: string
}
// Khi tạo user cũng phải truyền id?

// ✅ Tách riêng input và output type
interface User {
  id: string
  name: string
}

interface CreateUserInput {
  name: string  // Khi tạo không cần id
}
```

### 3. Lạm dụng optional field

```typescript
// ❌ Toàn bộ optional, contract hình đồng hư
interface CreateUserInput {
  name?: string
  email?: string
}

// ✅ Bắt buộc và optional rõ ràng
interface CreateUserInput {
  name: string   // Bắt buộc
  email: string  // Bắt buộc
  avatar?: string  // Optional
}
```

## Hướng dẫn cộng tác với AI

**Ý định cốt lõi**: Để AI generate code dựa trên contract

**Thuật ngữ then chốt**: `TypeScript type`, `Zod Schema`, `API contract`, `Request type`, `Response type`

**Chiến lược tương tác**:
1. Trước tiên cho AI xem file định nghĩa type
2. Nói với AI: "Dựa trên định nghĩa type này, giúp tôi implement API"
3. Code do AI generate sẽ tự động tuân thủ contract

```
Ví dụ Prompt:
"Dựa trên CreateUserRequest và UserResponse type trong types/user.ts,
giúp tôi implement POST /api/users interface, sử dụng Prisma để thao tác database"
```

## Tóm tắt phần này

| Nguyên tắc | Giải thích |
|------|------|
| Type ưu tiên | Trước khi viết code, định nghĩa TypeScript type trước |
| Single source of truth | Định nghĩa type quản lý tập trung, frontend-backend dùng chung |
| Tách input output | CreateInput và Entity là type khác nhau |
| Runtime validation | Dùng Zod để xác thực data lúc runtime |
