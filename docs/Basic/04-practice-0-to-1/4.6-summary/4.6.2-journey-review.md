# 4.6.2 Nhìn lại hành trình hoàn chỉnh từ 0 đến 1

> **Mục tiêu bước này**: Nhìn lại toàn bộ quá trình phát triển, hiểu cách mỗi bước liên kết tư duy chương 2 và kỹ thuật chương 3

## Chuỗi hoàn chỉnh từ ý tưởng đến sản phẩm

Hãy dùng sơ đồ sau để nhìn lại con đường hoàn chỉnh bạn đã đi qua:

```
Chương 2: Nghĩ rõ ràng        Chương 3: Nói rõ ràng          Chương 4: Làm ra sản phẩm
─────────────                ─────────────                  ─────────────

  Phát hiện vấn đề              Tư duy ngữ cảnh
     │                            │
     ▼                            ▼
  Tư duy JTBD  ─────────────────▶  Tích hợp PRD  ──────────────▶  4.1 Chuẩn bị
     │                            │                                │
     ▼                            ▼                                ▼
  Ba câu hỏi linh hồn          Framework S.C.A.F.F. ──────────▶  4.2 Trang tĩnh
     │                            │                                │
     ▼                            ▼                                ▼
  Tư duy trừ  ─────────────────▶  Đối thoại lặp  ──────────────▶  4.3 Chức năng cốt lõi
  (Định nghĩa MVP)                 │                                │
     │                            ▼                                ▼
     ▼                        Chẩn đoán vấn đề  ──────────────▶  4.4 Lưu trữ dữ liệu
  Tư duy ngược  ─────────────────▶  Chiến lược sửa  ──────────────▶  4.5 Debug
  (Dự đoán thất bại)

```

Mỗi chương không đứng riêng lẻ. Kết quả tư duy chương 2, thông qua kỹ thuật thể hiện chương 3, cuối cùng trở thành code có thể chạy được ở chương 4.

## Công cụ tư duy được dùng trong mỗi vòng lặp

Bảng dưới đây cho thấy tư duy và kỹ thuật hỗ trợ phía sau mỗi bước của chương 4:

| Bước chương 4 | Tư duy chương 2 được dùng | Kỹ thuật chương 3 được dùng | Kết quả cốt lõi |
|-----------|-----------------|-----------------|---------|
| **4.1 Chuẩn bị** | Ba câu hỏi linh hồn (xác nhận hướng đi), Định nghĩa MVP (làm rõ phạm vi) | Tích hợp PRD (tổng hợp yêu cầu) | Thẻ khởi động dự án |
| **4.2 Trang tĩnh** | Tư duy câu chuyện (kịch bản người dùng), User persona | Viết Prompt bằng framework S.C.A.F.F. | Khung trang trực quan hóa |
| **4.3 Chức năng cốt lõi** | Tư duy trừ (chỉ làm tính năng P0) | Đối thoại lặp (triển khai từng tính năng) | Tính năng thêm/xóa/hoàn thành |
| **4.4 Lưu trữ dữ liệu** | — | Prompt tiệm tiến (triển khai từng bước) | Lưu trữ bền vững localStorage |
| **4.5 Debug** | Tư duy ngược (dự đoán vấn đề có thể) | Quy trình Chẩn đoán→Sửa→Xác nhận | Khả năng giải quyết vấn đề |

Giá trị của bảng này là: **Lần sau khi làm dự án mới, bạn có thể thao tác theo cùng mô hình này**.

## Dữ liệu về thời gian và kết quả

Hãy xem dữ liệu thực tế để hoàn thành dự án này:

### Phân bổ thời gian

| Giai đoạn | Thời gian đầu tư | Kết quả |
|------|---------|------|
| 4.1 Chuẩn bị | Khoảng 15 phút | Định nghĩa dự án rõ ràng |
| 4.2 Trang tĩnh | Khoảng 20 phút | UI trang hoàn chỉnh |
| 4.3 Chức năng cốt lõi | Khoảng 35 phút | Ba tính năng thêm, xóa, sửa |
| 4.4 Lưu trữ dữ liệu | Khoảng 20 phút | Lưu trữ dữ liệu bền vững |
| 4.5 Debug | Khoảng 15-20 phút | Kinh nghiệm giải quyết vấn đề |
| **Tổng cộng** | **Khoảng 2 giờ** | **Ứng dụng hoàn chỉnh có thể dùng** |

### So sánh Prompt và Code

| Chỉ số | Giá trị | Giải thích |
|------|------|------|
| Số lượng Prompt gửi đi | Khoảng 10-15 câu | Bao gồm tạo ban đầu và điều chỉnh sửa |
| Số dòng code tạo ra | Khoảng 150-250 dòng | HTML + CSS + JavaScript |
| Code bạn cần hiểu | 0 dòng | AI xử lý tất cả chi tiết kỹ thuật |
| Yêu cầu bạn cần thể hiện rõ | 100% | Đây là công việc cốt lõi của bạn |

**Hiểu biết then chốt**: Vibe Coding chuyển công việc của bạn từ "viết code" thành "thể hiện yêu cầu". Thời gian bạn dành để nghĩ rõ và nói rõ, code do AI tạo ra.

## Quan hệ tiến triển của ba vòng lặp

Nhìn lại ba vòng lặp 4.2-4.4, chúng có quan hệ tiến triển rõ ràng:

```
Vòng 1 (4.2)              Vòng 2 (4.3)              Vòng 3 (4.4)
─────────────            ─────────────            ─────────────
   Trang tĩnh               Tính năng tương tác       Lưu trữ dữ liệu

   "Vỏ rỗng"        →      "Sống động"        →      "Nhớ được"

 Chỉ có ngoại hình         Nhấn có phản ứng          Làm mới không mất
 Không có tính năng        Nhưng làm mới là mất      Thực sự có thể dùng
```

Mô hình lặp ba vòng "tĩnh→tương tác→lưu trữ" này là nhịp độ phát triển phổ quát. Khi làm dự án khác, bạn cũng có thể tiến hành theo thứ tự này.

## Nếu làm lại một lần, những chỗ có thể nhanh hơn

Dựa trên kinh nghiệm lần này, nếu làm lại một lần, những điểm sau có thể giúp bạn tăng tốc:

### Khâu có thể nhanh hơn

| Khâu | Phương pháp tăng tốc |
|------|---------|
| Viết Prompt đầu tiên | Dùng trực tiếp template chương 3, không cần nghĩ từ đầu |
| Điều chỉnh style | Mô tả rõ sở thích thiết kế ngay từ đầu, giảm sửa đi sửa lại |
| Triển khai tính năng | Một Prompt triển khai một tính năng hiệu quả hơn yêu cầu nhiều tính năng cùng lúc |
| Debug | Cung cấp thông tin lỗi đầy đủ, AI sửa chính xác hơn |

### Nguyên nhân "chậm" thường gặp

| Biểu hiện chậm | Nguyên nhân | Phương pháp cải thiện |
|---------|------|---------|
| AI tạo ra không như ý | Prompt mô tả không đủ cụ thể | Dùng framework S.C.A.F.F. bổ sung thông tin |
| Điều chỉnh style nhiều lần | Không nói trước sở thích thiết kế | Mô tả màu sắc, phong cách ngay từ Prompt đầu tiên |
| Debug mất quá nhiều thời gian | Không cung cấp đủ thông tin lỗi cho AI | Copy toàn bộ lỗi console |
| Làm tính năng dở dang | Muốn triển khai quá nhiều tính năng cùng lúc | Một lần chỉ làm một tính năng, xác nhận xong rồi làm tiếp |

## Template quy trình làm việc có thể tái sử dụng

Dựa trên kinh nghiệm lần này, tổng kết một quy trình Vibe Coding có thể tái sử dụng:

```
┌─────────────────────────────────────────────────────────────┐
│                  Quy trình dự án Vibe Coding                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Giai đoạn chuẩn bị                                          │
│  ──────                                                     │
│  1. Trả lời ba câu hỏi linh hồn: User là ai? Đau đầu ở đâu? │
│     Tại sao chọn bạn?                                        │
│  2. Xác định phạm vi MVP: Lần đầu chỉ làm gì? Rõ ràng       │
│     không làm gì?                                            │
│  3. Sắp xếp thẻ khởi động dự án: Cấu trúc hóa kết quả tư duy │
│                                                             │
│  Giai đoạn phát triển                                        │
│  ──────                                                     │
│  4. Vòng 1 - Trang tĩnh: Viết Prompt bằng framework S.C.A.F.F.│
│  5. Vòng 2 - Chức năng cốt lõi: Một lần một tính năng, lặp   │
│     triển khai                                               │
│  6. Vòng 3 - Lưu trữ dữ liệu: Chọn phương án lưu trữ theo    │
│     nhu cầu                                                  │
│                                                             │
│  Giai đoạn hoàn thiện                                        │
│  ──────                                                     │
│  7. Kiểm thử toàn diện: Xác nhận từng mục theo danh sách     │
│     chức năng                                                │
│  8. Backup lưu trữ: Giữ lại phiên bản hiện tại, thuận tiện   │
│     sửa đổi sau này                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

Quy trình này không chỉ áp dụng cho danh sách công việc, bất kỳ dự án nào bạn muốn làm bằng Vibe Coding đều có thể tham khảo.
