# 3.7.1 Ôn tập điểm cốt lõi của chương

## Tổng quan 6 kỹ năng cốt lõi

Chương này dạy bạn 6 kỹ năng cốt lõi. Nhớ bảng này, bạn sẽ nhớ được tinh túy của cả chương:

| Kỹ năng | Câu hỏi cốt lõi | Câu trả lời một dòng | Phần tương ứng |
|-----|---------|-----------|---------|
| **Tư duy Context** | AI cần biết gì? | Background dự án + Chi tiết task + Nhu cầu cá nhân | 3.1 |
| **Diễn đạt có cấu trúc** | Cách tổ chức thông tin? | Dùng framework S.C.A.F.F. hoặc R.G.C. | 3.2 |
| **Lựa chọn kỹ thuật** | Tình huống nào dùng kỹ thuật nào? | Zero-shot → Few-shot → CoT → ToT | 3.3 |
| **Tích hợp PRD** | Biến ý tưởng thành task brief như thế nào? | Tích hợp thành quả Chương 2, điền vào template PRD | 3.4 |
| **Đối thoại lặp lại** | AI làm không đúng thì sao? | Feedback chính xác + Tiến gần dần | 3.5 |
| **Xử lý vấn đề** | AI báo lỗi thì sao? | Chẩn đoán nguyên nhân + Sửa chính xác + Xác minh hallucination | 3.6 |


## Lột xác từ "Prompt kém" đến "Prompt tốt"

Sau khi học xong chương này, prompt của bạn nên có sự thay đổi như sau:

### Trước khi lột xác: Mơ hồ, không đầy đủ

```
Giúp tôi làm một danh sách todo
```

Checklist vấn đề:
- ❌ Không có background dự án
- ❌ Không có tech stack
- ❌ Không có phạm vi chức năng
- ❌ Không có điều kiện ràng buộc
- ❌ Không có format đầu ra


### Sau khi lột xác: Rõ ràng, có cấu trúc

```markdown
【Situation - Tình huống】
Tôi đang làm một ứng dụng web danh sách todo cá nhân.
Tech stack: React + TypeScript + Tailwind CSS
Người dùng mục tiêu: Nhân viên văn phòng mới, hay quên việc (chính là tôi)
Nguyên tắc thiết kế: Cực kỳ đơn giản, mở ra là thấy todo hôm nay, thêm task xong trong 3 giây

【Challenge - Thử thách】
Implement chức năng "thêm task":
- Người dùng nhập nội dung task vào input box
- Nhấn phím Enter hoặc click nút thêm, task được thêm vào danh sách
- Thêm thành công thì tự động xóa nội dung input box
- Không được thêm nội dung trống (hiển thị thông báo đơn giản)

【Audience - Đối tượng】
Người maintain code là tôi, người mới học React, vui lòng thêm comment ở các logic quan trọng

【Format - Định dạng】
Cho tôi code hoàn chỉnh component AddTask, sử dụng TypeScript

【Foundations - Ràng buộc】
- Không dùng bất kỳ thư viện quản lý state nào
- Không dùng bất kỳ thư viện UI component nào
- Style dùng Tailwind CSS
```

Checklist kiểm tra:
- ✅ Có background dự án
- ✅ Có tech stack
- ✅ Có phạm vi chức năng
- ✅ Có điều kiện ràng buộc
- ✅ Có format đầu ra


## Sơ đồ ra quyết định lựa chọn kỹ thuật

Gặp task không biết dùng kỹ thuật nào? Đi theo flow này:

```
Bắt đầu
  │
  ▼
┌─────────────────────────────────────┐
│ AI có "làm được trực tiếp" không?    │
│ (Chuyển đổi code, tạo nội dung,      │
│  giải thích code)                    │
└─────────────────────────────────────┘
  │
  ├─ Có ──────────────────────────────▶ Zero-shot (hỏi trực tiếp)
  │
  ▼ Không
┌─────────────────────────────────────┐
│ Cần format đầu ra cụ thể không?     │
│ (API docs, phân loại, bắt chước      │
│  phong cách)                         │
└─────────────────────────────────────┘
  │
  ├─ Có ──────────────────────────────▶ Few-shot (cho 2-3 ví dụ)
  │
  ▼ Không
┌─────────────────────────────────────┐
│ Cần suy luận/phân tích nhiều bước?  │
│ (Phân tích độ phức tạp, debug Bug,   │
│  review logic)                       │
└─────────────────────────────────────┘
  │
  ├─ Có ──────────────────────────────▶ Chain of Thought (suy nghĩ từng bước)
  │
  ▼ Không
┌─────────────────────────────────────┐
│ Cần so sánh nhiều phương án?        │
│ (Chọn công nghệ, quyết định kiến trúc) │
└─────────────────────────────────────┘
  │
  ├─ Có ──────────────────────────────▶ Tree of Thoughts (so sánh nhiều phương án)
  │
  ▼ Không
┌─────────────────────────────────────┐
│ Chất lượng đầu ra rất quan trọng?   │
│ (Core code, tài liệu công khai)     │
└─────────────────────────────────────┘
  │
  ├─ Có ──────────────────────────────▶ Thêm Self-Critique (tự kiểm tra sửa)
  │
  ▼ Không
    Zero-shot là đủ
```


## Bảng tham khảo nhanh tình huống sử dụng 5 kỹ thuật

| Kỹ thuật | Tần suất sử dụng | Tình huống điển hình | Từ khóa |
|-----|---------|---------|-------|
| **Zero-shot** | 50% | Chuyển đổi code, tạo nội dung, giải thích code | "Hỏi trực tiếp" |
| **Few-shot** | 25% | Tạo API docs, phân loại, bắt chước phong cách | "Cho ví dụ" |
| **Chain of Thought** | 15% | Phân tích độ phức tạp, debug Bug, review logic | "Chia bước" |
| **Tree of Thoughts** | 2% | Chọn công nghệ, quyết định kiến trúc | "So phương án" |
| **Self-Critique** | 8% | Core code, tài liệu công khai | "Tự kiểm tra" |

**Gợi ý thực hành**:
1. Bắt đầu thử với Zero-shot
2. Nếu output không thỏa mãn, nâng cấp lên kỹ thuật khác
3. Output quan trọng nhớ thêm Self-Critique

## 3 công thức chính của chương

Nhớ 3 công thức này, bạn nắm được tinh túy của chương:

### Công thức 1: Chất lượng output AI

> **Chất lượng output AI = Chất lượng context × Năng lực AI**

Năng lực AI là cố định, điều bạn kiểm soát được chỉ có chất lượng context.

### Công thức 2: Prompt tốt

> **Prompt tốt = Background + Task + Ràng buộc + Format + Ví dụ (tùy chọn)**

Thiếu bất kỳ yếu tố nào, output của AI đều có thể lệch khỏi kỳ vọng.

### Công thức 3: Sửa lặp lại

> **Sửa chính xác = Chỉ ra vấn đề + Nói rõ lý do + Đưa ra kỳ vọng**

"Không đúng" mơ hồ không bằng "chỗ này nên như thế này" chính xác.


## Bảng tham khảo nhanh 4 loại Code Hallucination

| Loại | Mức độ nguy hiểm | Biểu hiện | Phương pháp xác minh |
|-----|---------|------|---------|
| **Package hallucination** | 🔴 Cao | Gợi ý package npm/pip không tồn tại | `npm search <tên package>` hoặc truy cập trang chính thức |
| **API hallucination** | 🟡 Trung bình | Bịa function hoặc method không tồn tại | Tham khảo tài liệu chính thức |
| **Logic hallucination** | 🟡 Trung bình | Logic code không khớp với mô tả | Test với trường hợp biên |
| **Version hallucination** | 🟡 Trung bình | Dùng syntax hoặc API đã deprecated | Kiểm tra tính tương thích phiên bản |

**Thói quen xác minh**: Với package và API mà AI gợi ý, xác minh trước khi sử dụng.
