# 3.7.3 Danh sách tham khảo nhanh Prompt

Phần này cung cấp một loạt checklist và template có thể sử dụng trực tiếp, nên lưu lại hoặc in ra để dùng.


## Bảng tham khảo 1 trang: Bắt buộc kiểm tra trước khi hỏi

Trước khi hỏi AI, kiểm tra nhanh 9 mục này:

```
┌─────────────────────────────────────────────────────────────┐
│                    Checklist tự kiểm Prompt v1.0             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  □ 1. Tôi đã nói rõ【Background】chưa?                       │
│       (Loại dự án, tech stack, tiến độ hiện tại)            │
│                                                             │
│  □ 2. Tôi đã nói rõ【Task】chưa?                             │
│       (Làm gì, input output là gì)                          │
│                                                             │
│  □ 3. Tôi đã nói rõ【Ràng buộc】chưa?                        │
│       (Giới hạn bắt buộc tuân thủ, không được làm gì)       │
│                                                             │
│  □ 4. Tôi đã nói rõ【Format】chưa?                           │
│       (Muốn code đầy đủ hay đoạn code, cần comment không)   │
│                                                             │
│  □ 5. Tôi đã cho【Ví dụ】chưa?                               │
│       (Nếu cần output format cụ thể)                        │
│                                                             │
│  □ 6. Prompt của tôi đủ【Cụ thể】chưa?                       │
│       (Có thể mô tả kỳ vọng chính xác hơn không)            │
│                                                             │
│  □ 7. Tôi đã nói AI【Không được làm gì】chưa?                │
│       (Ngăn AI "diễn thêm")                                 │
│                                                             │
│  □ 8. Tôi đã chuẩn bị sẵn sàng【Lặp lại】chưa?               │
│       (Không kỳ vọng một lần hoàn hảo)                      │
│                                                             │
│  □ 9. Tôi đã tích hợp【Thành quả tư duy Chương 2】chưa?      │
│       (User persona, phạm vi MVP, 3 câu hỏi linh hồn)       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```


## Template Prompt theo tình huống

### Tình huống 1: Tạo code

Áp dụng cho: Tạo component mới, implement chức năng mới, tạo module hoàn chỉnh

```markdown
【Background】
Loại dự án: [Ứng dụng web/Phân tích dữ liệu/Script tự động/...]
Tech stack: [React/Python/Node.js/...]
Tiến độ hiện tại: [Dự án mới bắt đầu/Đã có cấu trúc cơ bản/...]

【Task】
Vui lòng giúp tôi implement [Tên chức năng]:
- Mô tả chức năng: [User làm gì, hệ thống làm gì]
- Input: [User nhập gì]
- Output: [Hệ thống xuất gì]

【Ràng buộc】
Bắt buộc:
- [Ràng buộc 1]
- [Ràng buộc 2]

Không được:
- [Ràng buộc 3]
- [Ràng buộc 4]

【Yêu cầu format】
- [ ] File code hoàn chỉnh
- [ ] Có type TypeScript
- [ ] Có comment quan trọng
- [ ] Có hướng dẫn sử dụng
```

**Ví dụ điền**:

```markdown
【Background】
Loại dự án: Ứng dụng web danh sách todo cá nhân
Tech stack: React + TypeScript + Tailwind CSS
Tiến độ hiện tại: Dự án đã init, đã có component AddTask

【Task】
Vui lòng giúp tôi implement chức năng "xóa task":
- Mô tả chức năng: User click icon xóa bên phải task, task đó bị xóa khỏi danh sách
- Input: User click icon xóa
- Output: Task biến mất khỏi danh sách, hiển thị thông báo ngắn để hoàn tác

【Ràng buộc】
Bắt buộc:
- Trước khi xóa hiển thị xác nhận (tránh xóa nhầm)
- Sau khi xóa có thể hoàn tác trong 3 giây
- Style dùng Tailwind CSS

Không được:
- Không dùng bất kỳ thư viện UI component nào
- Không dùng confirm() popup (trải nghiệm không tốt)

【Yêu cầu format】
- [x] File code hoàn chỉnh
- [x] Có type TypeScript
- [x] Có comment quan trọng
- [ ] Có hướng dẫn sử dụng
```


### Tình huống 2: Sửa code

Áp dụng cho: Sửa Bug, tối ưu performance, refactor code

```markdown
【Code hiện tại】
```[ngôn ngữ]
[Paste code hiện tại]
```

【Mô tả vấn đề】
Vấn đề hiện tại là: [Mô tả cụ thể hiện tượng vấn đề]
Hành vi mong đợi là: [Mô tả hành vi đúng]

【Yêu cầu sửa】
- [Yêu cầu 1]
- [Yêu cầu 2]

【Ràng buộc】
- Chỉ sửa phần cần thiết, giữ nguyên code khác
- [Ràng buộc khác]
```

**Ví dụ điền**:

```markdown
【Code hiện tại】
```typescript
const handleSubmit = () => {
  if (inputValue) {
    addTask(inputValue);
    setInputValue('');
  }
}
```

【Mô tả vấn đề】
Vấn đề hiện tại là: Nhập khoảng trắng vẫn thêm được task
Hành vi mong đợi là: Chỉ khi thực sự có nội dung mới được thêm, khoảng trắng phải bị bỏ qua

【Yêu cầu sửa】
- Trước khi thêm bỏ khoảng trắng đầu cuối
- Sau khi bỏ khoảng trắng nếu rỗng thì hiển thị thông báo

【Ràng buộc】
- Chỉ sửa phần cần thiết, giữ nguyên code khác
- Thông báo dùng toast không dùng alert
```


### Tình huống 3: Debug vấn đề

Áp dụng cho: Code báo lỗi, chức năng bất thường, vấn đề performance

```markdown
【Hiện tượng vấn đề】
[Mô tả những gì bạn thấy]

【Hành vi mong đợi】
[Mô tả những gì bạn mong đợi thấy]

【Code liên quan】
```[ngôn ngữ]
[Paste code liên quan]
```

【Phương pháp đã thử】
1. [Thử 1]: [Kết quả]
2. [Thử 2]: [Kết quả]

【Thông tin môi trường】
- Browser/Môi trường chạy: [Phiên bản]
- Phiên bản thư viện liên quan: [Phiên bản]

【Vui lòng giúp tôi】
1. Phân tích nguyên nhân có thể
2. Đưa ra giải pháp
3. Giải thích tại sao xuất hiện vấn đề này
```

**Ví dụ điền**:

```markdown
【Hiện tượng vấn đề】
Click nút "hoàn thành task" thì trạng thái task không đổi, console không báo lỗi

【Hành vi mong đợi】
Click vào thì vòng tròn bên trái task nên chuyển sang trạng thái đã chọn

【Code liên quan】
```typescript
const toggleComplete = (id: string) => {
  setTasks(tasks.map(task =>
    task.id === id ? { ...task, complete: !task.complete } : task
  ));
}
```

【Phương pháp đã thử】
1. Kiểm tra id có truyền đúng không: console.log xác nhận id đúng
2. Kiểm tra state tasks: Mảng tasks trước và sau update không đổi

【Thông tin môi trường】
- Browser: Chrome 120
- Phiên bản React: 18.2.0

【Vui lòng giúp tôi】
1. Phân tích nguyên nhân có thể
2. Đưa ra giải pháp
3. Giải thích tại sao xuất hiện vấn đề này
```


### Tình huống 4: Chọn công nghệ

Áp dụng cho: Chọn thư viện, framework, phương án kiến trúc

```markdown
【Background dự án】
[Mô tả ngắn gọn dự án]

【Nhu cầu chọn lựa】
Tôi cần chọn [Loại lựa chọn], chủ yếu xem xét:
- [Yếu tố xem xét 1]
- [Yếu tố xem xét 2]
- [Yếu tố xem xét 3]

【Phương án ứng cử】(Tùy chọn)
1. [Phương án A]
2. [Phương án B]
3. [Phương án C]

【Vui lòng giúp tôi】
1. Phân tích ưu nhược điểm từng phương án
2. Đưa ra phương án gợi ý và lý do
3. Nói rõ tình huống nào nên chọn phương án khác
```

**Ví dụ điền**:

```markdown
【Background dự án】
Ứng dụng danh sách todo cá nhân, hiện tại data lưu trong localStorage, muốn hỗ trợ đồng bộ đa thiết bị

【Nhu cầu chọn lựa】
Tôi cần chọn phương án lưu trữ data backend, chủ yếu xem xét:
- Miễn phí hoặc chi phí thấp (dự án cá nhân)
- Dễ học (tôi là newbie backend)
- Hỗ trợ xác thực user

【Phương án ứng cử】
1. Supabase
2. Firebase
3. Tự xây dựng Node.js + MongoDB

【Vui lòng giúp tôi】
1. Phân tích ưu nhược điểm từng phương án
2. Đưa ra phương án gợi ý và lý do
3. Nói rõ tình huống nào nên chọn phương án khác
```


## Checklist tự kiểm lỗi thường gặp

Trước khi gửi Prompt, kiểm tra có mắc 5 lỗi thường gặp này không:

| # | Lỗi | Cách kiểm tra | Cách sửa |
|---|-----|---------|---------|
| 1 | **Không có background** | Xóa background thì AI còn hiểu không? | Thêm loại dự án và tech stack |
| 2 | **Quá mơ hồ** | "Tối ưu code" tối ưu cái gì? | Nói cụ thể tối ưu khía cạnh nào |
| 3 | **Không có ràng buộc** | AI có thể "diễn thêm" không? | Thêm "Danh sách không làm" |
| 4 | **Không có format** | Format output AI có ngẫu nhiên không? | Chỉ định muốn code hay giải thích |
| 5 | **Một lần muốn quá nhiều** | Task có quá 3 điểm chính không? | Chia thành nhiều vòng đối thoại |


## Hướng dẫn nhanh xác minh Hallucination

Khi AI gợi ý package hoặc API bạn không quen, dùng flow này để xác minh:

```
AI gợi ý một package hoặc API
        │
        ▼
┌─────────────────────────┐
│ 1. Xác minh package      │
│    có tồn tại không      │
│    npm search <package>  │
│    hoặc truy cập npmjs.com │
└─────────────────────────┘
        │
        ├─ Không tồn tại ──▶ 🔴 Package hallucination, yêu cầu AI gợi ý lại
        │
        ▼ Tồn tại
┌─────────────────────────┐
│ 2. Kiểm tra độ tin cậy   │
│    - Lượt tải/tuần > 1000? │
│    - Update gần nhất < 1 năm? │
│    - GitHub stars > 100? │
└─────────────────────────┘
        │
        ├─ Không đạt ───────▶ 🟡 Dùng thận trọng, cân nhắc phương án thay thế
        │
        ▼ Đạt
┌─────────────────────────┐
│ 3. Xác minh API có đúng  │
│    không - Tra tài liệu   │
│    chính thức            │
└─────────────────────────┘
        │
        ├─ API không tồn tại ─▶ 🔴 API hallucination, tra docs tìm API đúng
        │
        ▼ API tồn tại
        ✅ Có thể sử dụng
```


## Template feedback lặp lại

Khi output của AI không thỏa mãn, dùng template này để feedback:

```markdown
【Vấn đề】
[Chỉ ra cụ thể chỗ nào không đúng]

【Lý do】
[Giải thích tại sao như vậy không được]

【Kỳ vọng】
[Nói rõ ràng bạn muốn gì]

【Ví dụ】(Tùy chọn)
[Cho một ví dụ bạn mong đợi]
```

**Ví dụ điền**:

```markdown
【Vấn đề】
Code bạn cho, sau khi xóa task không có chức năng hoàn tác

【Lý do】
User có thể xóa nhầm, cần có cơ hội hối hận

【Kỳ vọng】
Sau khi xóa hiển thị thông báo "Hoàn tác" trong 3 giây, click có thể khôi phục task

【Ví dụ】
Giống như nút "Hoàn tác" xuất hiện ở đáy Gmail sau khi xóa email
```


## Template vạn năng có thể copy

Đây là template tổng quát, áp dụng cho hầu hết tình huống:

```markdown
## Background
Tôi đang làm [Loại dự án].
Tech stack: [Tech stack]
Người dùng mục tiêu: [Mô tả user]

## Task hiện tại
[Mô tả cụ thể cần làm gì]

## Yêu cầu
1. [Yêu cầu 1]
2. [Yêu cầu 2]
3. [Yêu cầu 3]

## Không cần
- [Không cần 1]
- [Không cần 2]

## Format output
[Nói rõ format output mong đợi]

## Về tôi
Tôi là [Trình độ kỹ thuật], nếu có [Lưu ý], vui lòng nhắc tôi.
```


## Điểm cốt lõi phần này

✓ **Bắt buộc kiểm tra trước khi hỏi**: Background, Task, Ràng buộc, Format, Ví dụ, Tính cụ thể, Danh sách không làm, Chuẩn bị lặp lại, Thành quả Chương 2

✓ **4 template tình huống**: Tạo code, Sửa code, Debug vấn đề, Chọn công nghệ

✓ **5 lỗi thường gặp**: Không background, Quá mơ hồ, Không ràng buộc, Không format, Một lần muốn quá nhiều

✓ **Xác minh hallucination**: Xác minh tồn tại trước, sau đó kiểm tra độ tin cậy, cuối cùng tra tài liệu chính thức


Phần tiếp theo, chúng ta sẽ thông qua 4 bài tập tổng hợp giúp bạn nội hóa các kỹ năng này.
