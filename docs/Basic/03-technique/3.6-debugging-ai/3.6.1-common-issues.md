# 3.6.1 Những biểu hiện "không nghe lời" phổ biến của AI

## Sau khi học xong phần này, bạn sẽ nắm được

- Nhận diện 6 loại vấn đề phổ biến trong output của AI
- Hiểu 4 dạng Hallucination của AI và tác hại của chúng
- Tìm hiểu về mối đe dọa bảo mật "Slopsquatting" mới nổi năm 2024-2025
- Có một bảng tra cứu nhanh các kỹ thuật xác minh hữu ích

## Sáu loại vấn đề phổ biến

Những biểu hiện "không nghe lời" của AI tưởng chừng rất đa dạng, nhưng tóm lại chủ yếu có 6 loại:

| Loại | Triệu chứng | Trường hợp điển hình |
|-----|------|---------|
| **Trả lời sai câu hỏi** | AI hiểu nhầm ý định của bạn | Bạn muốn trang đăng nhập, nó cho trang đăng ký |
| **Phát huy quá mức** | Làm những thứ bạn không yêu cầu | Bạn muốn đồng hồ đơn giản, nó cho bản đầy đủ với chuyển đổi múi giờ |
| **Làm thiếu sót** | Thiếu phần quan trọng | Không xử lý lỗi, thiếu kiểm tra biên |
| **Tự mâu thuẫn** | Logic trước sau không nhất quán | Comment nói "trả về mảng", code thực tế trả về object |
| **Hallucination** | Bịa đặt nội dung không tồn tại | Đề xuất thư viện không tồn tại, gọi API không tồn tại |
| **Vòng lặp chết** | Lặp lại cùng một lỗi | Bạn chỉ ra vấn đề, nó sửa, lần sau lại sửa về như cũ |

### Loại một: Trả lời sai câu hỏi

**Tình huống**: Bạn yêu cầu AI làm "chức năng đăng nhập người dùng", nó lại cho bạn bộ ba hoàn chỉnh "đăng ký + đăng nhập + quên mật khẩu".

**Tại sao lại thế**: AI dựa trên lượng dữ liệu huấn luyện lớn để khớp mẫu, khi nhìn thấy từ "đăng nhập", nó liên tưởng đến hệ thống xác thực người dùng phổ biến, rồi "tốt bụng" cho bạn giải pháp toàn diện.

**Dấu hiệu nhận biết**:
- Nội dung output nhiều hơn bạn yêu cầu
- Bao gồm module chức năng bạn chưa đề cập
- AI giải thích rằng "tôi giả định bạn còn cần..."

### Loại hai: Phát huy quá mức

**Tình huống**: Bạn chỉ muốn một component đơn giản hiển thị thời gian hiện tại, AI lại thêm vào lựa chọn múi giờ, chuyển đổi 12/24 giờ, tùy chỉnh định dạng, v.v.

**Tại sao lại thế**: AI đã thấy quá nhiều giải pháp "hoàn chỉnh", có xu hướng đưa ra implementation "toàn diện", ngay cả khi bạn chỉ cần phiên bản đơn giản nhất.

**Dấu hiệu nhận biết**:
- Lượng code vượt xa dự kiến
- Sử dụng thư viện bên thứ ba bạn không biết
- Bao gồm nhiều tùy chọn cấu hình bạn không cần

### Loại ba: Làm thiếu sót

**Tình huống**: Code AI cho có thể chạy, nhưng không xử lý "input người dùng để trống", "request mạng thất bại" và các trường hợp ngoại lệ khác.

**Tại sao lại thế**: Để code trông gọn gàng, hoặc vì bạn không yêu cầu rõ ràng, AI bỏ qua code phòng thủ.

**Dấu hiệu nhận biết**:
- Code không có try-catch hoặc xử lý lỗi
- Không có validation input
- "Happy Path" (đường đi lý tưởng) chạy được, trường hợp biên sẽ crash

### Loại bốn: Tự mâu thuẫn

**Tình huống**: AI nói "hàm này trả về danh sách người dùng", nhưng code thực tế trả về một object người dùng đơn lẻ.

**Tại sao lại thế**: AI sinh comment và sinh code là các quá trình tương đối độc lập, đôi khi xuất hiện không đồng bộ.

**Dấu hiệu nhận biết**:
- Comment không phù hợp với hành vi code
- Tên hàm gợi ý chức năng khác với implementation thực tế
- Phương án nói trước và code sau không khớp

### Loại năm: Hallucination (trọng tâm)

Đây là loại vấn đề nguy hiểm nhất, sẽ được triển khai chi tiết bên dưới.

### Loại sáu: Vòng lặp chết

**Tình huống**: Bạn chỉ ra code có vấn đề, AI sửa xong, vòng tiếp theo lại sửa về cách viết cũ.

**Tại sao lại thế**:
- Context đối thoại quá dài, AI "quên" mất sửa chữa trước đó
- Chỉ thị sửa của bạn chưa đủ rõ ràng
- Bản thân task vượt quá khả năng của AI

**Dấu hiệu nhận biết**:
- Cùng một lỗi xuất hiện lặp lại
- Sửa đổi của AI càng lúc càng "vòng vo"
- Sửa một vấn đề lại tạo ra hai vấn đề mới

## Trọng tâm: Nhận diện và ứng phó với Hallucination của AI

AI Hallucination là hiện tượng AI sinh ra nội dung **trông đúng nhưng thực tế sai**. Trong tình huống lập trình, điều này có thể khiến code không chạy được, thậm chí tạo ra lỗ hổng bảo mật.

### Bốn loại Hallucination trong code

| Loại | Biểu hiện | Mức độ nguy hại | Ví dụ |
|------|------|---------|------|
| **Package Hallucination** | Đề xuất package npm/pip không tồn tại | 🔴 Cao (rủi ro bảo mật) | `npm install super-easy-utils` (package không tồn tại) |
| **API Hallucination** | Bịa hàm hoặc method không tồn tại | 🟡 Trung bình | Gọi `array.findLast()` không tồn tại trong JS phiên bản cũ |
| **Logic Hallucination** | Logic code không khớp với mô tả | 🟡 Trung bình | Nói "trả về mảng đã loại trùng", thực tế không loại trùng |
| **Version Hallucination** | Sử dụng cú pháp hoặc API đã deprecated | 🟡 Trung bình | Dùng lifecycle cũ của React class component |

### Package Hallucination: Loại Hallucination nguy hiểm nhất

Tại sao Package Hallucination có mức độ nguy hại cao nhất? Vì nó liên quan đến **bảo mật chuỗi cung ứng phần mềm**.

**Trường hợp thực tế**: Nghiên cứu bảo mật năm 2024-2025 đã phát hiện một phương thức tấn công có tên "Slopsquatting":

1. Nhà nghiên cứu kiểm tra 16 mô hình AI chủ lưu, phát hiện khoảng **20% package được đề xuất là không tồn tại**
2. Đáng lo ngại hơn, **43% tên package hallucination sẽ xuất hiện lặp lại trong nhiều lần hỏi**
3. Kẻ tấn công có thể đăng ký những tên package mà AI thường "hallucinate", cấy code độc hại
4. Khi developer cài đặt các package theo đề xuất của AI, họ sẽ trúng bẫy

**Chuỗi tấn công**:
```
AI hallucinate tên package → Kẻ tấn công đăng ký tên đó → Cấy code độc → Developer cài theo đề xuất AI → Hệ thống bị xâm nhập
```

**Mối đe dọa thực tế**: Tháng 10/2025, công ty bảo mật phát hiện hoạt động độc hại "PhantomRaven", lợi dụng kỹ thuật này lây nhiễm 126 package npm, đánh cắp npm tokens, GitHub credentials và các thông tin nhạy cảm khác của developer.

### API Hallucination: Trông đúng nhưng không chạy được

**Tình huống điển hình**:

```javascript
// Code do AI sinh ra
const lastItem = myArray.findLast(item => item.active);
```

Vấn đề: `findLast()` là method được giới thiệu trong ES2023, không khả dụng trong trình duyệt cũ hoặc Node.js. AI có thể nhầm lẫn các phiên bản API khác nhau.

**Các pattern API Hallucination phổ biến**:
- Nhầm lẫn API của các thư viện khác nhau (coi method của Lodash là method native)
- Sử dụng API đã deprecated
- Bịa đặt tùy chọn cấu hình không tồn tại

### Logic Hallucination: Code chạy được nhưng kết quả sai

**Tình huống điển hình**:

Bạn yêu cầu AI viết "hàm loại trùng", nó cho bạn:

```javascript
function removeDuplicates(arr) {
  // Loại bỏ phần tử trùng lặp trong mảng
  return arr.filter((item, index) => arr.indexOf(item) === index);
}
```

Code trông không có vấn đề, comment cũng đúng. Nhưng nếu mảng chứa object, method này sẽ không hiệu quả, vì object so sánh theo reference chứ không phải value.

### Version Hallucination: Cách viết "lỗi thời"

**Tình huống điển hình**:

Bạn yêu cầu AI viết component bằng React, nó cho bạn class component:

```javascript
class MyComponent extends React.Component {
  componentWillMount() {
    // ...
  }
}
```

Vấn đề: `componentWillMount` đã bị deprecated sau React 16.3, trong React 18 sẽ có cảnh báo.

## Bảng tra cứu nhanh kỹ thuật xác minh

Đối mặt với code do AI sinh ra, dùng checklist này để xác minh nhanh:

### Xác minh package có tồn tại

```bash
# npm package
npm search <tên-package>
# hoặc truy cập trực tiếp https://www.npmjs.com/package/<tên-package>

# Python package
pip index versions <tên-package>
# hoặc truy cập trực tiếp https://pypi.org/project/<tên-package>
```

### Xác minh API có đúng không

1. **Tra cứu tài liệu chính thức**: Đừng chỉ tin giải thích của AI
2. **Kiểm tra tương thích**: Sử dụng [caniuse.com](https://caniuse.com) (frontend) hoặc xem version notes của thư viện
3. **Test phạm vi nhỏ**: Chạy thử trong môi trường độc lập trước, xác nhận có dùng được

### Yêu cầu AI cung cấp nguồn

Khi AI đề xuất thư viện hoặc API mà bạn không quen, hãy hỏi thêm:

```
Vui lòng cung cấp link tài liệu chính thức của thư viện này.
```

```
API này được giới thiệu trong phiên bản nào? Vui lòng cung cấp nguồn tham khảo.
```

Nếu AI không thể đưa ra link hợp lệ, hoặc link mở ra là 404, rất có thể đó là hallucination.

### Xác minh tính đúng đắn của logic

1. **Test với trường hợp biên**: Mảng rỗng, chuỗi rỗng, null, giá trị siêu lớn
2. **Test với phản ví dụ**: Cố tình nhập dữ liệu "phải thất bại", xem có xử lý đúng không
3. **Để AI tự kiểm tra**:
   ```
   Vui lòng kiểm tra code trên, liệt kê các trường hợp biên và ngoại lệ có thể xảy ra, cũng như code hiện tại có xử lý đúng chúng hay không.
   ```

## Tóm tắt phần này

✓ **Sáu loại vấn đề**: Trả lời sai câu hỏi, phát huy quá mức, làm thiếu sót, tự mâu thuẫn, hallucination, vòng lặp chết

✓ **Bốn loại Hallucination**: Package Hallucination (nguy hiểm nhất), API Hallucination, Logic Hallucination, Version Hallucination

✓ **Mối đe dọa Slopsquatting**: Kẻ tấn công lợi dụng tên package bị AI hallucinate để tấn công chuỗi cung ứng, 20% package AI đề xuất có thể không tồn tại

✓ **Thói quen xác minh**: Với package và API do AI đề xuất, xác minh trước khi dùng; với logic code, test bằng trường hợp biên

Nhận diện vấn đề chỉ là bước đầu tiên. Phần tiếp theo, chúng ta sẽ học cách nhanh chóng định vị nguyên nhân gốc rễ của vấn đề.
