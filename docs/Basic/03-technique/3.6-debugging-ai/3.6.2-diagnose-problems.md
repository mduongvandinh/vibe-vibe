# 3.6.2 Chẩn đoán vấn đề: AI sai ở đâu

## Sau khi học xong phần này, bạn sẽ nắm được

- Sử dụng "phương pháp chẩn đoán nhanh 3 phút" để định vị vấn đề
- Phân biệt "tôi chưa nói rõ" và "AI không đủ năng lực"
- Chọn chiến lược ứng phó phù hợp dựa trên loại vấn đề
- Có một cây quyết định chẩn đoán

## Câu hỏi cốt lõi của chẩn đoán

Khi output của AI không đúng kỳ vọng, trước tiên bạn cần trả lời một câu hỏi:

> **Là tôi chưa nói rõ, hay AI không làm đúng?**

Câu trả lời cho câu hỏi này quyết định bước tiếp theo bạn nên làm:
- Nếu là bạn chưa nói rõ → Bổ sung context, mô tả lại
- Nếu là AI không làm đúng → Đổi cách hỏi, hoặc đổi chiến lược

## Phương pháp chẩn đoán nhanh 3 phút

Trước khi phân tích sâu, hãy dùng ba bước này để kiểm tra nhanh, có thể bắt được khoảng 60% vấn đề phổ biến:

### Bước một: Kiểm tra chạy code (30 giây)

```bash
# Nếu là dự án JavaScript/TypeScript
npx eslint <tên-file>   # Kiểm tra vấn đề cú pháp và format
npx tsc --noEmit      # Kiểm tra lỗi kiểu (nếu dùng TypeScript)
```

**Vấn đề có thể phát hiện**:
- Lỗi cú pháp (thiếu ngoặc, đánh vần sai từ khóa)
- Kiểu không khớp
- Biến chưa định nghĩa

### Bước hai: Kiểm tra dependencies và API (60 giây)

Đối chiếu với câu lệnh import trong code, kiểm tra:

- [ ] Package được import có tồn tại không? (dùng phương pháp xác minh trong 3.6.1)
- [ ] Method được gọi có thực sự tồn tại trong package đó không?
- [ ] Version có khớp không?

**Vấn đề có thể phát hiện**:
- Package Hallucination
- API Hallucination
- Vấn đề tương thích version

### Bước ba: Chạy test hiện có (90 giây)

Nếu dự án có test case:

```bash
npm test           # hoặc lệnh test của dự án bạn
```

**Vấn đề có thể phát hiện**:
- Thay đổi hành vi (chức năng chạy được trước bị làm hỏng)
- Lỗi logic
- Xử lý trường hợp biên không đúng

## Phân tích nguyên nhân gốc rễ theo bốn góc

Nếu chẩn đoán 3 phút không định vị được vấn đề, dùng bốn góc này để phân tích nguyên nhân căn bản:

```
                    Tôi nói rõ ràng
                        ↑
          ┌─────────────┼─────────────┐
          │             │             │
          │   AI sai    │  Bổ sung    │
Task đơn  │  → Đổi cách │  context    │  Task phức
giản      │     hỏi     │  → Mô tả lại│  tạp
          │             │             │
          ├─────────────┼─────────────┤
          │             │             │
          │  Tách task  │ Mô tả lại + │
          │  → Làm từng │  tách nhỏ   │
          │     bước    │  → Giảm độ  │
          │             │   phức tạp  │
          └─────────────┴─────────────┘
                        ↓
                   Tôi chưa nói rõ
```

### Góc một: Task đơn giản + Tôi nói rõ ràng → AI sai

**Đặc điểm**:
- Task rất rõ ràng, không nên có nhầm lẫn
- Thông tin bạn cung cấp đủ đầy đủ
- Nhưng output của AI rõ ràng không đúng

**Chiến lược ứng phó**:
- Đổi cách hỏi để mô tả lại
- Đưa ví dụ đúng cho AI tham khảo
- Thử công cụ AI khác

**Ví dụ**:
```
Prompt gốc: Viết hàm kiểm tra năm nhuận

Vấn đề: Logic AI cho không đúng

Đổi cách hỏi:
"Vui lòng viết hàm JavaScript kiểm tra năm nhuận.
Quy tắc năm nhuận:
1. Chia hết cho 4 và không chia hết cho 100, là năm nhuận
2. Chia hết cho 400, cũng là năm nhuận
Vui lòng implement nghiêm ngặt theo quy tắc này."
```

### Góc hai: Task đơn giản + Tôi chưa nói rõ → Bổ sung context

**Đặc điểm**:
- Bản thân task không phức tạp
- Nhưng bạn giả định AI biết một số nền tảng
- AI làm theo hiểu biết của nó, khác với ý bạn

**Chiến lược ứng phó**:
- Bổ sung background dự án
- Làm rõ tech stack và ràng buộc
- Nói rõ format output bạn mong đợi

**Ví dụ**:
```
Prompt gốc: Viết validation form

Vấn đề: AI dùng thư viện validation không có trong dự án bạn

Bổ sung context:
"Dự án của tôi dùng React + Zod để validation form.
Vui lòng dùng Zod viết validation schema cho form đăng ký người dùng, bao gồm:
- Validation format email
- Mật khẩu tối thiểu 8 ký tự
- Xác nhận mật khẩu phải khớp"
```

### Góc ba: Task phức tạp + Tôi nói rõ ràng → Tách task

**Đặc điểm**:
- Task liên quan đến nhiều bước hoặc module
- Bạn mô tả rất rõ ràng
- Nhưng chất lượng output của AI không ổn định, có chỗ đúng có chỗ sai

**Chiến lược ứng phó**:
- Chia task lớn thành task nhỏ
- Một lần chỉ cho AI làm một việc
- Hoàn thành từng bước rồi mới tích hợp

**Ví dụ**:
```
Prompt gốc (quá lớn):
"Implement hệ thống xác thực người dùng hoàn chỉnh, bao gồm đăng ký, đăng nhập, quên mật khẩu, quản lý JWT token"

Sau khi tách:
Vòng một: "Trước tiên implement chức năng đăng ký người dùng, chỉ cần email và mật khẩu"
Vòng hai: "Bây giờ thêm chức năng đăng nhập, trả về JWT token"
Vòng ba: "Thêm middleware xác thực token"
Vòng bốn: "Cuối cùng thêm chức năng quên mật khẩu"
```

### Góc bốn: Task phức tạp + Tôi chưa nói rõ → Mô tả lại + Tách nhỏ

**Đặc điểm**:
- Task phức tạp
- Có thể bạn cũng chưa nghĩ rõ hoàn toàn
- Output của AI khác xa với ý bạn

**Chiến lược ứng phó**:
- Lùi một bước, làm rõ nhu cầu của mình
- Dùng phương pháp PRD học ở phần 3.4 để sắp xếp tư duy
- Sau đó tách thành task nhỏ hoàn thành từng cái

**Ví dụ**:
```
Prompt gốc (mơ hồ và phức tạp):
"Giúp tôi làm app ghi chú giống Notion"

Sau khi làm rõ nhu cầu:
"Tôi muốn làm app ghi chú cá nhân, phiên bản MVP chỉ cần:
1. Tạo/sửa/xóa ghi chú
2. Trang danh sách ghi chú
3. Lưu trữ local

Trước tiên giúp tôi implement chức năng đầu tiên: tạo và hiển thị danh sách ghi chú.
Tech stack: React + localStorage"
```

## Prompt chẩn đoán: Để AI nhắc lại hiểu biết

Trước khi bắt đầu task, hoặc sau khi phát hiện vấn đề, có thể dùng Prompt này để AI nhắc lại hiểu biết của nó:

```markdown
Trước khi tiếp tục, vui lòng trả lời các câu hỏi sau:

1. **Mục tiêu task bạn hiểu là gì?**
   (Mô tả bằng một câu)

2. **Bạn dự định dùng phương án kỹ thuật nào?**
   (Liệt kê các điểm kỹ thuật chính)

3. **Có chỗ nào bạn không chắc, cần tôi làm rõ không?**
   (Nếu không có thì nói "Không")

Vui lòng trả lời các câu hỏi này trước, sau khi xác nhận hiểu biết nhất quán thì mới bắt đầu viết code.
```

**Tại sao chiêu này hiệu quả**:
- Phát hiện sớm hiểu lầm của AI
- Bạn và AI đạt được sự nhất quán về "làm cái gì" trước khi bắt tay vào
- Chi phí thấp hơn nhiều so với sửa code sai sau này

## Định vị nhanh các vấn đề phổ biến

| Triệu chứng | Nguyên nhân có thể | Bước tiếp theo |
|-----|-------------|-------|
| Code không chạy được, báo lỗi cú pháp | AI sinh code không đầy đủ | Yêu cầu AI đưa ra code đầy đủ |
| Runtime báo "undefined" | Thiếu định nghĩa biến hoặc vấn đề async | Kiểm tra data flow, bổ sung khởi tạo |
| Chức năng không khớp với mô tả | AI hiểu lầm nhu cầu | Dùng ngôn ngữ cụ thể hơn để mô tả lại |
| Import thư viện không biết | AI phát huy quá mức | Làm rõ ràng buộc, chỉ định chỉ dùng một số thư viện |
| Code chạy được nhưng kết quả sai | Logic Hallucination | Dùng boundary test để xác minh, để AI tự kiểm tra |
| Compile báo lỗi kiểu | API Hallucination hoặc vấn đề version | Tra tài liệu chính thức để xác nhận API |
| Sửa chỗ này hỏng chỗ kia | Task quá lớn, mất context | Tách task, làm từng bước |

## Tóm tắt phần này

✓ **Câu hỏi cốt lõi**: Trước tiên phân biệt "tôi chưa nói rõ" hay "AI không làm đúng"

✓ **Chẩn đoán 3 phút**: Kiểm tra chạy → Xác minh dependencies → Chạy test, bắt được 60% vấn đề

✓ **Phân tích bốn góc**: Dựa trên độ phức tạp task × độ rõ ràng mô tả, chọn chiến lược khác nhau

✓ **Kỹ thuật nhắc lại**: Để AI nói rõ hiểu biết trước khi bắt tay vào, phát hiện sớm sai lệch

Sau khi định vị được vấn đề, phần tiếp theo chúng ta sẽ học các chiến lược sửa lỗi cụ thể - làm sao để AI sửa code cho đúng.
