# 3.5.2 Mô hình cơ bản của đối thoại lặp

## Sau khi học tiểu mục này, bạn sẽ nắm vững

- Mô hình iteration ba giai đoạn: Xem hướng → Sửa vấn đề → Chau chuốt chi tiết
- Hành động chính và checkpoint của mỗi vòng đối thoại
- Một ví dụ đối thoại iteration hoàn chỉnh (Danh sách việc cần làm của Tiểu Lý)
- Template đối thoại iteration có thể sao chép trực tiếp

## Mô hình iteration ba giai đoạn

Đối thoại iteration không phải là sửa đổi qua lại vô định hướng. Iteration hiệu quả tuân theo một mô hình rõ ràng:

```
Vòng 1: Xem hướng
    ↓
  Hướng có đúng không? Tư duy tổng thể có đúng không?
    ↓
Vòng 2: Sửa vấn đề
    ↓
  Chức năng có đầy đủ không? Có khuyết điểm rõ ràng không?
    ↓
Vòng 3: Chau chuốt chi tiết
    ↓
  Cấu trúc code có tốt không? Có trường hợp biên nào không?
    ↓
  Hoàn thành
```

### Vòng 1: Xem hướng

**Mục tiêu**: Xác nhận AI hiểu ý định của bạn, hướng tổng thể đúng.

**Hành động chính**:
- Đưa ra yêu cầu cốt lõi, không cần quan tâm chi tiết
- Nói rõ với AI "đầu tiên cho tôi một implementation cơ bản"
- Trọng tâm xem: Sự hiểu biết của AI có đúng không? Hướng lớn có đúng không?

**Checkpoint**:
- [ ] AI làm có phải chức năng bạn muốn không?
- [ ] Phương án kỹ thuật có nhất quán với kỳ vọng của bạn không?
- [ ] Nếu hướng sai, bây giờ phải sửa ngay

**Vấn đề thường gặp**: Hướng sai. Ví dụ bạn muốn một popup, AI làm cho bạn một trang mới.

### Vòng 2: Sửa vấn đề

**Mục tiêu**: Sửa các vấn đề rõ ràng của vòng đầu, bổ sung chức năng bị thiếu.

**Hành động chính**:
- Chỉ ra vấn đề cụ thể, không nói "không đúng lắm"
- Liệt kê các điểm chức năng cần thêm
- Có thể đưa ra nhiều chỉnh sửa một lúc, nhưng không quá 3-5 cái

**Checkpoint**:
- [ ] Các chức năng cốt lõi đã thực hiện hết chưa?
- [ ] Logic tương tác có đúng không?
- [ ] Có bug rõ ràng nào không?

**Vấn đề thường gặp**: Thiếu chức năng hoặc lỗi logic. Ví dụ thiếu validation input, hoặc click button không phản ứng.

### Vòng 3: Chau chuốt chi tiết

**Mục tiêu**: Tối ưu cấu trúc code, xử lý trường hợp biên, nâng cao chất lượng.

**Hành động chính**:
- Quan tâm khả năng bảo trì của code
- Kiểm tra trường hợp biên (input rỗng, input quá dài, ký tự đặc biệt)
- Tối ưu đặt tên, comment, cấu trúc

**Checkpoint**:
- [ ] Cấu trúc code có rõ ràng không?
- [ ] Đã xử lý trường hợp biên chưa?
- [ ] Code có thể dùng trực tiếp cho production không?

**Vấn đề thường gặp**: Code có thể dùng nhưng không đủ tốt. Ví dụ tất cả logic viết trong một hàm, hoặc không có xử lý lỗi.

## Ví dụ hoàn chỉnh: Chức năng "thêm nhiệm vụ" của Tiểu Lý

Hãy xem Tiểu Lý sử dụng mô hình ba giai đoạn như thế nào để iteration ra chức năng thêm nhiệm vụ ưng ý.

### Vòng 1 đối thoại: Xem hướng

**Prompt của Tiểu Lý:**
```
Tôi đang phát triển ứng dụng danh sách việc cần làm, sử dụng React + TypeScript + Tailwind CSS.

Hãy giúp tôi thực hiện chức năng "thêm nhiệm vụ":
- Một input box + một button thêm
- Click button có thể thêm nhiệm vụ vào danh sách

Đầu tiên cho tôi một implementation cơ bản, sau này sẽ hoàn thiện.
```

**Kết quả đầu ra của AI:**
```tsx
import { useState } from 'react';

interface Task {
  id: number;
  title: string;
}

export default function AddTaskForm() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [inputValue, setInputValue] = useState('');

  const handleAdd = () => {
    const newTask: Task = {
      id: Date.now(),
      title: inputValue,
    };
    setTasks([...tasks, newTask]);
    setInputValue('');
  };

  return (
    <div>
      <input
        type="text"
        value={inputValue}
        onChange={(e) => setInputValue(e.target.value)}
        className="border p-2"
      />
      <button onClick={handleAdd} className="bg-blue-500 text-white p-2 ml-2">
        添加
      </button>
      <ul>
        {tasks.map((task) => (
          <li key={task.id}>{task.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

**Kiểm tra của Tiểu Lý**:
- ✅ Hướng đúng: input box + button + danh sách nhiệm vụ
- ✅ Tech stack đúng: React + TypeScript + Tailwind
- ⚠️ Nhưng có vấn đề: không có validation input, có thể thêm nhiệm vụ rỗng

**Đánh giá**: Hướng đúng, chuyển sang vòng hai.

### Vòng 2 đối thoại: Sửa vấn đề

**Prompt của Tiểu Lý:**
```
Chức năng cơ bản được rồi, hãy thêm các cải tiến sau:

1. Hỗ trợ nhấn phím Enter để thêm nhiệm vụ (không chỉ click button)
2. Thêm validation input rỗng:
   - Khi input rỗng, button hiển thị trạng thái vô hiệu hóa
   - Khi cố thêm nhiệm vụ rỗng, không thực hiện bất kỳ hành động nào
3. Input box thêm placeholder: "Nhập nhiệm vụ mới..."
```

**Kết quả đầu ra của AI:**
```tsx
import { useState } from 'react';

interface Task {
  id: number;
  title: string;
}

export default function AddTaskForm() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [inputValue, setInputValue] = useState('');

  const isInputEmpty = inputValue.trim() === '';

  const handleAdd = () => {
    if (isInputEmpty) return;

    const newTask: Task = {
      id: Date.now(),
      title: inputValue.trim(),
    };
    setTasks([...tasks, newTask]);
    setInputValue('');
  };

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === 'Enter') {
      handleAdd();
    }
  };

  return (
    <div>
      <input
        type="text"
        value={inputValue}
        onChange={(e) => setInputValue(e.target.value)}
        onKeyDown={handleKeyDown}
        placeholder="Nhập nhiệm vụ mới..."
        className="border p-2 rounded"
      />
      <button
        onClick={handleAdd}
        disabled={isInputEmpty}
        className={`p-2 ml-2 rounded ${
          isInputEmpty
            ? 'bg-gray-300 cursor-not-allowed'
            : 'bg-blue-500 text-white hover:bg-blue-600'
        }`}
      >
        添加
      </button>
      <ul className="mt-4">
        {tasks.map((task) => (
          <li key={task.id} className="py-1">{task.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

**Kiểm tra của Tiểu Lý**:
- ✅ Thêm bằng Enter: đã thực hiện
- ✅ Validation input rỗng: đã thực hiện
- ✅ placeholder: đã thêm
- ⚠️ Vấn đề cấu trúc code: logic validation và logic UI trộn lẫn

**Đánh giá**: Chức năng hoàn chỉnh, chuyển sang vòng ba tối ưu cấu trúc.

### Vòng 3 đối thoại: Chau chuốt chi tiết

**Prompt của Tiểu Lý:**
```
Chức năng hoàn chỉnh rồi, hãy tối ưu cấu trúc code:

1. Tách logic validation input thành hàm độc lập validateTaskInput
2. Quản lý tên class style bằng constant thống nhất (dễ chỉnh sửa sau này)
3. Thêm comment cần thiết để giải thích mục đích của component
```

**Kết quả đầu ra cuối cùng của AI:**
```tsx
import { useState } from 'react';

// Kiểu dữ liệu nhiệm vụ
interface Task {
  id: number;
  title: string;
}

// Constant style
const STYLES = {
  input: 'border p-2 rounded focus:outline-none focus:ring-2 focus:ring-blue-300',
  buttonBase: 'p-2 ml-2 rounded transition-colors',
  buttonEnabled: 'bg-blue-500 text-white hover:bg-blue-600',
  buttonDisabled: 'bg-gray-300 cursor-not-allowed text-gray-500',
  taskItem: 'py-1 border-b border-gray-100',
};

// Validation input nhiệm vụ
function validateTaskInput(input: string): boolean {
  return input.trim().length > 0;
}

/**
 * Component form thêm nhiệm vụ
 * Chức năng: input box + button thêm, hỗ trợ thêm bằng Enter, có validation input rỗng
 */
export default function AddTaskForm() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [inputValue, setInputValue] = useState('');

  const isValid = validateTaskInput(inputValue);

  const handleAdd = () => {
    if (!isValid) return;

    const newTask: Task = {
      id: Date.now(),
      title: inputValue.trim(),
    };
    setTasks([...tasks, newTask]);
    setInputValue('');
  };

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === 'Enter') {
      handleAdd();
    }
  };

  return (
    <div className="p-4">
      <div className="flex">
        <input
          type="text"
          value={inputValue}
          onChange={(e) => setInputValue(e.target.value)}
          onKeyDown={handleKeyDown}
          placeholder="Nhập nhiệm vụ mới..."
          className={STYLES.input}
        />
        <button
          onClick={handleAdd}
          disabled={!isValid}
          className={`${STYLES.buttonBase} ${
            isValid ? STYLES.buttonEnabled : STYLES.buttonDisabled
          }`}
        >
          Thêm
        </button>
      </div>
      <ul className="mt-4">
        {tasks.map((task) => (
          <li key={task.id} className={STYLES.taskItem}>
            {task.title}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

**Kiểm tra của Tiểu Lý**:
- ✅ Logic validation độc lập: hàm `validateTaskInput`
- ✅ Style quản lý thống nhất: constant `STYLES`
- ✅ Comment rõ ràng: giải thích mục đích component
- ✅ Code có thể bảo trì: cấu trúc rõ ràng, dễ mở rộng

**Kết quả**: Ba vòng đối thoại, từ "có thể dùng" đến "dùng tốt".

## Checklist hành động của mỗi vòng đối thoại

| Giai đoạn | Trọng tâm của bạn | Từ khóa trong prompt | Kiểm tra cái gì |
|-----|---------|------------|---------|
| Vòng 1 | Xem hướng | "implementation cơ bản", "đầu tiên cho tôi một..." | Hướng có đúng không? Hiểu có đúng không? |
| Vòng 2 | Sửa vấn đề | "hãy thêm...", "sửa..." | Chức năng đầy đủ chưa? Logic đúng chưa? |
| Vòng 3 | Chau chuốt chi tiết | "tối ưu cấu trúc", "tách thành hàm" | Code dễ bảo trì không? Trường hợp biên? |

## Template có thể sao chép: Script đối thoại iteration

### Template vòng đầu: Thiết lập hướng

```markdown
Tôi đang phát triển [tên dự án], sử dụng [tech stack].

Hãy giúp tôi thực hiện [tên chức năng]:
- [yêu cầu cốt lõi 1]
- [yêu cầu cốt lõi 2]

Đầu tiên cho tôi một implementation cơ bản, chúng ta sẽ từng bước hoàn thiện sau.
```

### Template vòng hai: Sửa vấn đề

```markdown
Chức năng cơ bản được rồi, hãy thêm các cải tiến sau:

1. [chức năng cần thêm/vấn đề cần sửa]
2. [chức năng cần thêm/vấn đề cần sửa]
3. [chức năng cần thêm/vấn đề cần sửa]
```

### Template vòng ba: Tối ưu chi tiết

```markdown
Chức năng hoàn chỉnh rồi, hãy tối ưu code:

1. [yêu cầu tối ưu cấu trúc]
2. [xử lý trường hợp biên]
3. [yêu cầu chất lượng khác]
```

## Khi nào có thể bỏ qua một giai đoạn?

| Tình huống | Có thể bỏ qua | Lý do |
|-----|---------|------|
| Nhiệm vụ rất đơn giản | Vòng 3 | Lượng code ít, không cần tối ưu cấu trúc |
| Kết quả đầu ra vòng đầu đã rất tốt | Vòng 2 | Trực tiếp chuyển sang chau chuốt chi tiết |
| Chỉ là prototype nhanh để verify | Vòng 3 | Sau này sẽ viết lại, không cần hoàn hảo |

## Giá trị kinh nghiệm về số lần iteration

| Độ phức tạp nhiệm vụ | Số lần iteration điển hình | Ví dụ |
|-----------|-------------|------|
| Đơn giản (chức năng đơn lẻ) | 1-2 vòng | Một button, một input box |
| Trung bình (nhiều chức năng) | 2-3 vòng | Một form, một list component |
| Phức tạp (module hoàn chỉnh) | 3-5 vòng | Một trang hoàn chỉnh, một tương tác phức tạp |

Nếu vượt quá 5 vòng vẫn chưa đạt hiệu quả hài lòng, hãy xem xét liệu bản thân yêu cầu có đủ rõ ràng không, hoặc nên bắt đầu cuộc đối thoại mới.

## Điểm chính của tiểu mục

✓ **Mô hình ba giai đoạn**: Xem hướng → Sửa vấn đề → Chau chuốt chi tiết

✓ **Mỗi vòng có trọng tâm**: Vòng đầu không quan tâm chi tiết, vòng hai không quan tâm cấu trúc, vòng ba tập trung vào chất lượng

✓ **Checkpoint rõ ràng**: Mỗi vòng kết thúc đều có tiêu chuẩn kiểm tra rõ ràng

✓ **Điều chỉnh linh hoạt**: Nhiệm vụ đơn giản có thể bỏ qua giai đoạn, nhiệm vụ phức tạp có thể cần nhiều vòng hơn

Tiểu mục tiếp theo, chúng ta sẽ học cách đưa feedback hiệu quả cho AI—đây là chìa khóa thành công của iteration.
