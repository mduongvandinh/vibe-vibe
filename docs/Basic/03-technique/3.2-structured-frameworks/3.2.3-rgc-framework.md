# 3.2.3 Framework Role → Goal → Constraints (Phiên bản rút gọn)

## Sau khi học xong phần này, bạn sẽ nắm được

- Ba yếu tố của framework R.G.C. và ý nghĩa của chúng
- Tình huống nào phù hợp với framework rút gọn này
- Tiêu chí lựa chọn giữa S.C.A.F.F. và R.G.C.
- Biết khi nào nên nâng cấp từ R.G.C. lên S.C.A.F.F.


## Cấu trúc framework

R.G.C. là viết tắt của 3 từ tiếng Anh:

| Chữ cái | Tiếng Anh | Tiếng Việt | Câu hỏi cốt lõi |
|-----|------|------|---------|
| **R** | Role | Vai trò | Cho AI đóng vai gì? |
| **G** | Goal | Mục tiêu | Cần hoàn thành nhiệm vụ gì? |
| **C** | Constraints | Ràng buộc | Có những điều kiện giới hạn nào? |

Logic thiết kế của framework này là: **Định danh vai trò → Nói mục tiêu → Vạch ranh giới**.

So với S.C.A.F.F., R.G.C. nhẹ hơn, phù hợp cho câu hỏi nhanh và nhiệm vụ tương đối đơn giản.


## Giải thích chi tiết ba yếu tố

### R - Role (Vai trò)

Cho AI vào "chế độ chuyên gia" cụ thể.

**Tại sao vai trò quan trọng**: Cùng một câu hỏi, góc nhìn của lập trình viên và góc nhìn của product manager sẽ trả lời rất khác nhau. Chỉ định vai trò giúp đầu ra của AI phù hợp hơn với kỳ vọng của bạn.

**Ví dụ vai trò thường dùng**:
- "Bạn là một developer React dày dạn kinh nghiệm"
- "Bạn là một kỹ sư Python chú trọng tính dễ đọc của code"
- "Bạn là một nhà phân tích giỏi về trực quan hóa dữ liệu"
- "Bạn là một mentor lập trình thân thiện với người mới bắt đầu"

**Kỹ thuật điền**: Mô tả vai trò có thể bao gồm chuyên môn, phong cách ưa thích, mức độ kinh nghiệm.

### G - Goal (Mục tiêu)

Nói rõ cần hoàn thành nhiệm vụ gì.

**Nội dung điền**:
- Mô tả nhiệm vụ cụ thể
- Kết quả đầu ra mong đợi
- Tiêu chuẩn thành công

**Kỹ thuật điền**: Dùng cấu trúc "động từ + danh từ", như "triển khai một function", "phân tích đoạn code này", "giải thích khái niệm này".

### C - Constraints (Ràng buộc)

Vạch ranh giới của nhiệm vụ.

**Nội dung điền**:
- Giới hạn kỹ thuật (ngôn ngữ, framework, thư viện)
- Yêu cầu định dạng (độ dài, phong cách)
- Giới hạn nội dung (không muốn gì)

**Kỹ thuật điền**: Ràng buộc càng rõ ràng, AI càng ít "thêm thắt" tự ý.


## Ví dụ hoàn chỉnh: Refactor code

### Tình huống nhiệm vụ

Bạn có một đoạn code dùng được nhưng rất rối, muốn AI giúp refactor.

### ❌ Prompt kém

```
Giúp tôi tối ưu đoạn code này:
[dán code]
```

**Vấn đề**: "Tối ưu" có nhiều cách hiểu — tối ưu hiệu năng? Tối ưu tính dễ đọc? Tối ưu kiến trúc? AI không biết bạn muốn loại nào.

### ✅ Viết lại bằng framework R.G.C.

```markdown
【Role - Vai trò】
Bạn là một kỹ sư Python chú trọng tính dễ đọc và dễ bảo trì của code.

【Goal - Mục tiêu】
Refactor đoạn code dưới đây để nâng cao tính dễ đọc:
- Làm cho tên biến rõ ràng hơn
- Trích xuất logic lặp lại thành function
- Thêm comment cần thiết

```python
def f(l):
    r=[]
    for i in l:
        if i>0:
            r.append(i*2)
    return r
```

【Constraints - Ràng buộc】
- Giữ chức năng hoàn toàn không thay đổi
- Không dùng list comprehension (tôi chưa học phần đó)
- Không cần thêm type annotation
- Comment bằng tiếng Việt
```

### Đầu ra có thể của AI

```python
def double_positive_numbers(numbers):
    """
    Lọc các số dương từ danh sách và nhân đôi mỗi số dương

    Tham số: numbers - danh sách số đầu vào
    Trả về: danh sách mới chứa các số dương đã nhân đôi
    """
    result = []

    for number in numbers:
        # Chỉ xử lý số dương
        if number > 0:
            doubled = number * 2
            result.append(doubled)

    return result
```


## Thêm ví dụ về R.G.C.

### Ví dụ một: Giải thích khái niệm

```markdown
【Role】Bạn là một mentor lập trình thân thiện với người mới học

【Goal】Giải thích bằng ngôn ngữ dễ hiểu "hàm callback" là gì

【Constraints】
- Không dùng thuật ngữ kỹ thuật khác
- Lấy một ví dụ tương tự trong cuộc sống
- Giới hạn trong 200 chữ
```

### Ví dụ hai: Tạo dữ liệu test

```markdown
【Role】Bạn là một data engineer quen thuộc với nghiệp vụ thương mại điện tử

【Goal】Tạo 10 dòng dữ liệu đơn hàng mô phỏng

【Constraints】
- Định dạng: JSON array
- Mỗi dòng bao gồm: ID đơn hàng, tên người dùng, tên sản phẩm, số tiền, thời gian đặt hàng
- Phạm vi số tiền: 50-500k VND
- Phạm vi thời gian: tháng 1 năm 2024
```

### Ví dụ ba: Review code

```markdown
【Role】Bạn là một code reviewer nghiêm khắc nhưng thân thiện

【Goal】Review đoạn code này, chỉ ra các vấn đề tiềm ẩn:
[dán code]

【Constraints】
- Chỉ quan tâm vấn đề bảo mật và hiệu năng
- Không đánh giá phong cách code
- Mỗi vấn đề đưa ra gợi ý sửa
- Số lượng vấn đề không quá 5 cái
```


## S.C.A.F.F. vs R.G.C.: Hai cách viết cho cùng một nhiệm vụ

Giả sử nhiệm vụ là: Thêm chức năng "hoàn thành nhiệm vụ" cho danh sách việc cần làm.

### Cách viết R.G.C. (phiên bản nhanh)

```markdown
【Role】Bạn là một developer React

【Goal】Triển khai chức năng đánh dấu nhiệm vụ là đã hoàn thành khi click vào

【Constraints】
- Dùng TypeScript
- Nhiệm vụ hoàn thành hiển thị gạch ngang
- Dùng Tailwind CSS
```

### Cách viết S.C.A.F.F. (phiên bản đầy đủ)

```markdown
【Situation】
Dự án danh sách việc cần làm, React + TS + Tailwind, đã có component AddTask và TaskList

【Challenge】
Triển khai chức năng "hoàn thành nhiệm vụ":
- Click vào text nhiệm vụ, chuyển đổi trạng thái hoàn thành/chưa hoàn thành
- Nhiệm vụ đã hoàn thành hiển thị gạch ngang và màu xám nhạt
- Có thể click lặp lại để chuyển đổi trạng thái

【Audience】
Tôi là người mới học React, vui lòng giải thích logic quản lý state

【Format】
Cập nhật code component TaskList, thêm comment cần thiết

【Foundations】
- Dùng useState quản lý state
- Không dùng bất kỳ thư viện animation nào
- Thay đổi style phải có hiệu ứng transition 0.2s
```

### Tiêu chí lựa chọn

| Tình huống | Framework khuyến nghị |
|-----|---------|
| Quen thuộc với bối cảnh dự án, nhiệm vụ đơn giản rõ ràng | R.G.C. |
| Dự án mới hoặc nhiệm vụ phức tạp, cần mô tả chi tiết bối cảnh | S.C.A.F.F. |
| Hỏi nhanh, chỉ muốn xác minh một ý tưởng | R.G.C. |
| Phát triển chính thức, code sẽ vào dự án | S.C.A.F.F. |
| Đầu ra của AI không lý tưởng, cần tăng ràng buộc | Nâng cấp từ R.G.C. lên S.C.A.F.F. |


## Khi nào nâng cấp từ R.G.C. lên S.C.A.F.F.

Khi bạn dùng R.G.C. đặt câu hỏi rồi phát hiện đầu ra của AI không phù hợp kỳ vọng, đây thường là tín hiệu **thiếu thông tin**.

**Tín hiệu thường gặp**:

| Biểu hiện vấn đề | Có thể thiếu thông tin | Hướng nâng cấp |
|---------|--------------|---------|
| Stack công nghệ không đúng | Bối cảnh dự án | Thêm Situation |
| Chức năng quá đơn giản/quá phức tạp | Nhu cầu cụ thể | Bổ sung Challenge |
| Phong cách code không khớp | Thông tin người bảo trì | Thêm Audience |
| Định dạng đầu ra lộn xộn | Yêu cầu định dạng | Thêm Format |

**Ví dụ nâng cấp**:

```markdown
# R.G.C. ban đầu
【Role】Developer React
【Goal】Triển khai form validation
【Constraints】Không dùng thư viện bên thứ ba

# AI đưa ra phương án validation quá phức tạp

# Nâng cấp thành S.C.A.F.F.
【Situation】Dự án blog cá nhân, chỉ có một form đăng nhập đơn giản
【Challenge】Validate định dạng email và password không trống, khi lỗi hiển thị thông báo
【Audience】Tôi là người mới học, vui lòng dùng cách triển khai đơn giản nhất
【Format】Code component hoàn chỉnh + comment tiếng Việt
【Foundations】Chỉ dùng useState, không dùng useReducer hoặc pattern phức tạp khác
```


## Template R.G.C. có thể sao chép

```markdown
【Role - Vai trò】
Bạn là một [mô tả chuyên môn/phong cách] [danh tính nghề nghiệp]

【Goal - Mục tiêu】
[Động từ] [Mô tả nhiệm vụ cụ thể]

【Constraints - Ràng buộc】
- [Điều kiện giới hạn 1]
- [Điều kiện giới hạn 2]
- [Điều kiện giới hạn 3]
```


## Điểm chính của phần này

✓ **Ba yếu tố R.G.C.**: Role (Vai trò) → Goal (Mục tiêu) → Constraints (Ràng buộc)

✓ **Tình huống áp dụng**: Hỏi nhanh, nhiệm vụ đơn giản, đã có nhận thức rõ ràng về dự án

✓ **Quan hệ với S.C.A.F.F.**: R.G.C. là phiên bản rút gọn, khi đầu ra không lý tưởng có thể nâng cấp

✓ **Tín hiệu nâng cấp**: Khi đầu ra của AI không phù hợp kỳ vọng, kiểm tra xem có thiếu bối cảnh, nhu cầu, đối tượng hoặc thông tin định dạng không


Phần tiếp theo, chúng ta giới thiệu một "template vạn năng" — lựa chọn an toàn khi bạn không chắc dùng framework nào.
