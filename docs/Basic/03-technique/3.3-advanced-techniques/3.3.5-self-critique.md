# 3.3.5 Self-Critique: Để AI tự kiểm tra

## Qua phần này bạn sẽ nắm được

- Định nghĩa và nguyên lý của Self-Critique (tự phê bình)
- Tại sao AI tự kiểm tra có thể nâng cao chất lượng output
- Danh sách các chiều tự kiểm tra cốt lõi
- Cách hướng dẫn AI tự kiểm tra trong prompt
- Hạn chế của Self-Critique

## Self-Critique là gì

Ý tưởng cốt lõi của Self-Critique (tự phê bình) là: **Để AI sau khi generate nội dung, tự kiểm tra lại một lần, phát hiện và sửa vấn đề**.

Giống như sau khi viết xong bài văn tự đọc lại một lượt, thường có thể phát hiện lỗi bị bỏ sót ban đầu.

```
Generate → Tự kiểm tra → Sửa chữa
```

## Hiểu biết cốt lõi: Tại sao tự kiểm tra hiệu quả

> "Phương pháp SELF-REFINE có thể nâng cao chất lượng output AI khoảng 20% mà không cần training thêm."
> —— Bài báo nghiên cứu CMU 2023

Con số này cho chúng ta biết: cùng một AI, thêm một bước tự kiểm tra, hiệu quả có thể cải thiện rõ ràng.

Lý do nằm ở chỗ:
1. **Lần generate đầu thường có sót**: AI generate nhanh có thể bỏ qua trường hợp biên
2. **Tự kiểm tra đổi góc nhìn**: Chế độ review sẽ quan tâm các khía cạnh khác nhau
3. **Cải thiện lặp lại chính xác hơn**: Sửa dựa trên vấn đề cụ thể, chính xác hơn generate lại

## Các chiều tự kiểm tra cốt lõi

Nội dung khác loại, chiều cần kiểm tra khác nhau:

### Chiều tự kiểm tra code

| Chiều | Nội dung kiểm tra | Vấn đề thường gặp |
|-----|---------|---------|
| **Tính đúng đắn chức năng** | Có implement đúng yêu cầu không | Thiếu sót một phần chức năng |
| **Trường hợp biên** | Giá trị rỗng, giá trị cực, input bất thường | Không xử lý null/undefined |
| **Bảo mật** | XSS, injection, dữ liệu nhạy cảm | Input người dùng chưa lọc |
| **Hiệu suất** | Độ phức tạp thời gian/không gian | Vòng lặp lồng nhau không cần thiết |
| **Khả năng đọc** | Đặt tên, comment, cấu trúc | Tên biến không rõ ràng |
| **Khả năng maintain** | Code lặp, độ coupling | Hardcode magic number |

### Chiều tự kiểm tra content/tài liệu

| Chiều | Nội dung kiểm tra |
|-----|---------|
| **Tính chính xác** | Thông tin có đúng không |
| **Tính đầy đủ** | Có thiếu sót điểm quan trọng không |
| **Tính rõ ràng** | Có dễ hiểu không |
| **Tính nhất quán** | Thuật ngữ, phong cách có thống nhất không |

## Prompt kém vs Prompt tốt

### Tình huống: Generate function validate form

### ❌ Prompt kém

```
Viết một function validate form đăng ký người dùng, kiểm tra email và password.
```

AI có thể generate một phiên bản cơ bản, nhưng thiếu sót trường hợp biên.

### ✅ Prompt tốt (có Self-Critique)

```
Viết một function validate form đăng ký người dùng, kiểm tra email và password.

Sau khi generate, vui lòng tự kiểm tra:
1. Có bao phủ tất cả trường hợp biên (giá trị rỗng, chuỗi rỗng, chỉ có khoảng trắng) không?
2. Có lỗ hổng bảo mật (XSS, rủi ro injection) không?
3. Thông báo lỗi có rõ ràng, người dùng có biết vấn đề cụ thể không?
4. Có code lặp lại không cần thiết không?

Nếu có vấn đề, vui lòng sửa rồi output phiên bản cuối cùng.
```

### Output AI với prompt tốt

AI sẽ generate code trước, sau đó kiểm tra từng điều, cuối cùng đưa ra phiên bản cải thiện:

```javascript
// Vấn đề phát hiện khi tự kiểm tra:
// 1. Phiên bản gốc không xử lý trường hợp trim rồi rỗng
// 2. Thông báo lỗi không đủ cụ thể
// 3. Regex email có thể nghiêm ngặt hơn

// Phiên bản sau khi cải thiện:
function validateRegistration(email, password) {
  const errors = [];

  // Xử lý khoảng trắng
  const trimmedEmail = email?.trim() || '';
  const trimmedPassword = password || '';

  // Validate email
  if (!trimmedEmail) {
    errors.push('Email không được để trống');
  } else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(trimmedEmail)) {
    errors.push('Format email không đúng, vui lòng kiểm tra có chứa @ và tên miền');
  }

  // Validate password
  if (!trimmedPassword) {
    errors.push('Password không được để trống');
  } else {
    if (trimmedPassword.length < 8) {
      errors.push('Độ dài password ít nhất 8 ký tự');
    }
    if (!/[A-Z]/.test(trimmedPassword)) {
      errors.push('Password cần chứa ít nhất một chữ cái in hoa');
    }
    if (!/[0-9]/.test(trimmedPassword)) {
      errors.push('Password cần chứa ít nhất một số');
    }
  }

  return {
    isValid: errors.length === 0,
    errors
  };
}
```

## Thư viện câu lệnh tự kiểm tra thường dùng

### Tự kiểm tra tổng quát

```
Sau khi generate, vui lòng kiểm tra xem có thiếu sót hoặc lỗi không, nếu có hãy sửa.
```

### Tự kiểm tra code

```
Vui lòng tự kiểm tra:
1. Đã xử lý tất cả trường hợp biên chưa?
2. Có vấn đề bảo mật tiềm ẩn không?
3. Hiệu suất có thể tối ưu không?
Nếu có vấn đề, vui lòng sửa rồi output phiên bản cuối cùng.
```

### Tự kiểm tra nghiêm ngặt

```
Vui lòng đóng vai một reviewer code nghiêm ngặt, review code bạn vừa generate:
- Tìm ra ít nhất 3 chỗ có thể cải thiện
- Đưa ra phiên bản sau khi cải thiện
```

### Tự kiểm tra chiều cụ thể

```
Vui lòng từ góc độ [bảo mật/hiệu suất/khả năng đọc] review đoạn code này, chỉ ra vấn đề và sửa.
```

## Ví dụ thực chiến: Dự án todo list

Tiểu Lý để AI generate một function sắp xếp, và yêu cầu tự kiểm tra.

### Prompt Self-Critique

```
Viết cho ứng dụng todo list của tôi một function sắp xếp, hỗ trợ sắp xếp theo các cách sau:
- Theo thời gian tạo (mới đến cũ)
- Theo deadline (gần đến xa, không có deadline xếp cuối)
- Theo độ ưu tiên (cao > trung > thấp)

Cấu trúc dữ liệu task:
{
  id: string,
  title: string,
  createdAt: Date,
  dueDate: Date | null,
  priority: 'high' | 'medium' | 'low'
}

Sau khi generate, vui lòng tự kiểm tra:
1. Logic sắp xếp có xử lý đúng null/undefined không?
2. Thứ tự sắp xếp độ ưu tiên có đúng như mong đợi không?
3. Interface function có rõ ràng dễ dùng không?
Nếu có vấn đề, vui lòng sửa.
```

### Output AI (bao gồm quá trình tự kiểm tra)

```javascript
// Phiên bản ban đầu implement...

// Phát hiện khi tự kiểm tra:
// 1. dueDate là null thì so sánh trực tiếp sẽ có vấn đề ✓ Đã xử lý
// 2. Độ ưu tiên dùng so sánh chuỗi không đáng tin cậy, cần map thành số → Cần sửa
// 3. Function có thể linh hoạt hơn, hỗ trợ tăng dần/giảm dần → Đã tối ưu

// Phiên bản cuối cùng:
const priorityMap = { high: 3, medium: 2, low: 1 };

function sortTasks(tasks, sortBy, order = 'desc') {
  const direction = order === 'desc' ? -1 : 1;

  return [...tasks].sort((a, b) => {
    switch (sortBy) {
      case 'createdAt':
        return direction * (new Date(b.createdAt) - new Date(a.createdAt));

      case 'dueDate':
        // null xếp cuối
        if (!a.dueDate && !b.dueDate) return 0;
        if (!a.dueDate) return 1;
        if (!b.dueDate) return -1;
        return direction * (new Date(a.dueDate) - new Date(b.dueDate));

      case 'priority':
        return direction * (priorityMap[b.priority] - priorityMap[a.priority]);

      default:
        return 0;
    }
  });
}
```

## Self-Critique lặp lại

Với output quan trọng, có thể tự kiểm tra nhiều vòng:

```
Vòng một: Kiểm tra tính đúng đắn chức năng
Vòng hai: Kiểm tra bảo mật
Vòng ba: Kiểm tra hiệu suất và chất lượng code
```

Mỗi vòng tập trung một chiều, từng bước hoàn thiện.

## Hạn chế của Self-Critique

| Hạn chế | Biểu hiện | Cách ứng phó |
|-----|------|---------|
| Bias tự nhận thức | AI có thể cho output của mình không có vấn đề | Dùng câu lệnh "đóng vai reviewer nghiêm ngặt" |
| Kiểm tra không kỹ | Có thể bỏ sót một số chiều | Liệt kê rõ các chiều cần kiểm tra |
| Càng kiểm tra càng rối | Sửa chữa có thể đưa vào vấn đề mới | Giới hạn phạm vi sửa, một lần chỉ sửa một chỗ |
| Tăng token | Output dài hơn | Dùng cho output quan trọng, task đơn giản thì bỏ qua |

## Phối hợp với review thủ công

Self-Critique không thể thay thế review thủ công, mà là **giảm gánh nặng review thủ công**.

Flow đề xuất:
1. AI generate + tự kiểm tra → Được phiên bản đầu
2. Bạn xem nhanh, phát hiện vấn đề rõ ràng → Để AI sửa
3. Cuối cùng thủ công xác nhận logic quan trọng

## Template có thể sao chép

### Template generate code + tự kiểm tra

```markdown
[Mô tả task]

Sau khi generate, vui lòng tự kiểm tra:
1. Có bao phủ tất cả trường hợp biên không?
2. Có lỗ hổng bảo mật không?
3. Code có rõ ràng dễ maintain không?
Nếu có vấn đề, vui lòng sửa rồi output phiên bản cuối cùng.
```

### Template review nghiêm ngặt

```markdown
Vui lòng đóng vai một [vai trò: reviewer code/biên tập/QA] nghiêm ngặt, review output bạn vừa rồi:
- Tìm ra ít nhất [số lượng] chỗ có thể cải thiện
- Giải thích ảnh hưởng của từng vấn đề
- Đưa ra phiên bản sau khi cải thiện
```

### Template review chiều cụ thể

```markdown
Vui lòng từ các chiều sau review output của bạn:
- [ ] [chiều 1]
- [ ] [chiều 2]
- [ ] [chiều 3]

Với từng chiều, nói rõ có pass không, nếu không pass vui lòng sửa.
```

## Những điểm chính của phần này

✓ **Bản chất của Self-Critique**: Để AI sau khi generate tự kiểm tra, phát hiện và sửa vấn đề

✓ **Tại sao hiệu quả**: Tự kiểm tra đổi góc nhìn, có thể phát hiện vấn đề bị bỏ sót lần đầu

✓ **Chiều cốt lõi**: Tính đúng đắn chức năng, trường hợp biên, bảo mật, hiệu suất, khả năng đọc

✓ **Câu lệnh thường dùng**: "Vui lòng tự kiểm tra...nếu có vấn đề vui lòng sửa", "Đóng vai reviewer nghiêm ngặt"

✓ **Hạn chế**: Có thể tự nhận thức, kiểm tra không kỹ, cần phối hợp review thủ công

Phần tiếp theo, chúng ta sẽ học cách chọn kỹ thuật phù hợp—Hướng dẫn lựa chọn kỹ thuật.
