# 3.3.2 Few-shot Prompting: Dùng ví dụ dạy AI

## Qua phần này bạn sẽ nắm được

- Định nghĩa và nguyên lý hoạt động của Few-shot
- Tại sao ví dụ hiệu quả hơn giải thích dài
- Cách chọn ví dụ chất lượng cao
- Best practices về số lượng ví dụ
- Tình huống áp dụng và hạn chế của Few-shot

## Few-shot Prompting là gì

Few-shot (ít mẫu) nghĩa là: **Đưa cho AI vài ví dụ, để nó học pattern rồi xử lý task mới**.

```
Task: Chuyển đổi yêu cầu người dùng thành task kỹ thuật

Ví dụ 1:
Yêu cầu: "Người dùng có thể thêm công việc cần làm"
Task:
- Tạo component input box
- Implement sự kiện click nút thêm
- Cập nhật state danh sách task

Ví dụ 2:
Yêu cầu: "Người dùng có thể xóa công việc cần làm"
Task:
- Thêm nút xóa cho mỗi task
- Implement logic xác nhận xóa
- Xóa task tương ứng khỏi danh sách

Bây giờ hãy xử lý:
Yêu cầu: "Người dùng có thể đánh dấu task là đã hoàn thành"
```

AI sau khi xem hai ví dụ, đã "học được" quy tắc chuyển đổi, có thể xử lý yêu cầu mới theo cùng format.

## Hiểu biết cốt lõi: Tại sao ví dụ hiệu quả hơn giải thích

> "Trình diễn một lần, thắng hơn giải thích trăm lần."

Đây không phải cường điệu. Khi con người học kỹ năng mới, xem minh họa hiệu quả hơn nghe giải thích. AI cũng vậy.

| Cách thức | Hiệu quả | Lý do |
|-----|------|------|
| Giải thích quy tắc dài | Dễ bỏ sót chi tiết, format không ổn định | AI cần "hiểu" ý định của bạn |
| Cung cấp ví dụ | Format nhất quán, chi tiết đầy đủ | AI trực tiếp "bắt chước" pattern |

**Kiểm nghiệm thực tế cho thấy**: Với task format output, độ chính xác của Few-shot cao hơn Zero-shot 20-40%.

## Số lượng ví dụ: Bao nhiêu là phù hợp?

| Số lượng | Tình huống áp dụng | Cân nhắc |
|-----|---------|------|
| **1 cái** (One-shot) | Format rõ ràng, quy tắc đơn giản | Tiết kiệm token nhất, nhưng pattern có thể chưa rõ |
| **2-3 cái** | Hầu hết tình huống | Cân bằng hiệu quả và chi phí, khuyên dùng mặc định |
| **4-5 cái** | Pattern phức tạp, nhiều trường hợp biên | Hiệu quả tốt hơn, nhưng tiêu thụ token tăng |
| **Nhiều hơn** | Rất hiếm khi cần | Lợi ích giảm dần, cân nhắc xem có cần fine-tune |

**Quy tắc kinh nghiệm**: Bắt đầu từ 2 ví dụ, nếu output không ổn định, tăng lên 3.

## Cách chọn ví dụ chất lượng cao

### Nguyên tắc một: Tính đại diện

Ví dụ phải bao phủ **trường hợp điển hình**, không nên toàn là trường hợp đặc biệt.

```
❌ Chọn ví dụ kém (toàn trường hợp biên):
- Xử lý chuỗi rỗng
- Xử lý văn bản quá dài
- Xử lý ký tự đặc biệt

✅ Chọn ví dụ tốt (trước điển hình, sau biên):
- Văn bản độ dài bình thường (điển hình)
- Văn bản hỗn hợp tiếng Việt tiếng Anh (biến thể phổ biến)
- Xử lý chuỗi rỗng (trường hợp biên)
```

### Nguyên tắc hai: Tính đa dạng

Ví dụ phải bao phủ **các loại khác nhau**, tránh AI overfit một pattern duy nhất.

```
Task: Phân loại phản hồi người dùng

❌ Ví dụ kém (toàn tiêu cực):
- "Quá khó dùng" → Tiêu cực
- "Phần mềm rác" → Tiêu cực

✅ Ví dụ tốt (bao phủ các loại):
- "Quá khó dùng" → Tiêu cực
- "Cũng tốt, nhưng hy vọng có thêm chế độ tối" → Trung lập
- "Dùng ba tháng, năng suất tăng nhiều" → Tích cực
```

### Nguyên tắc ba: Format nhất quán

Tất cả ví dụ **format input output phải thống nhất**.

```
❌ Format không nhất quán:
Ví dụ 1: Input "..." → Output: danh sách task
Ví dụ 2: Input: "..." Output - task 1 - task 2

✅ Format nhất quán:
Ví dụ 1:
Input: "..."
Output:
- Task 1
- Task 2

Ví dụ 2:
Input: "..."
Output:
- Task 1
- Task 2
```

## Prompt kém vs Prompt tốt

### ❌ Prompt kém

```
Giúp tôi chuyển user story thành task phát triển, format phải rõ ràng, bao gồm công việc frontend và backend.

User story: Với tư cách người dùng, tôi hy vọng có thể tìm kiếm task
```

**Vấn đề**: Không có ví dụ, AI không biết "format rõ ràng" của bạn là như thế nào.

### ✅ Prompt tốt

```
Task: Chuyển đổi user story thành danh sách task phát triển

Ví dụ:
User story: Với tư cách người dùng, tôi hy vọng có thể lọc task theo ngày
Task phát triển:
【Frontend】
- Thêm component date picker
- Implement quản lý state lọc
- Cập nhật logic render danh sách task
【Backend】
- Thêm tham số API lọc theo ngày
- Implement điều kiện query database

Bây giờ hãy xử lý:
User story: Với tư cách người dùng, tôi hy vọng có thể tìm kiếm task
```

### So sánh output

Prompt tốt sẽ có output tuân thủ nghiêm ngặt format ví dụ:
```
Task phát triển:
【Frontend】
- Thêm component input tìm kiếm
- Implement quản lý state từ khóa tìm kiếm
- Implement logic tìm kiếm debounce
- Cập nhật render danh sách task, highlight văn bản khớp
【Backend】
- Thêm tham số API từ khóa tìm kiếm
- Implement query database fuzzy matching
```

## Ví dụ thực chiến: Dự án todo list

Tiểu Lý cần AI giúp generate định nghĩa type TypeScript cho nhiều component. Anh ấy muốn format thống nhất.

### Prompt Few-shot

```
Task: Generate định nghĩa TypeScript Props type cho React component

Ví dụ 1:
Mô tả component: Một component hiển thị tiêu đề task, tiêu đề bắt buộc, tùy chọn hiển thị trạng thái hoàn thành
Output:
interface TaskTitleProps {
  title: string;           // Tiêu đề task, bắt buộc
  isCompleted?: boolean;   // Trạng thái hoàn thành, tùy chọn
}

Ví dụ 2:
Mô tả component: Một component button, văn bản hiển thị bắt buộc, sự kiện click bắt buộc, tùy chọn trạng thái disabled
Output:
interface ButtonProps {
  label: string;           // Văn bản button, bắt buộc
  onClick: () => void;     // Sự kiện click, bắt buộc
  disabled?: boolean;      // Trạng thái disabled, tùy chọn
}

Bây giờ hãy xử lý:
Mô tả component: Một component card task, bao gồm tiêu đề bắt buộc, mô tả tùy chọn, deadline tùy chọn, độ ưu tiên bắt buộc (cao/trung/thấp)
```

### Output của AI

```typescript
interface TaskCardProps {
  title: string;                        // Tiêu đề task, bắt buộc
  description?: string;                 // Mô tả task, tùy chọn
  dueDate?: Date;                       // Deadline, tùy chọn
  priority: 'high' | 'medium' | 'low';  // Độ ưu tiên, bắt buộc
}
```

Lưu ý AI tự động học được:
- Style comment (`// giải thích, bắt buộc/tùy chọn`)
- Thuộc tính tùy chọn dùng `?`
- Enum type dùng union type

## Tình huống áp dụng

| Tình huống | Ví dụ | Tại sao cần Few-shot |
|-----|------|-------------------|
| Format output | Generate tài liệu API | Đảm bảo format nhất quán |
| Task phân loại | Phân tích tâm trạng, phân loại tag | Làm rõ tiêu chuẩn phân loại |
| Task chuyển đổi | Yêu cầu → Task, Code → Tài liệu | Học quy tắc chuyển đổi |
| Bắt chước phong cách | Viết content theo phong cách cụ thể | Học phong cách ngôn ngữ |

## Hạn chế của Few-shot

| Hạn chế | Biểu hiện | Giải pháp |
|-----|------|---------|
| Tiêu thụ token cao | Ví dụ chiếm nhiều context | Tinh giản ví dụ, chỉ giữ thông tin quan trọng |
| Khó chọn ví dụ | Chọn sai ví dụ dẫn đến hiệu quả kém | Tuân theo nguyên tắc đại diện, đa dạng, nhất quán |
| Bắt chước quá mức | AI sao chép chi tiết ví dụ | Dùng nội dung ví dụ khác nhau, chỉ giữ format giống nhau |

## Template có thể sao chép

### Template Few-shot tổng quát

```markdown
Task: [mô tả task]

Ví dụ 1:
Input: [ví dụ input 1]
Output:
[ví dụ output 1]

Ví dụ 2:
Input: [ví dụ input 2]
Output:
[ví dụ output 2]

Bây giờ hãy xử lý:
Input: [input thực tế]
```

### Template task phân loại

```markdown
Task: Phân loại phản hồi người dùng thành [danh sách loại]

Ví dụ:
Phản hồi: "[ví dụ phản hồi 1]"
Phân loại: [loại]

Phản hồi: "[ví dụ phản hồi 2]"
Phân loại: [loại]

Phản hồi: "[ví dụ phản hồi 3]"
Phân loại: [loại]

Hãy phân loại:
Phản hồi: "[nội dung cần phân loại]"
```

### Template task chuyển đổi

```markdown
Task: Chuyển đổi [format nguồn] thành [format đích]

Ví dụ quy tắc chuyển đổi:

Nguồn: [nội dung nguồn ví dụ]
Đích:
[nội dung đích ví dụ]

Nguồn: [nội dung nguồn ví dụ]
Đích:
[nội dung đích ví dụ]

Hãy chuyển đổi:
Nguồn: [nội dung thực tế]
```

## Preview nâng cao: Few-shot động

Trong phiên bản nâng cao, bạn sẽ học được "Few-shot động"—**tự động chọn ví dụ liên quan nhất** dựa trên input của người dùng, nâng cao hơn nữa hiệu quả và tiết kiệm token.

## Những điểm chính của phần này

✓ **Bản chất của Few-shot**: Dùng ví dụ dạy AI pattern, thay vì dùng văn bản giải thích quy tắc

✓ **Số lượng ví dụ**: 2-3 cái là điểm cân bằng tốt nhất

✓ **Ba nguyên tắc chọn ví dụ**: Đại diện, đa dạng, format nhất quán

✓ **Tình huống áp dụng**: Format output, phân loại, chuyển đổi, bắt chước phong cách

✓ **Lựa chọn với Zero-shot**: Nếu Zero-shot format không ổn định, chuyển sang Few-shot

Phần tiếp theo, chúng ta sẽ học cách để AI "suy nghĩ trước khi trả lời"—Chain of Thought.
