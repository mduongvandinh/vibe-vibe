# 3.3.6 Hướng dẫn lựa chọn kỹ thuật: Tình huống nào dùng kỹ thuật gì

## Qua phần này bạn sẽ nắm được

- Đánh giá nhanh task nên dùng kỹ thuật nào
- Chiến lược kết hợp các kỹ thuật
- Một bảng tra cứu có thể xem bất cứ lúc nào

## Flow quyết định cốt lõi

Gặp một task, chọn kỹ thuật theo flow sau:

```
Bắt đầu
  ↓
Task này AI "trực tiếp biết làm" không?
  ├─ Có → Zero-shot (hỏi trực tiếp)
  └─ Không ↓

Cần format output cụ thể không?
  ├─ Có → Few-shot (đưa ví dụ)
  └─ Không ↓

Cần suy luận/phân tích nhiều bước không?
  ├─ Có → Chain of Thought (suy nghĩ từng bước)
  └─ Không ↓

Cần so sánh nhiều phương án không?
  ├─ Có → Tree of Thoughts (so sánh nhiều đường)
  └─ Không ↓

Chất lượng output có rất quan trọng không?
  ├─ Có → Thêm Self-Critique (tự kiểm tra sửa)
  └─ Không → Zero-shot là đủ
```

## Bảng quyết định đầy đủ

| Loại task | Kỹ thuật đề xuất | Lý do | Task ví dụ |
|---------|---------|------|---------|
| Chuyển đổi format code | Zero-shot | AI đã nắm quy tắc chuyển đổi | Python 2 → Python 3 |
| Tạo nội dung | Zero-shot | Task sáng tạo không cần ví dụ | Viết mô tả sản phẩm |
| Giải thích code | Zero-shot | AI có khả năng hiểu code tốt | Giải thích đoạn code này làm gì |
| Format output | Few-shot | Dùng ví dụ đảm bảo format nhất quán | Generate tài liệu API |
| Task phân loại | Few-shot | Dùng ví dụ làm rõ tiêu chuẩn phân loại | Phân loại phản hồi người dùng |
| Bắt chước phong cách | Few-shot | Dùng ví dụ học phong cách | Viết content theo phong cách cụ thể |
| Phân tích độ phức tạp | Chain of Thought | Cần suy luận từng bước | Phân tích độ phức tạp thời gian |
| Kiểm tra Bug | Chain of Thought | Cần suy luận từng bước | Phân tích tại sao trang không cập nhật |
| Review logic | Chain of Thought | Cần xét nhiều nhánh | Review logic validate form |
| Lựa chọn công nghệ | Tree of Thoughts | Cần so sánh nhiều phương án | Chọn database |
| Quyết định kiến trúc | Tree of Thoughts | Cần cân nhắc nhiều phương án | Thiết kế phong cách API |
| Code quan trọng | + Self-Critique | Cần đảm bảo chất lượng | Logic nghiệp vụ cốt lõi |
| Output công khai | + Self-Critique | Cần giảm lỗi | Tài liệu API đối ngoại |

## Chiến lược kết hợp sử dụng

Đôi khi một kỹ thuật không đủ, có thể kết hợp:

### Kết hợp một: Few-shot + Self-Critique

**Tình huống**: Cần format output, và yêu cầu chất lượng cao

```
Task: Generate tài liệu giao diện API

Ví dụ 1:
Giao diện: GET /users
Tài liệu:
- Mô tả: Lấy danh sách người dùng
- Tham số: page (phân trang), limit (số lượng mỗi trang)
- Trả về: Mảng người dùng

Ví dụ 2:
Giao diện: POST /users
Tài liệu:
- Mô tả: Tạo người dùng mới
- Tham số: name (bắt buộc), email (bắt buộc)
- Trả về: Object người dùng mới tạo

Vui lòng generate tài liệu cho giao diện sau:
Giao diện: DELETE /users/:id

Sau khi generate, vui lòng tự kiểm tra:
- Có tuân thủ format ví dụ không?
- Có thiếu sót thông tin cần thiết không?
Nếu có vấn đề vui lòng sửa.
```

### Kết hợp hai: Chain of Thought + Self-Critique

**Tình huống**: Task phân tích phức tạp, cần đảm bảo suy luận đúng

```
Vui lòng phân tích độ phức tạp thời gian của thuật toán sắp xếp này.

Các bước phân tích:
1. Xác định cấu trúc vòng lặp
2. Phân tích số lần thực hiện mỗi tầng vòng lặp
3. Tính tổng độ phức tạp thời gian

Sau khi phân tích xong, vui lòng tự kiểm tra:
- Mỗi bước suy luận có đúng không?
- Kết luận cuối cùng có hợp lý không?
Nếu có lỗi vui lòng sửa.
```

### Kết hợp ba: Tree of Thoughts + Chain of Thought

**Tình huống**: Quyết định phức tạp, mỗi phương án cần phân tích sâu

```
Vui lòng giúp tôi chọn phương án quản lý state cho ứng dụng.

Phân tích ba phương án:
1. React Context
2. Redux Toolkit
3. Zustand

Với mỗi phương án, vui lòng phân tích từng bước:
- Bước một: Hiểu nguyên lý cốt lõi của nó
- Bước hai: Phân tích ưu điểm trong tình huống của tôi
- Bước ba: Phân tích vấn đề tiềm ẩn
- Bước bốn: Đưa ra tình huống phù hợp

Cuối cùng so sánh đề xuất.
```

## Tham khảo tần suất sử dụng hàng ngày

Dựa trên kinh nghiệm phát triển thực tế, tần suất sử dụng các kỹ thuật khoảng như sau:

| Kỹ thuật | Tần suất dùng hàng ngày | Tình huống điển hình |
|-----|------------|---------|
| Zero-shot | 50% | Hầu hết task đơn giản |
| Few-shot | 25% | Format output |
| Chain of Thought | 15% | Phân tích logic phức tạp |
| Self-Critique | 8% | Đảm bảo chất lượng output quan trọng |
| Tree of Thoughts | 2% | Quyết định lựa chọn công nghệ |

**Đề xuất thực hành**:
1. Bắt đầu từ Zero-shot thử
2. Nếu output không thỏa mãn, nâng cấp sang kỹ thuật khác
3. Output quan trọng nhớ thêm Self-Critique

## Checklist lựa chọn nhanh

### Tôi muốn làm chuyển đổi code/format
→ **Zero-shot**

### Tôi cần format output thống nhất
→ **Few-shot** (đưa 2-3 ví dụ)

### Tôi cần phân tích logic phức tạp/kiểm tra Bug
→ **Chain of Thought** (suy nghĩ từng bước)

### Tôi cần làm lựa chọn công nghệ/so sánh phương án
→ **Tree of Thoughts** (so sánh nhiều phương án)

### Output này rất quan trọng, không được sai
→ Thêm **Self-Critique** (tự kiểm tra sửa)

## Thẻ tra cứu nhanh kỹ thuật

Có thể lưu hoặc in ra, tra cứu bất cứ lúc nào:

```
┌─────────────────────────────────────────────────────┐
│              Thẻ tra cứu kỹ thuật Prompt v1.0        │
├─────────────────────────────────────────────────────┤
│                                                     │
│  Zero-shot   │ Task AI biết làm, hỏi trực tiếp       │
│              │ VD: chuyển đổi code, tạo nội dung      │
│                                                     │
│  Few-shot    │ Cần format cụ thể, đưa ví dụ          │
│              │ VD: tài liệu API, task phân loại       │
│                                                     │
│  CoT         │ Suy luận phức tạp, suy nghĩ từng bước │
│              │ VD: phân tích độ phức tạp, kiểm tra Bug│
│                                                     │
│  ToT         │ So sánh phương án, khám phá nhiều đường│
│              │ VD: lựa chọn công nghệ, quyết định kiến trúc│
│                                                     │
│  Self-Critique │ Output quan trọng, tự kiểm tra sửa  │
│                │ VD: code cốt lõi, tài liệu công khai│
│                                                     │
├─────────────────────────────────────────────────────┤
│  Flow mặc định: Zero-shot → Không thỏa mãn? → Nâng cấp kỹ thuật│
│  Output quan trọng: Kỹ thuật bất kỳ + Self-Critique  │
└─────────────────────────────────────────────────────┘
```

## Nối với phần tiếp theo

Chúc mừng bạn, đã hoàn thành học tập kỹ thuật prompt nâng cao 3.3!

Bây giờ bạn đã nắm vững:
- **3.1**: Nên nói cho AI thông tin gì (context)
- **3.2**: Cách tổ chức những thông tin này (framework có cấu trúc)
- **3.3**: Dùng cách nào để AI xử lý (kỹ thuật prompt)

Phần tiếp theo **3.4 Viết PRD đầu tiên của bạn**, chúng ta sẽ **kết hợp** thành quả suy nghĩ sản phẩm chương 2 và kỹ thuật prompt chương 3 **với nhau**, tạo thành một workflow hoàn chỉnh.

Bạn sẽ học được:
- Cách chuyển hóa thành quả ba câu hỏi linh hồn, user persona, tư duy làm trừ thành PRD
- Một template PRD tinh gọn phù hợp người mới bắt đầu
- Cách dùng độ ưu tiên hướng dẫn AI phát triển từng giai đoạn

## Những điểm chính của phần này

✓ **Flow cốt lõi chọn kỹ thuật**: Trực tiếp biết làm → Cần format → Cần suy luận → Cần so sánh → Cần chất lượng

✓ **Kết hợp thường dùng nhất**: Few-shot + Self-Critique, CoT + Self-Critique

✓ **Tần suất dùng hàng ngày**: Zero-shot 50%, Few-shot 25%, CoT 15%, Self-Critique 8%, ToT 2%

✓ **Đề xuất thực hành**: Bắt đầu từ Zero-shot, không thỏa mãn mới nâng cấp; Output quan trọng thêm Self-Critique

## Checklist hoàn thành chương

Trước khi vào phần tiếp theo, xác nhận bạn đã:

- [ ] Hiểu Zero-shot: Hỏi trực tiếp task AI biết làm
- [ ] Hiểu Few-shot: Dùng ví dụ dạy AI format
- [ ] Hiểu Chain of Thought: Suy luận phức tạp suy nghĩ từng bước
- [ ] Biết Tree of Thoughts tồn tại: Dùng khi so sánh phương án
- [ ] Hiểu Self-Critique: Output quan trọng để AI tự kiểm tra
- [ ] Có thể chọn kỹ thuật phù hợp dựa trên loại task

Nếu tất cả đã tích được, chúc mừng bạn, sẵn sàng vào phần 3.4 rồi!
