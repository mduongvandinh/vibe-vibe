# 5.1.5 Thực hành GitHub Desktop: 10 phút bắt đầu

Chương này sẽ hướng dẫn bạn từng bước hoàn thành cài đặt và các hoạt động cơ bản của GitHub Desktop.

## Bước 1: Tải xuống và cài đặt

Truy cập trang web chính thức của GitHub Desktop để tải xuống gói cài đặt:

**Địa chỉ trang web**: [desktop.github.com](https://desktop.github.com)

- Tải phiên bản tương ứng với hệ điều hành của bạn (Windows/Mac)
- Sau khi tải xong, nhấp đúp vào gói cài đặt, hoàn thành cài đặt theo hướng dẫn

**Bạn sẽ thấy**: Sau khi cài đặt, biểu tượng GitHub Desktop sẽ xuất hiện trong danh sách ứng dụng của bạn.

::: warning Gợi ý cho người dùng trong nước
GitHub có thể truy cập chậm ở trong nước. Nếu tốc độ tải rất chậm, bạn có thể thử:
1. Tải vào lúc khác (sáng sớm thường nhanh hơn)
2. Sử dụng phát wifi di động
3. Tìm kiếm "gương GitHub Desktop trong nước"

Nếu thực sự không thể tải, bạn có thể tạm thời bỏ qua mục này, sử dụng phương pháp ở 5.1.2 và 5.1.3.
:::

## Bước 2: Đăng ký/Đăng nhập tài khoản GitHub

Mở GitHub Desktop, nó sẽ nhắc bạn đăng nhập.

**Nếu bạn không có tài khoản GitHub**:
1. Nhấp vào "Create your free account" hoặc truy cập [github.com](https://github.com)
2. Điền tên người dùng, email, mật khẩu
3. Hoàn thành xác minh email

**Nếu bạn đã có tài khoản**:
1. Nhấp vào "Sign in to GitHub.com"
2. Đăng nhập trong trang trình duyệt mở ra
3. Cho phép GitHub Desktop truy cập tài khoản của bạn

**Bạn sẽ thấy**: Sau khi đăng nhập thành công, giao diện sẽ hiển thị "Let's get started!" hoặc trang chào mừng tương tự.

## Bước 3: Biến danh sách việc cần làm thành kho lưu trữ

Bây giờ chúng ta cần biến dự án danh sách việc cần làm mà bạn đã làm ở chương bốn thành kho lưu trữ Git.

### Cách 1: Tạo từ thư mục hiện có

1. Nhấp vào **"Create a New Repository on your Hard Drive"** hoặc **"Add an Existing Repository"**

2. Nếu chọn "Create New":
   - **Name**: Nhập tên kho lưu trữ, ví dụ `my-todo-list`
   - **Local Path**: Chọn **thư mục cha** của thư mục dự án
   - Đánh dấu **"Initialize this repository with a README"**
   - Nhấp **"Create Repository"**

3. Sao chép các file danh sách việc cần làm vào thư mục kho lưu trữ mới tạo

### Cách 2: Thêm dự án hiện có trực tiếp (được khuyên dùng)

1. Nhấp vào **File** → **Add Local Repository**
2. Chọn thư mục dự án danh sách việc cần làm
3. Nếu có cảnh báo "không phải kho lưu trữ Git", nhấp **"create a repository"**
4. Xác nhận tạo

**Bạn sẽ thấy**: Bên trái hiển thị tên dự án, phần giữa hiển thị những thay đổi file.

## Bước 4: Lần đầu tiên Commit (lưu)

Bây giờ dự án của bạn đã là kho lưu trữ Git. Hãy tạo điểm lưu đầu tiên.

1. Trong giao diện chính GitHub Desktop, bên trái sẽ hiển thị tất cả các file thay đổi
2. Nếu là kho lưu trữ mới, tất cả các file sẽ hiển thị là "mới thêm"

3. Tìm ô **Summary** ở góc dưới bên trái
   - Nhập một mô tả, ví dụ: "Phiên bản hoàn thành chương bốn danh sách việc cần làm"
   - Description có thể để trống

4. Nhấp nút xanh **"Commit to main"**

**Bạn sẽ thấy**:
- Danh sách file bên trái biến mất (vì tất cả thay đổi đã được lưu)
- Giao diện hiển thị "No local changes"

Chúc mừng! Bạn vừa tạo điểm lưu đầu tiên.

## Bước 5: Xem lịch sử (History)

Hãy xem điểm lưu mà chúng ta vừa tạo.

1. Nhấp vào tab **"History"** ở trên (hoặc tìm ở bên trái)
2. Bạn sẽ thấy một dòng thời gian, mỗi nút là một Commit

**Bạn sẽ thấy**:
- Commit vừa tạo xuất hiện trong danh sách
- Hiển thị mô tả bạn đã viết (ví dụ "Phiên bản hoàn thành chương bốn danh sách việc cần làm")
- Bên phải hiển thị những file được bao gồm trong Commit này

## Bước 6: Mô phỏng sửa hỏng rồi quay lại

Hãy kiểm tra tính năng "tải" của chúng ta.

### 6.1 Trước tiên thực hiện một thay đổi

1. Sử dụng AI IDE hoặc trình soạn thảo văn bản của bạn để mở file HTML danh sách việc cần làm
2. Thay đổi gì đó (ví dụ đổi tiêu đề thành "Kiểm tra quay lại")
3. Lưu file

### 6.2 Tạo một điểm lưu mới

1. Quay lại GitHub Desktop
2. Bạn sẽ thấy thay đổi vừa rồi hiển thị trong danh sách Changes
3. Viết mô tả: "Kiểm tra thay đổi"
4. Nhấp **"Commit to main"**

### 6.3 Quay lại phiên bản trước

1. Nhấp vào tab **"History"**
2. Tìm Commit "Phiên bản hoàn thành chương bốn danh sách việc cần làm"
3. Nhấp chuột phải vào nó
4. Chọn **"Revert Changes in Commit"** (hoặc **"Revert this Commit"**)
5. Xác nhận hoạt động

**Bạn sẽ thấy**:
- Tạo một Commit mới, mô tả tương tự "Revert Kiểm tra thay đổi"
- Mở file HTML, tiêu đề đã quay lại trạng thái ban đầu

## Bước 7: Đẩy lên đám mây (Push)

Bước cuối cùng, tải mã của bạn lên trang web GitHub.

1. Nhấp vào nút **"Publish repository"** hoặc **"Push origin"** ở trên
2. Trong hộp thoại mở ra:
   - **Name**: Xác nhận tên kho lưu trữ
   - **Description**: Có thể viết một mô tả (tùy chọn)
   - **Keep this code private**: Khuyên đánh dấu (giữ kín)
3. Nhấp **"Publish Repository"**

**Bạn sẽ thấy**:
- Nút thay đổi thành "Fetch origin"
- Không có thông báo lỗi

### Xác minh thành công

1. Mở trình duyệt, truy cập [github.com](https://github.com)
2. Đăng nhập tài khoản của bạn
3. Trên trang cá nhân, bạn nên có thể thấy kho lưu trữ vừa tạo
4. Nhấp vào, bạn có thể thấy các file mã của bạn

Chúc mừng! Mã của bạn hiện đã được sao lưu trên đám mây. Ngay cả khi máy tính hỏng, bạn cũng có thể tìm lại từ GitHub.

## Câu hỏi thường gặp

| Vấn đề | Nguyên nhân có thể | Giải pháp |
|------|---------|---------|
| Push thất bại | Vấn đề kết nối mạng | Kiểm tra kết nối internet, thử lại sau |
| Không tìm thấy thư mục dự án | Vấn đề đường dẫn | Xác nhận vị trí thư mục, thêm lại |
| Đăng nhập thất bại | Vấn đề tài khoản | Thử đăng nhập github.com trước |
| Hoạt động rất chậm | Vấn đề kết nối (phổ biến ở trong nước) | Đợi, hoặc thử lại lúc khác |
| Nhắc "not a git repository" | Chưa khởi tạo | Tạo kho lưu trữ theo Bước 3 |

## Danh sách xác minh thành công

Nếu hoàn thành tất cả các bước dưới đây, có nghĩa là bạn đã nắm vững các hoạt động cơ bản của GitHub Desktop:

- [ ] Cài đặt GitHub Desktop thành công
- [ ] Đã đăng nhập tài khoản GitHub
- [ ] Biến dự án danh sách việc cần làm thành kho lưu trữ
- [ ] Tạo Commit đầu tiên
- [ ] Thấy được bản ghi Commit trong History
- [ ] Kiểm tra thành công tính năng quay lại
- [ ] Đẩy mã lên đám mây GitHub
- [ ] Thấy được dự án của bạn trên github.com

Nếu tất cả đã hoàn thành, chúc mừng bạn -- bạn đã biết cách sử dụng công cụ quản lý phiên bản mà lập trình viên chuyên nghiệp dùng hàng ngày!
