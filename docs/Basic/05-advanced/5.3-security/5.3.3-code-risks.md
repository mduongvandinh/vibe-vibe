# 5.3.3 Những lỗ hổng bảo mật trong mã

Sau phần này, bạn sẽ nắm vững:
- 5 loại lỗi bảo mật mà AI thường mắc
- Cách xác định khóa hardcoded trong mã
- Cách sử dụng tệp .env đúng cách
- Mẹo cấu hình .gitignore

## 5 loại lỗi bảo mật mà AI thường mắc

Dựa trên báo cáo Veracode 2025 và phân tích của cộng đồng bảo mật, mã được AI tạo ra thường có những vấn đề bảo mật sau:

### 1. Khóa hardcoded

Đây là vấn đề phổ biến nhất và nguy hiểm nhất.

```javascript
// ❌ Nguy hiểm: khóa trực tiếp viết trong mã
const API_KEY = "sk-proj-abc123xyz...";
const DB_PASSWORD = "SuperSecret123";

// ✅ An toàn: sử dụng biến môi trường
const API_KEY = process.env.API_KEY;
const DB_PASSWORD = process.env.DB_PASSWORD;
```

### 2. Bỏ qua xác nhân đầu vào

Mã được AI tạo ra thường giả sử rằng đầu vào là "bình thường", không thực hiện xác nhận.

```javascript
// ❌ Nguy hiểm: sử dụng trực tiếp đầu vào của người dùng
function searchUser(username) {
  return db.query(`SELECT * FROM users WHERE name = '${username}'`);
}
// Kẻ tấn công có thể nhập: ' OR '1'='1  để lấy tất cả dữ liệu người dùng

// ✅ An toàn: sử dụng truy vấn có tham số
function searchUser(username) {
  return db.query('SELECT * FROM users WHERE name = $1', [username]);
}
```

### 3. Sử dụng cấu hình mặc định không an toàn

```javascript
// ❌ Nguy hiểm: cho phép yêu cầu CORS từ mọi nơi
app.use(cors({ origin: '*' }));

// ✅ An toàn: chỉ cho phép origin cụ thể
app.use(cors({ origin: 'https://yoursite.com' }));
```

### 4. Tiết lộ thông tin quá mức

```javascript
// ❌ Nguy hiểm: tiết lộ thông tin lỗi chi tiết cho người dùng
app.use((err, req, res, next) => {
  res.status(500).json({
    error: err.message,
    stack: err.stack,  // tiết lộ cấu trúc mã
    dbQuery: err.query // tiết lộ truy vấn cơ sở dữ liệu
  });
});

// ✅ An toàn: chỉ trả về thông tin cần thiết
app.use((err, req, res, next) => {
  console.error(err);  // ghi lại thông tin chi tiết trên máy chủ
  res.status(500).json({ error: 'Lỗi máy chủ, vui lòng thử lại sau' });
});
```

### 5. Sử dụng thư viện lỗi thời hoặc có lỗ hổng

AI có thể đề xuất một số thư viện lỗi thời hoặc có lỗ hổng đã biết. Chúng ta sẽ thảo luận chi tiết về vấn đề này trong phần 5.3.5.

## Cách xác định khóa hardcoded

Tìm kiếm những từ khóa này trong mã:

| Từ khóa | Có thể là gì |
|--------|-----------|
| `password`、`passwd`、`pwd` | Mật khẩu |
| `secret`、`api_key`、`apikey` | API key |
| `token`、`auth`、`bearer` | Token xác thực |
| `sk-`、`pk-`、`AKIA` | Khóa dịch vụ cụ thể (OpenAI, AWS, v.v.) |
| `-----BEGIN` | Private key hoặc chứng chỉ |

**Phương pháp kiểm tra nhanh**:

Tìm kiếm những mẫu này trong thư mục dự án của bạn. Nếu bạn thấy một chuỗi dài phía sau trông giống như khóa thực (thay vì `process.env.XXX`), bạn cần cảnh báo.

## Sử dụng tệp .env để lưu trữ thông tin nhạy cảm

Tệp `.env` là cách tiêu chuẩn để lưu trữ cấu hình nhạy cảm.

### Tạo tệp .env

Tạo tệp `.env` trong thư mục gốc của dự án:

```bash
# Ví dụ tệp .env
# API key
OPENAI_API_KEY=sk-proj-khóa thực của bạn
STRIPE_SECRET_KEY=sk_test_khóa thực của bạn

# Kết nối cơ sở dữ liệu
DATABASE_URL=postgres://user:password@localhost:5432/mydb

# Cấu hình khác
NODE_ENV=development
```

### Đọc biến môi trường trong mã

```javascript
// JavaScript/Node.js
const apiKey = process.env.OPENAI_API_KEY;
```

```python
# Python
import os
api_key = os.environ.get('OPENAI_API_KEY')
```

### Tạo tệp .env.example

Để cho những người khác (hoặc bạn trong tương lai) biết cần cấu hình những biến môi trường nào, hãy tạo tệp `.env.example`:

```bash
# .env.example - tệp này có thể được gửi đến Git
# Sao chép tệp này thành .env, rồi điền giá trị thực

OPENAI_API_KEY=điền khóa của bạn ở đây
STRIPE_SECRET_KEY=điền khóa của bạn ở đây
DATABASE_URL=điền chuỗi kết nối cơ sở dữ liệu ở đây
```

## Cấu hình .gitignore để ngăn chặn rò rỉ

Tệp `.gitignore` cho Git biết những tệp nào không được tải lên.

Tạo hoặc chỉnh sửa tệp `.gitignore` trong thư mục gốc của dự án:

```bash
# Tệp biến môi trường - quan trọng nhất!
.env
.env.local
.env.development
.env.production
.env*.local

# Thư mục dependency
node_modules/
venv/
__pycache__/

# Tệp trình soạn thảo và hệ thống
.DS_Store
Thumbs.db
.vscode/
.idea/

# Sản phẩm xây dựng
dist/
build/
*.log
```

::: warning Chú ý
Nếu bạn đã gửi tệp `.env` trước khi thêm `.gitignore`, chỉ thêm `.gitignore` là không đủ.

Bạn cần:
1. Xóa tệp khỏi lịch sử Git
2. **Ngay lập tức thay đổi tất cả khóa bị rò rỉ**

Vì lịch sử Git có thể được xem được, thậm chí nếu tệp bị xóa.
:::

## Kiểm tra danh sách công việc dự án của bạn

Xem lại danh sách công việc mà bạn đã làm trong chương bốn, kiểm tra những điểm sau:

- [ ] Mã không chứa khóa hoặc mật khẩu hardcoded
- [ ] Nếu có cuộc gọi API, khóa được đọc từ biến môi trường
- [ ] Tệp `.env` (nếu có) đã được thêm vào `.gitignore`
- [ ] Không có thông tin nhạy cảm được xuất ra trong console.log

Nếu đó chỉ là một danh sách công việc giao diện trước (sử dụng localStorage), thường không sẽ có những vấn đề này. Nhưng việc phát triển thói quen kiểm tra là rất quan trọng, vì dự án tương lai của bạn sẽ ngày càng phức tạp.
